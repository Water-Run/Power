# 验证、精度声明与性能基线

状态：验证计划 v0
原则：在数据和误差范围没有公开前，不使用“工程级精度”作为宣传语。

2026-09-07 实现增量：新增图运行时已有单位/拓扑负测、惯量/RL 解析解、机电二阶/热一阶收敛、损耗路由与再生能量、失败回滚、ABI 生命周期及 JSON 场景/采样回放测试。运行命令与精确物理范围见 [模型运行时](MODEL_RUNTIME.md)。以下仍是覆盖全产品的目标验证计划。

## 1. 如何证明“比原版模拟级别更高”

3D、更多参数和更高采样率都不能单独证明模型更准。Power! 只有同时满足以下四点，才可对某个模型作更高精度声明：

1. **方程和假设可追踪**：说明模型守恒量、适用范围、经验参数和降阶假设。
2. **数值行为可验证**：有解析解/制造解、守恒残差、步长收敛和失败诊断。
3. **物理输出可比较**：对照有许可的台架、数据表或公开实验，并报告误差，不只展示“看起来合理”的曲线。
4. **系统耦合可核算**：燃料/电池输入、机械输出、热损失、附件和储能变化在同一能量账本闭合。

精度声明按“组件 + 工作区间 + 档位 + 数据集版本”发布。例如可以说“2-RC 电池模型在 15–35 °C、该脉冲工况上的端电压 RMSE 为 X”，不能泛称“电池 99% 准确”。

## 2. 核心核算量

每个守恒域都实现统一 residual telemetry。对时间窗 `[t0, t1]`：

```text
energy_residual = energy_in - energy_out - delta_stored_energy
mass_residual   = mass_in   - mass_out   - delta_stored_mass
charge_residual = charge_in - charge_out - delta_stored_charge
species_residual[i] = species_in[i] - species_out[i]
                    + species_produced[i] - delta_stored_species[i]
```

报告绝对值、相对于传递量的归一化值，以及各组件贡献。反应模型还要检查其声明的元素或伪组分闭合。接近零传递量时只报告绝对残差，避免相对误差爆炸。数值钳制、饱和、控制 deadline miss、陈旧信号、报文丢弃和总线错误必须单独计数，不能藏在残差里。

## 3. 测试层级

### L0：Lua 定义、单位与模型编译

- Lua quantity 转换、量纲检查、稳定 ID 和 DSL 版本迁移。
- descriptor→C model 的规范化结果、未知字段、缺失单位、非法拓扑和资源上限。
- 沙箱负向测试：`io/os/debug/loadlib`、路径逃逸、依赖循环、bytecode、内存/指令/递归超限。
- Model VM 销毁后，编译所得 C graph 不再依赖 Lua table、字符串或 GC 生命周期。

### L1：解析/制造解

- 自由转子、恒扭矩惯量、弹簧/阻尼轴、理想齿轮和离合极限。
- RC/RLC、电池等效电路、热阻热容网络。
- 采样保持、传感器一/二阶响应、执行器死区/迟滞/速率限制、PI/PID 闭环和消息总线仲裁时序。
- 封闭气体绝热压缩、孔口临界流、管段传播和容积平衡。
- 多组分混合/输运、无反应催化器极限、已知放热反应与壁面热容的制造解。
- 曲柄滑块位置/速度/加速度与封闭形式对照。
- 一维导热和对流阶跃；质量/惯量由几何与密度计算。

### L2：组件数据

| 组件 | 主要对照量 |
|---|---|
| 电芯/电池包 | OCV-SOC-T、脉冲端电压、容量、库仑效率、温升、功率限值 |
| 电机/逆变器 | 扭矩—转速包络、效率/损耗图、母线功率、弱磁、热降额 |
| ICE 气缸 | motoring 压力、firing 压力相位/峰值、IMEP、热释放和缸壁热流 |
| 进排气/增压 | 流量曲线、歧管压力、增压器 map、波传播时间 |
| 排气/后处理 | 背压—流量、壁温/热浸、催化器 light-off、储氧/转化率、入口/尾管组分质量流 |
| 机械传动 | 传动比、效率、扭转模态、离合滑摩功、换挡能量 |
| 热组件 | 稳态热阻、瞬态时间常数、冷却回路压降/换热 |
| 传感器/执行器 | 频率响应、采样/传输延迟、量化/噪声、行程/速率/电流限制、失效位置 |
| ECU/VCU/BMS/MCU | 任务周期/优先级、闭环阶跃、状态迁移、扭矩/功率仲裁、故障降级 |
| 低压电网/通信 | 静态/瞬态压降、brownout/唤醒、报文仲裁/带宽/延迟/超时/bus-off |
| 材料 | 密度/热/电/磁曲线插值、温度范围和来源元数据 |

### L3：动力总成场景

- BEV：静态测功、加速、恒速、再生制动、低 SOC/高温降额、预充故障、传感器偏置、报文超时和低压掉电。
- ICE：拖动、冷/热怠速、节气门阶跃、全负荷扫速、断火、超速限制、冷启动催化 light-off、富/稀切换、尾管堵塞和氧传感器/节气门故障。
- DJS/DQ200 整机：冷起动、爬行/起步、K1/K2 预选与交接、连续升降挡、ECU—TCU 扭矩干预、液压不足、离合器过热、背压/欠压故障和左右半轴负载；在供体标定完成前只运行明确标记的合成参数场景。
- EC5/AT8 整机：变矩器失速/耦合、锁止滑差、1–4/R 换挡、主压力/摩擦元件充油、ATF 热保护、ECU—TCU 扭矩干预、排气堵塞和半轴负载；AT8 齿比/行星/液压供体数据缺失时不得用 AL4 或网络常见值填空。
- REV：SOC 滞环启停、效率岛跟踪、持续爬坡功率不足、热限制。
- 并联 HEV：发动机启动同步、扭矩填补、换挡、再生与液压制动协调。
- 功率分流 HEV：行星排速度/扭矩约束、MG1 超速限制、SOC 维持。
- PHEV：充电、charge-depleting、混合过渡、charge-sustaining 和低温功率限制。

每个场景保存输入、Lua DSL/model ABI 版本、求解配置、随机种子、期望 KPI 范围和能量账本，形成可回放 golden case。

### L4：宿主与平台

- C 和 C++ 最小宿主分别链接 `.a`、加载 `.so`、从内存提供 Lua 定义并创建/步进/销毁模型。
- 老宿主加载新库、新宿主请求老 ABI 的兼容测试；未知尾字段和较小 `struct_size` 测试。
- Godot、Unity、Unreal 适配器各有无渲染 smoke scene；崩溃/重载/多实例/暂停恢复。
- Linux Wayland/X11、Vulkan 实机和软件栈、PipeWire/ALSA/JACK/Null 音频组合。
- 无窗口、无 GPU、无音频设备的服务器运行必须是常规路径，不是特殊补丁。

## 4. 收敛与误差门槛

Phase 0 用原型和数据集冻结每类模型的最终阈值。首轮建议门槛如下，均标记为**暂定**：

| 项目 | 暂定门槛 |
|---|---|
| 步长收敛 | 将主步与相关子步减半后，稳态/积分 KPI 变化通常小于 1%；峰值/事件相位另设模型专用阈值 |
| 孤立守恒 | 在无外部输入/损失的测试中，残差随步长收敛且不呈单向无界漂移 |
| 能量账本 | 完整工况的未解释残差不大于已传递能量的 0.5%；所有经验损失必须列账 |
| 确定性 | 同一构建、架构、配置和输入逐步 hash 相同；跨 CPU/编译器以容差 KPI 比较 |
| 失败行为 | 不允许静默 NaN；不收敛、超出 map、事件风暴和队列溢出都有稳定错误码与上下文 |

这些数字不能跨模型机械套用。声学瞬态、离合冲击和燃烧峰值要分别规定相位与幅值指标；验证报告必须同时给出误差分布和最差点。

## 5. 各动力形式的关键 KPI

### ICE

- 指示/制动扭矩、IMEP/BMEP、机械效率、BSFC、空气/燃油流量。
- 缸压峰值、CA10/50/90、点火到峰压相位、排气温度、增压压力。
- 转速阶跃、失火波动、扭转振动主阶次。

### BEV

- DC 输入与轴输出功率、逆变器/铜/铁/机械损失。
- SOC、端电压、峰值电流、可用功率、回收能量和包温差。
- 扭矩跟踪、弱磁区、热降额开始点和恢复滞环。

### HEV/PHEV/REV

- 整车牵引需求与 ICE/电机/电池功率分配。
- 工况首尾 SOC 修正后的燃油/电耗、模式驻留时间、启停次数。
- 模式切换扭矩连续性、离合滑摩能、发动机工作点分布。
- PHEV 的充电输入—电池增量能量—充电损失闭合。

### 电子控制系统

- 每个任务的释放、开始、完成、deadline 和最坏执行预算；同时间戳的优先级/事件顺序可复现。
- 传感器真实值、观测值、质量状态和 age；控制命令、执行器实际位置/电流、饱和/速率限制驻留时间。
- 扭矩、空燃比、转速、SOC、温度等闭环的稳态误差、超调、整定时间和扰动抑制。
- 低压 brownout、报文超时、传感器偏置/掉线、执行器卡滞后的检测时间、降级状态和物理后果。
- 控制器测试必须使用与物理组件相同的采样/延迟路径；绕过传感器直接读取真值的结果只能标为理想控制基线。

### 排气与后处理

- 排气门/上游边界到尾管的质量、组分和焓流；歧管/管段/消声器压力、温度与传播相位。
- 背压对泵气功、残余气体、扭矩和燃耗的反馈；涡轮轴功与气体焓降闭合。
- 催化器基体温度、light-off 时间、储氧或等效反应状态、各组分瞬时/累计转化率和尾管质量。
- 冷启动、热浸、富/稀切换、高流量、老化参数和堵塞场景的误差与步长/网格收敛。
- 法规循环可作为输入工况，但未经认可数据与合规流程的输出不作认证声明。

## 6. 音频验证

声音既要物理可解释，也要好听，两类测试分开：

- 阶次跟踪：主燃烧阶次、电机电磁阶次、齿轮啮合频率随 RPM 的轨迹正确。
- 时序：点火、阀事件、排气传播和听到的脉冲具有可解释延迟。
- 数字质量：无 NaN、削波计数受控、重采样混叠受限、循环缓冲无数据竞争。
- 实时稳定：基准 Linux 机器以 48 kHz/指定 buffer 连续运行 30 分钟无引擎自身造成的 underrun；设备/系统 xruns 单独记录。
- 听感 ABX/主观评分作为产品指标，但不能替代物理验证。

## 7. 3D 与材质验证

- glTF 官方验证器通过，PBR 基准场景做 golden-image 容差比较。
- 部件姿态与解析机构学在 TDC/BDC、气门最大升程、齿轮啮合等关键角度一致。
- 由密度和几何得到的质量/惯量与模型输入核对；修改视觉材质不应改变物理结果。
- 热/压力/流量叠加使用快照时间戳，不能显示“未来状态”或错误插值过离散事件。
- 剖切、爆炸和 LOD 只影响表达，不改变仿真拓扑。

## 8. 性能预算

Phase 0 必须登记一台可复现的桌面基准机和一台最低支持机。没有硬件基线时，只使用以下结构化目标，不发布空泛 FPS 数字：

| 路径 | 首个 release gate |
|---|---|
| `Game` headless | 在最低支持机上批量运行目标实例数仍快于实时；实例数由首个宿主游戏确定 |
| `Interactive` headless | 一套代表性 ICE 或 BEV 动力总成持续达到 `realtime_factor >= 1.0`，并保留 3D/音频预算 |
| 实时循环 | warm-up 后每步零堆分配；p50/p95/p99 与最坏事件步分别记录 |
| 控制调度 | 每类任务统计 release jitter、deadline miss、信号 age 和总线队列高水位；超预算行为确定且可回放 |
| 排气求解 | 分别记录 0D/1D 网络、组分与后处理反应耗时；切换降阶模型必须出现在能力/误差报告中 |
| 音频回调 | 零分配、零阻塞锁、固定上限工作量；队列溢出可观测 |
| 3D | 参考场景在最低支持 GPU 达到冻结的帧预算；物理结果不随 FPS 改变 |
| FFI | 一帧使用批量输入/快照，不产生 O(部件数) 的细粒度跨边界调用 |
| 内存 | 静态模型、运行状态、快照、音频和资产缓存分别计量；多实例共享只读资产 |

所有 benchmark 输出 JSON，包含 Git SHA、C 编译器/版本/flags、Lua/SDL 版本、CPU/GPU、内核、构建类型、模型 hash 和求解配置；CI 只对稳定噪声范围做回归门禁。

## 9. 数据治理

每个验证数据集必须记录：

- 来源、版权/许可、采集设备、校准信息和允许的发布范围。
- 原始数据 hash、清洗脚本版本、单位、采样率和缺失值处理。
- 训练/校准集与最终验证集分离，避免用拟合数据证明自身。
- 参数的来源等级：测量、厂家曲线、文献、估计、默认；UI 中可追踪。
- ECU 标定、传感器/执行器响应、通信矩阵和排放数据分别记录脱敏/发布限制；缺少 OEM 数据时使用公开基准并明确不能代表具体量产控制器。
- 后处理数据记录入口组分、空速、温度、老化状态和采样设备；只给“效率百分比”而缺工况边界的数据不能支撑通用模型。
- 不确定度或至少合理范围，允许敏感度分析而不是伪精确单值。

任何不能进入公开仓库的数据都只在受控验证流水线使用；公开报告可以给聚合误差，但不能泄露受限原始数据。

## 10. 鲁棒性与安全边界

- 对 Lua C bindings、descriptor/model builder、包/VFS parser、C ABI 和原生插件入口做 fuzz。
- 属性测试生成合法/非法组件图，检查守恒、终止和诊断稳定性。
- 极端温度、零惯量、断路/短路、阀面积突变、反转、超速和大 `dt` 必须有定义行为。
- 传感器卡死/偏置/噪声、执行器卡滞、控制任务超时、总线拥塞/bus-off、低压 brownout 和反复唤醒必须终止于定义状态，不能靠宿主帧序偶然恢复。
- 反向排气流、零/负压差、组分耗尽、催化器过温、尾管堵塞和反应刚性必须有非负/守恒约束及稳定诊断，不允许静默生成负组分质量。
- 受限 Lua 资产不得访问任意文件、网络/进程、原生模块或无限依赖深度；只允许 text chunk。
- FFI 的销毁后使用、空指针、错误 `struct_size`、多线程误用均进入负向测试。

## 11. 版本发布所需证据

| 版本阶段 | 必需证据 |
|---|---|
| Prototype | L0/L1 通过，受控轴系与排气切片的守恒/时序账本可观察，benchmark 可复现 |
| Alpha | 对应动力形式至少一组 L2 数据和一条 L3 golden scenario；电子控制与排气链路不可被理想接口绕过；明确误差与降级模型 |
| Beta | Linux/SDK L4 矩阵、长稳测试、资产 fuzz、公开验证报告和许可证清单 |
| 1.0 | Lua DSL/model ABI/C ABI 兼容政策、全部承诺拓扑的验证包、迁移工具、性能基线和长期支持范围 |

“功能能跑”不足以进入 Beta；“画面和声音像”不足以发布工程精度声明。
