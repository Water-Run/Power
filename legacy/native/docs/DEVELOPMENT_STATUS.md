## 2. “完整动力总成”的不可缩减边界

两个首批样例共同使用 `power.complete_powertrain.v1`。发动机和变速器名称不能代替系统边界；可发布的完整样例必须包含下图所有内部域：

```text
空气 + 燃油 + 12 V + 驾驶员/车辆网络
              │
              v
    ECU/传感器/执行器 <-> 进气—燃烧—曲轴—冷却/润滑/附件
                               │                 │
            排气门—后处理—消声—尾管             │
                               │                 v
                     背压/热反馈          发动机—变速器耦合
                                                  │
                         ┌────────────────────────┴───────────────────────┐
                         │                                                │
                 DMF—DQ200 K1/K2                                  驱动盘—变矩器/锁止
                 奇偶轴/预选/机电液压                              AT8 行星机构/摩擦元件/液压
                         │                                                │
                         └──────────── 主减速器—差速器—左右半轴 ──────────┘
                                                  │
                                                  v
                            半轴扭矩 + 尾管组分/热 + 电/热负载 + 诊断/NVH
```

轮胎、制动器、车身惯量、空气动力和道路坡度属于宿主边界，但它们的轮速与反扭矩必须反馈；附件功率、12 V 消耗、排气背压或变速器损耗不得在边界处凭空消失。

## 3. 固定步进的整机同步顺序

首个整机执行器采用 100 µs 固定同步点，顺序冻结为：

1. 锁存驾驶员、道路、环境和故障输入；
2. 到期传感器采样，推进 12 V 电源、ECU/TCU 任务和命令延迟；
3. 由上一同步点的轴速/压力计算离合器或变矩器反扭矩；
4. 推进发动机进气、喷油、燃烧、曲轴与热状态；
5. 推进 DCT 交接或 4AT 变矩器/液压/换挡/ATF 状态；
6. 推进主减速器、差速器、半轴与宿主等效负载；
7. 以发动机排气边界推进排气守恒网，并把歧管压力留给下一同步点；
8. 汇总机械、化学、热、质量/组分、电能账本、跨组件耦合残差、诊断和状态 hash。

这是确定性的显式协同仿真基线。后续图求解器会识别发动机—离合器/变矩器—轴系和发动机—排气压力的强耦合组；在采用迭代或隐式求解前，当前一 tick 延迟和任何速度投影都必须作为可见的 `coupling_adjustment`/残差，而不能静默隐藏。

### PSA EC5 + AT8 4AT

样例已建立 EC5 115 Ch + 四挡 BVA AT8 候选组合、AL4/AT8 谱系适用边界、完整取证清单和 E1/E2/F1/F2/F3 家族级作用拓扑。运行时代码已有通用 SI 发动机、排气网络以及变矩器、锁止、四挡换挡、液压和 ATF 热骨架；尚缺供体身份、EC5 标定、AT8 齿比/行星几何/摩擦元件/阀体/TCU 数据。详见 [样例说明](https://github.com/Water-Run/Power/blob/c342d4c05c9d0b14cae0ce1a85e3f2100dfd7bb3/legacy/native/assets/samples/psa_ec5_at8_4at/README.md) 与 [机器可读证据清单](https://github.com/Water-Run/Power/blob/c342d4c05c9d0b14cae0ce1a85e3f2100dfd7bb3/legacy/native/assets/samples/psa_ec5_at8_4at/source_manifest.toml)。

## 5. 游戏集成契约

物理线程不依赖 SDL、窗口、GPU 或设备音频。宿主按以下模式集成：

1. 通过唯一导出函数获取与调用方结构尺寸兼容的函数表；
2. 创建 context 和实例，批量提交带通道 ID 的 SI 标量输入；
3. 仅以基准 tick 整数倍推进，物理时间不追随可变渲染帧长；
4. 把快照读取到宿主自有缓冲区，在渲染/音频线程插值消费；
5. 记录输入、模型指纹、seed、构建/ABI 和逐同步点 hash，以便回放/联机诊断；
6. 不从宿主回调重入同一实例；实例销毁前 context 保持有效。

模型句柄、带单位描述编译、结构化编译错误和通道自省已开放；完整样例进入公开 ABI 前，还需 VFS/Lua、非线性组件、不可变事件流和完整录制/恢复。内部组件 API 不承诺 ABI 稳定，只用于当前模型验证和图编译器开发。
