## 证据与限制

规定的串行 `dotnet run --file tools/Build.cs -- verify` 覆盖两个程序集目标、实际 MCP 进程、全部实验室、Zig 存档和 C# ABI。计数、结果和日志路径见 [VALIDATION.md](VALIDATION.md)。在 .NET 10 上运行的 Standard 程序集检查不代表 Unity 运行时验收。

燃油供给包含[有限油箱](LIQUID_FUEL_TANK.zh-CN.md)和[可追踪的泄压回流](LIQUID_FUEL_RETURN.zh-CN.md)，保留质量、热能、化学能和压力功账本。[液压 AT 控制器](AT_CONTROL.zh-CN.md)调节执行器压力并确认实际挡域/锁止。独立参考与完整事务为这些研究模型提供证据；完整 ECU/TCU 协调和实测硬件行为仍待完成。

当前环境未设置 `POWER_UNITY_EDITOR`。工作室导入、回放和已准备的测试仍需实际 Editor/Play、渲染及 Player/IL2CPP 证据。

全部参数仍为 `unverified`。EA211 DJS + DQ200 和 PSA EC5 + AT8 在 [assets/samples](../assets/samples) 中保留完整边界和证据清单。缺失的 OEM 测量仍保持缺失。许可证和历史源码出处保持完整。

CLI `list-labs`、MCP 示例发现和串行验证共用[一份实验室目录](../assets/labs/catalog.json)。验证会检查目录是否覆盖每个实验室源文件。

## 下一步开发顺序

1. 继续实现压力相关相平衡、空化、实测泵充液/调压及更精细的电磁/电子驱动。 当有限液体体积与喷雾动量被分解后,替换所声明的导出位移功边界。保持已供给液体、已蒸发燃油与反应分别可观察,并保留独立参考。
2. 用点火控制、进/排气动力学、机械损失与更丰富的热化学扩展发动机。保留完整的发动机目标。
3. 扩展 DCT 驱动及实测行星排/AT 液压，再基于现有采样 DCT 和 AT 控制器协调 ECU/TCU 扭矩请求与换挡。加入实测传感器、执行器和可恢复故障。
4. 用锁定的编辑器运行 `unity-test`,然后取得 Player/IL2CPP 证据。把通道选择、图编辑与保存作为彼此独立的功能完成。
5. 在声明标定样本或发布就绪之前,为两套目标动力总成取得实测图谱、OEM 数据与不确定度预算。
