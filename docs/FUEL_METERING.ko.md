# 유한 기체 연료 레일과 사이클 도즈 계량

[English](FUEL_METERING.md) · [简体中文](FUEL_METERING.zh-CN.md) · [Français](FUEL_METERING.fr.md) · [Русский](FUEL_METERING.ru.md) · [日本語](FUEL_METERING.ja.md) · **한국어** · [Deutsch](FUEL_METERING.de.md) · [Español](FUEL_METERING.es.md) · [Italiano](FUEL_METERING.it.md) · [Português](FUEL_METERING.pt-BR.md)

`gas_fuel_injector`는 유한하게 추적되는 가스 레일에서 호환되는 가스 챔버로 연료를 옮깁니다. 전진 크랭크 창이 사이클마다 요청된 연료 질량 하나를 래치합니다. 압력, 온도, 노즐 면적, 쓸 수 있는 레일 재고가 실제 공급을 정합니다. 제어기는 할당량 근처에서 포트를 조릅니다. 받는 상태에 연료를 직접 더하지 않고, 요청된 도즈가 공급되었다고 가정하지도 않습니다.

이것은 현재의 일정 물성 기체 혼합물 모델을 확장합니다. 별도의 공기 유입, 연료 계량, 혼합, 규정 반응을 이제 모델링할 수 있습니다. 액체 가솔린 분무, 증발, 니들/전기 동역학, 액체 레일/탱크 물리, 상세 화학종 물성, 교정된 OEM 분사/ECU 거동은 구현하지 않습니다. 이들은 완전한 엔진 목표를 향한 필요한 작업으로 남아 있습니다.

## 흐름, 구성 성분, 에너지

공급원과 수신기는 서로 다른 유한 예혼합 가스 노드입니다. 둘은 R, gamma, 발열량, 화학양론비를 공유합니다. 공급원은 순수한 기체 연료일 수도 있고, 연료를 포함한 추적 혼합물일 수도 있습니다. 흐름은 명시적 면적과 유량 계수를 가진, 기존의 압력 의존 초킹/아임계 [가스 오리피스](GAS_NETWORK.ko.md) 법칙을 따릅니다. 역압 흐름은 닫힙니다. 수신기 가스가 레일을 역으로 채우지 않습니다.

할당량이 다루는 것은 **연료 질량**이지, 공급원 혼합물의 총질량이 아닙니다. 각 가스 진행은 연료 유량을 `remaining_cycle_fuel / advance_duration`으로 제한합니다. 같은 흐름 계수가 총질량과 상류 열 엔탈피를 스케일합니다. 구성 성분 분율은 실제 상류 상태를 씁니다. Heun 단계와 수용된 공급 이력은 같은 전달을 씁니다. 그래서 레일 압력이 떨어지거나 공급원 조성이 바뀌어도, 받는 쪽의 연료, 레일 고갈, 열 에너지, 화학 재고는 일관됩니다.

내부 연료 전달은 외부 `fuel_energy_in`이나 저장소 엔탈피에 들어가지 않습니다. 저장된 공급원 화학 에너지는 연료와 함께 움직이고, 별도의 연소 컴포넌트가 그것을 소비할 때만 가스 열이 됩니다. 호환되지 않는 화학이나 열량 가스 매개변수는 컴파일 때 거부됩니다. 도즈 제한은 적분 뒤에 질량이나 에너지를 고치는 대신, 받아들이는 흐름을 바꿉니다.

## 사이클과 명령 계약

| 데이터 | 의미 |
|---|---|
| 공급원 A / 수신기 B | 서로 다른, 유한하고 추적되는 가스 체적 |
| `area`, `discharge_coefficient` | 양의 m2/mm2와 (0,1]의 계수 |
| `crank_node` | 명시적 회전 타이밍 기준. 움직이는 크랭크 챔버는 자기 크랭크를 씁니다 |
| `cycle_angle` | 명시적 각도 단위의 360도 또는 720도 |
| `start_angle`, `duration_angle` | 창의 시작과, 한 사이클을 넘지 않는 양의 지속 |
| `maximum_dose` | 사이클당 양의 연료 한도, kg |
| 입력 `fuel_dose_per_cycle` | [0,maximum_dose]의 요청 kg |

이상적인 직사각형 창은 전진 운동 중에만 열립니다. 수용된 첫 열린 창 진행이 요청 도즈를 샘플링합니다. 그 관측 사이클 중의 쓰기는 다음 창에 적용됩니다. 요청 사이클 채널은 래치된 목표를 계속 보여 줍니다. 0은 그 사이클을 끕니다. 쓸 수 있는 압력이나 연료가 부족하면, 실제 공급은 목표보다 낮게 남습니다. 성공한 스텝이 전체 도즈를 의미하지는 않습니다.

사이클 순번은 표현 가능한 크랭크 각에서 재구성되는, 부호 있는 유계 정수입니다. 더 일찍 관측된 사이클로 돌아가도 그 할당량은 재설정되지 않습니다. 운동을 되돌리면 창이 닫힙니다. 기계 구간당 이동은 `min(0.25 rad,duration/8)`로 제한됩니다. 창 끝점은 기존의 고정 틱/대칭 분할 근사를 쓰므로, 불연속 근처의 타이밍은 시간 스텝 세분화가 필요합니다. 정확한 연속 전환 시각은 주장하지 않습니다.

출력에는 현재 계량 창의 개방, 마지막 틱의 평균 공급 연료 유량, 래치된 요청 도즈, 관측 사이클의 공급 도즈, 누적 공급 연료가 포함됩니다. 유한 레일의 압력, 온도, 남은 연료는 보통의 가스 채널입니다. 보정을 포함한 모든 할당량/순번/공급 이력은 투기적 상태와 함께 복사되고 해시됩니다. 취소, 늦은 실패, 분기는 완전한 상태를 보존합니다.

자산 v17은 노즐 기록과 타이밍 기록을 모두 보존합니다. JSON, CLI, MCP는 같은 모델을 공유합니다. 스키마와 컴파일러는 단위, 한계, 유한하고 호환되는 끝점, 타이밍 소유를 검사합니다. Core 대상은 의존성 없는 net10.0/netstandard2.1을 유지합니다.

## 실험과 증거

`metered-fired-cylinder`는 예혼합 연료 흡기를 공기만 있는 입구와 유한 기체 레일로 바꿉니다. 이상적인 인젝터가 규정 Wiebe 연소 전에, 크랭크 창을 통해 명시적 8/12/4 mg 요청을 공급합니다. 도즈 변경은 다음으로 관측되는 창에서 샘플링됩니다. 0.6초 실험은 28 mg를 공급하고, 약 27.930 mg를 태우며, 약 1228.918 J를 방출합니다. 타지 않은 연료와 경계에서 잃은 연료는 구성 성분 수지에 남습니다. 모든 매개변수는 합성이며 `unverified`입니다.

검사는 정확한 할당량 제한 공급, 유한 레일 고갈, 역압, 창 중간의 명령 래치, 할당량을 다시 발행하지 않는 역전, 매끄러운 세분화를 갖춘 독립 2용기 질량/엔탈피 ODE, 해석적 계량 연소, 완전한 트랜잭션, 상태 용량/단위/화학, 할당 없는 스텝을 다룹니다. 보고서, 이식 가능한 자산, MCP가 모든 경계에서 일치합니다. 별도의 공급 채널과 연소 채널이 수용된 명령과 실제 연료·열을 구분합니다. 측정된 한계와 런타임/성능 증거는 [VALIDATION.ko.md](VALIDATION.ko.md)를 참고하세요. 스튜디오 뷰와 Edit/Play 테스트는 C# 9 소스로 준비되어 있습니다. 실제 Unity 편집기와 Player 수용은 아직 남아 있습니다.
