# 采样双离合同步与分阶段交接

[English](DCT_CONTROL.md) · **简体中文** · [Français](DCT_CONTROL.fr.md) · [Русский](DCT_CONTROL.ru.md) · [日本語](DCT_CONTROL.ja.md) · [한국어](DCT_CONTROL.ko.md) · [Deutsch](DCT_CONTROL.de.md) · [Español](DCT_CONTROL.es.md) · [Italiano](DCT_CONTROL.it.md) · [Português](DCT_CONTROL.pt-BR.md)

`dct_controller` 拥有[七前进/倒挡研究图](DUAL_CLUTCH_TRANSMISSION.zh-CN.md)的两个驱动离合器通道和八个选择器通道。它的整数请求挡位指令与已确认的实际挡位、所选路径、换挡阶段、测得的同步误差和控制器故障是分开的。

这是一个传感器驱动的研究状态机,带有显式扭矩中断。它不确立完整的 TCU/ECU 扭矩混合、详细的接合齿/锁环或离合器执行器行为、标定的换挡策略,或完整的车辆故障管理。

## 状态与物理确认

| 阶段 | 保持的指令策略与转移 |
|---|---|
| 空挡 | 两个驱动离合器和选择器都释放 |
| 准备 | 目标对侧路径处于空载并被预选,而先前的驱动离合器仍接合 |
| 释放 | 先前驱动离合器的开度斜坡下降;目标驱动离合器保持释放 |
| 同步 | 两个驱动离合器都释放时,目标选择器斜坡到全开;等待测得的滑差与物理锁止 |
| 接合 | 目标驱动离合器斜坡上升;另一个驱动离合器保持释放 |
| 行驶 | 已确认目标驱动离合器/选择器;允许相邻空载路径的预选 |
| 故障 | 两个驱动离合器与每个选择器都释放;保持故障,直到空挡或不同的请求 |

交接进行期间目标被锁存。随后的非空挡请求在该交接之后处理;空挡在到期的采样上中止。同一输入轴路径的变更先释放其驱动离合器,再改选择器。对侧输入轴路径的变更可以在驱动释放之前准备空载目标。每条路径最多指令一个选择器,且不使用有指令的驱动离合器重叠。

选择器开度斜坡使用配置的接合时长。选择器只有在指令全开、测得滑差处于所给容差内且物理模式为 `Locked` 之后才就绪。驱动离合器只有在全接合指令、较小的驱动滑差和物理锁止之后才被确认。接受指令并不表示瞬时速比或物理挡位已经完成。

未驱动的预选可能短暂扰动已确认路径。驱动离合器或所选路径尚未物理锁止时,快照中的实际挡位为零。持续丢失单独计时;控制器不把一次瞬态采样当成持续故障。该计时器在阶段变化和恢复时重置。

## 请求挡位、方向与故障

请求挡位是 `[-1,7]` 内的整数,零为空挡,-1 为倒挡。静态、立即与排程输入校验都拒绝小数。源指令使用显式的 `state_code` 单位;普通离合器比例不会被解释成挡位号。

同步超时返回可观测的空载故障。车速为正且高于所给速度限值时的倒挡请求,或运动为负时的前进请求,会作为换向故障被阻止。已确认的驱动/选择器锁止持续丢失使用同一所给超时和不同的故障码。这些控制器结果是物理策略状态,不是数值失败,也不是隐含的成功换挡 KPI。

| 故障码 | 含义 |
|---:|---|
| 0 | 无故障 |
| 1 | 同步/接合超时 |
| 2 | 换向请求被车辆运动阻止 |
| 3 | 已确认锁止持续丢失 |

空挡清除故障并松开传动系。另一个有效请求可以开始新的尝试;反复提交同一个失败目标不会在每个采样上重置超时。更高层的故障决策、合理性检查、传感器故障以及驾驶员/车辆安全功能仍是分开的工作。

## 定义与所有权

控制器声明发动机 A 节点、整车节点、奇/偶驱动离合器 ID、按前进 1–7/倒挡顺序的八个选择器,以及其请求挡位输入。全部十个执行器通道必须互异、初始释放,且只有一个所有者。编译器核验普通离合器类型、轴/轮毂/主减速拓扑、奇/偶分配、倒挡惰轮路径和稳定引用。选择器列表被复制进不可变的定义/编译数据。

显式时序由采样、释放、接合和同步超时的纳秒数组成。采样对齐到物理节拍;其他时间是正的采样整数倍,且至多十秒。同步容差与换向速度限值使用 `rad_s` 或 `rpm`。不会悄悄填入 OEM 数值、执行器图谱或损耗曲线。

智能体写入请求挡位。直接写驱动/选择器会返回 `controlled_input`,带有正确的指令名/通道,且修订号/状态不变。读取暴露实时请求、已确认挡位、已指令的奇/偶选择、阶段、目标选择器滑差和故障。这些状态码与物理通道保持各自不同的语义。

## 整数时钟与完整事务

采样运行在有界整数仿真时间上。写入输入不推进控制记忆。保持的比例送入正常的物理求解器;惯量、齿轮反作用、同步热与驱动热仍在现有账本中。控制器状态包含锁存/活动挡位、选择、阶段/故障、阶段时钟、测得误差和持续锁止计时器。分支、取消、延迟失败的批次和试探区间一并复制/哈希/回滚该记忆与每一条保持的指令。成功的步进与快照不分配托管内存。

长时间的受控挡位运行使用来自中点速度的补偿坐标增量。其补偿属于事务并被哈希;严格的相位容差不变。这解决了新的长时带载同步场景所暴露的累积舍入。更早的模型路径保留先前的积分与回放行为。

报告的状态上限明确为 **128**,32 个节点与 64 个组件不变。这允许完整的研究用点火/DCT/控制器组合,它超过先前的 64 状态界限。精确边界的编译/步进以及超限的物理/控制器模型都有检查;构建/测试仍串行。

## 可移植与共享实验

资产 v22 为每个 DCT 控制器增加一条带类型的 104 字节路径/时序/容差记录。它保留 v1–v21 读取器、稳定的既有 ID,以及有界的计数/长度、摘要、带类型的所有权、单位和物理编译检查。控制器模型增加指纹标签 26。请求/实际/选择/阶段/误差/故障字段追加在后,不改变既有 ID。一份真实的 v21 图夹具保留其摘要,以及同一运行时下升级后的回放。

`controlled-dual-clutch` 对全部七条路径和选定的降挡发出挡位请求。它通过物理完成来观察最终交接与未驱动预选,而不是假定一个名义时间。`controlled-fired-dual-clutch` 把同一采样策略与开放气缸预混燃烧组合在一起。JSON、CLI、可移植回放和实际 MCP 子服务器共享这些定义。

[VALIDATION.md](VALIDATION.zh-CN.md)记录状态/互锁、故障/恢复、所有权、整数输入、不可变路径、容量、长时相位保持、守恒和完整回放证据。全部参数仍为 `unverified`。扭矩混合、完整的执行器/传感器/ECU 行为、完整 AT、实际 Unity 以及标定目标动力总成仍未完成。
