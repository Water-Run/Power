# ネイティブ Zig 境界

オーナーは 2026-09-10 に、ネイティブ言語の移行を再開しました。`legacy/native` 配下のネイティブプロトタイプは、テストとホストを含めて Zig へ移行済みです。これらは別の研究ランタイムのままです。`Power.Core` と `Power.Assets` は、依存関係のないマネージド契約とデュアルターゲットを保ち、Unity はマネージドアセンブリをロードし続けます。

## 相互運用

ネイティブ共有ライブラリは、バージョン付きの `pwr_get_api` エントリポイント、固定幅のスカラーフィールド、構造体サイズ、整数ナノ秒時間、世代ハンドル、呼び出し側が所有するスナップショットバッファ、関数テーブルを保持します。Zig の `extern struct` 宣言と `.c` 呼び出し規約が、既存のバイナリ ABI を表します。このリポジトリに C ソースやヘッダーは不要です。.NET ビルドツール内の C# P/Invoke 実験ランナーは、この境界の利用者のままです。ネイティブのエンジン、排気、トランスミッションのプロトタイプは、内部の Zig API のままです。マネージドのモデルスキーマや、公開ネイティブ機能へ、黙って追加されることはありません。

移行では、方程式、モデル制限、安定した ID、診断、バッチロールバック、エネルギーと質量の台帳、回帰シナリオを残す必要があります。ネイティブプロトタイプの忠実度と、`unverified` なサンプルキャリブレーションは変わりません。ネイティブ検証は、実際の Unity Editor、Play Mode、IL2CPP のエビデンスとも、完全なパワートレイン目標の完成とも、別です。

## 来歴

元の C 実装は、Git コミット `c342d4c05c9d0b14cae0ce1a85e3f2100dfd7bb3` から復元できます。そのソースファイルのパスとハッシュは、`legacy/native/migration-manifest.json` に記録されています。Zig ポートは、元の著作権と、GPL-3.0-or-later および Unity Linking Exception の通知を保持します。歴史的な設計・研究文書は、元の引用を保持します。それらの C 時代の記述は、新しいビルドを説明しません。

未使用だった LuaInstaller ランチャーと、そのパッケージング README は、2026-09-11 に退役しました。元のパスとハッシュは同じマニフェストに含まれ、同じソースリビジョンを指します。ランチャーは未実装の `power_native` ブリッジに依存しており、動作するビルドの一部になったことはありません。現在の CLI とモデル操作は、既存の C#/JSON と Zig のホストに加え、C# ビルドツールの P/Invoke ABI ホストを使います。歴史的文書にある Lua の提案は来歴の記録であり、現在の依存関係や実装要件ではありません。

## ビルドと保守

コンパイラは `.zig-version` で Zig 0.15.2 にピン留めされています。ビルドツールの `install-zig` コマンド（`tools/Build.cs` 内）は、公式の [Zig ダウンロードメタデータ](https://ziglang.org/download/index.json) と、コミット済みのプラットフォーム別アーカイブハッシュを使います。ビルドに C トランスレータ、ヘッダー、CMake、C ソースのコンパイルは不要です。Linux には libc は不要です。macOS は OS 付属の `libSystem` を使います。ポートは最初に一度翻訳され、その後、共有バイナリレイアウトを持つ保守対象の Zig モジュールへ分割されました。メモリ、数学関数、アトミック操作は、Zig とプラットフォーム OS の API を使います。安全性検査は ReleaseSafe ビルドでも有効なままです。

Zig ソースは、すべてのプラットフォームで LF チェックアウトを使います。macOS では、検証ツールが Zig ビルドのサブプロセスに限り `DEVELOPER_DIR=/dev/null` を設定し、Apple SDK の探索を無効にします。これにより Zig 同梱の Darwin リンカースタブが選ばれ、Zig 0.15.2 の [Xcode 26.4 以降の SDK との非互換](https://github.com/ghostty-org/ghostty/issues/11991) を避けます。その `libSystem` スタブは arm64e ターゲットを使います。システムの Xcode 選択は変わりません。これらのネイティブターゲットに、Apple フレームワークや SDK ヘッダーは不要です。

`dotnet run --file tools/Build.cs -- verify` は、マネージド検証のあと、逐次のネイティブ検証を実行します。`native-verify` はネイティブ部分だけを実行します。`native-verify` の実装（`tools/Build.cs` 内）は、C/C++ のソースとヘッダー、および Lua のソース・バイトコード・パッケージを拒否します。コンパイラのピンと整形を検査し、ライブラリと両方の Zig ホストをビルドし、Zig スイートと C# P/Invoke ABI ホストスイートを実行し、電気—熱実験を元の C ベースラインフィクスチャと比較します。Linux ではさらに、公開エクスポートが `pwr_get_api` だけであることと、ライブラリに未解決の外部シンボルがないことを検査します。

ベースライン比較は、モデルフィンガープリント、単位、チャンネル対応、11 個のサンプル時刻、物理値を保持します。ツールチェーンをまたぐ値には、明示的な絶対/相対許容差を使います。リプレイハッシュは、同じバイナリの中で一致する必要があります。`artifacts/reports` 配下のレポートは、実行、KPI/リプレイの結果、未検証のキャリブレーションを区別します。無視されるコンパイラキャッシュと、私的なサードパーティの参照チェックアウトは、リポジトリのソースではありません。

## アーカイブテストの修正

古いテストのエントリポイントのうち 3 つは、`CHECK` マクロが失敗してもゼロを返していました。ポートはこれらの失敗を伝播します。エンジンスイートは以前、隠れた失敗で止まっていました。最後の 22 Nm 負荷サンプルが、レブリミッターの燃料カットに当たり得たためです。そのシナリオは、明示的なリミッターテストとして残します。連続燃焼には、合成の 32 Nm 試験負荷を使います。背圧の比較は、共有の運転状態から始め、速度を比べる前に解析的なポンピングトルクの増分を検査します。起動やストールの交絡を避けるためです。エンジンの方程式や、製品向けキャリブレーション値は変更していません。自動パワートレインの網羅は、リプレイ、差分エネルギー、ブラウンアウト、ロールバックも実行するようになりました。古い CMake ビルドは、そのモジュール全体を省いていました。
