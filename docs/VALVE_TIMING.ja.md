# クランク角バルブタイミング

[English](VALVE_TIMING.md) · [简体中文](VALVE_TIMING.zh-CN.md) · [Français](VALVE_TIMING.fr.md) · [Русский](VALVE_TIMING.ru.md) · **日本語** · [한국어](VALVE_TIMING.ko.md) · [Deutsch](VALVE_TIMING.de.md) · [Español](VALVE_TIMING.es.md) · [Italiano](VALVE_TIMING.it.md) · [Português](VALVE_TIMING.pt-BR.md)

`gas_orifice` 上の任意の `valve_timing` は、その開度に周期的なクランク角の包絡線を掛けます。固定ガス容器と可動気筒を、同じ Core、JSON、CLI、MCP、移植可能アセットの定義を通して扱います。包絡線は、加速、停止、逆転の間、実際のクランク位置に従います。これは有効流路面積を表します。カム接触、物理的なバルブリフト、ばね力、摩擦はモデル化しません。

## 契約と位相

```json
"valve_timing": {
  "crank_node": 1,
  "cycle_angle": { "value": 720, "unit": "deg" },
  "open_angle": { "value": 520, "unit": "deg" },
  "duration_angle": { "value": 200, "unit": "deg" }
}
```

`crank_node` は回転ノードを識別しなければなりません。三つの角度はすべて、明示的な `deg` または `rad` の単位を必要とします。サイクル角はちょうど 360 度または 720 度です。継続角は 1e-6 ラジアンからサイクル角までの間です。開き角は有限で、サイクルを法として正規化されます。負の角度と、サイクル境界をまたぐローブはサポートされます。複数のバルブが一つのクランクを参照でき、ローブの重なりも含みます。

位相は、初期位置を含む、参照されたクランクの角度に対する相対です。気筒の幾何位相は**自動では加算されません**。作成者が、各気筒に適切なバルブ開き角を選ぶ必要があります。720 度サイクルは、連続するクランク回転を区別します。ピストン位置、速度、経過時間から推論される暗黙の 4 ストローク位相はありません。

サイクル `C`、開き角 `a`、継続角 `D`、ピーク開度 `u`、クランク角 `theta` について:

```text
s = modulo(theta - a, C)       // in [0, C)
opening = u sin²(pi s / D)     // 0 < s < D
opening = 0                   // otherwise, including both boundaries
A_effective = A_orifice * opening
```

このプロファイルとその一階導関数は、ローブ境界で連続です。逆回転はそれをたどり直します。停止したクランクは現在の開度を保持し、流れ続けることができます。開度は流れの向きを選びません。既存の圧力駆動で双方向のオリフィス則が、引き続き適用されます。その流量係数は、別の乗数のままです。

タイミング付き絞りでは、`initial_input` とその任意の入力チャンネルが**ピーク開度**、つまり [0, 1] の分数を指定します。チャンネルの量は `peak_opening` です。ゼロはローブを無効にします。出力量 `effective_opening` は `Field.Opening`（JSON の KPI フィールド `opening`）を使い、実際の分数を報告します。`mass_flow` はその分数で評価されます。タイミングのない絞りは、既存の入力量と意味論を保ちます。スケジュールされた、および対話的なピーク変更は、アトミックな入力検証とリビジョン検査を保ちます。

## 積分と回復

タイミング付きモデルは、ガス半ステップ / クランク仕事の全ステップ / ガス半ステップという対称な積分を使います。独立したクランクで駆動される固定容器も含みます。前半は開始時のクランク角を、後半は結果の角度を使います。ガスソルバーは、各半ステップの中で自身の質量/エネルギー動力学を解きます。バルブ端を連続的に位置決めしたり、外側の機械ティックを適応させたりはしません。

アクティブな各ローブについて、外側ティックは次を満たす必要があります。

```text
limit = min(0.25 rad, D / 8)
max(abs(theta_next - theta_old), dt * max(abs(omega_old), abs(omega_next))) <= limit
8 * binary64_epsilon * max(abs(theta_old), abs(theta_next)) <= limit
```

端点速度の限界は、正味の角度変化が小さい逆転もカバーします。精度の限界は、アンラップされた角度がローブに必要な分解能を失うことを防ぎます。分解能不足のティックは、両端点が閉じているときでも失敗します。狭い開口全体を、黙って飛び越すことはできません。無効化されたピークは、ローブの分解能を要求しません。これらは数値上のガードであり、誤差許容や、任意の動力学に対する保証ではありません。

失敗は `NumericalFailure` / `numerical_failure` を返し、呼び出し側バッチのどの部分もコミットしません。先行するティックとスケジュールされた入力を含みます。`step_ns` を減らし、モデル/セッションを作り直してください。イベントが新しいティックになお揃うことを確認します。非常に大きい初期角度には、接続されたすべてのコンポーネントの位相と整合する等価な角度を選んでください。既存の気筒とガスの限界も適用されます。隠れた可変カム状態は追加されません。クランク位置とピーク入力は、すでにスナップショット、ハッシュ、分岐に参加します。

滑らかで壁のない参照事例は、2 次収束を示します。壁温度は外側ティックの間固定されるため、壁結合モデルは 1 次のままです。既存の平衡付近の流量制限は、局所次数を下げ得ます。保存とリプレイは、それだけでは時間精度を示しません。

## エビデンスと互換性

検査には、解析的な包絡線の値、明示的なサイクル、位相の周回、加速、逆転、静止したクランク、無効化されたピーク、ローブ全体の未解決な横断、キャンセル、バッチ全体のロールバック、独立した分岐、割り当てなしのステッピング/スナップショットが含まれます。

固定容器のブローダウンテストは、sin 二乗の露出を独立に積分し、閉じた形の断熱チョーク放出解を使います。正転と逆転の両方の事例が、ティック細分化の下で収束します。別の可動気筒テストは、質量、内部エネルギー、クランク運動、角度依存の絞りを、独立に書かれた RK4 の ODE で積分し、両方のローブ境界を横断します。参照の細分化が、Core の結果と比較する前に、それ自身の精度を確立します。しきい値は[検証記録](VALIDATION.ja.md)を参照してください。

フィンガープリントタグ 6、対象コンポーネント/クランク ID、正規化されたプロファイルパラメーターを加えるのは、タイミング付きモデルだけです。タイミングのないモデルは、以前のフィンガープリントとステッピングを保ちます。アセット v5 は有界なタイミングレコードを加え、v1–v4 リーダーを保持します。それ以前の本物のフィクスチャが、フィンガープリントとアップグレードされたリプレイを検査します。[アセットレイアウト](ASSET_FORMAT.ja.md)を参照してください。

[クランクタイミング気筒のラボラトリー](../assets/labs/crank-timed-cylinder.power.json)は、吸気と排気のプロファイルで、合成チャンバーを繰り返される 720 度サイクルにわたってモータリングします。スケジュールされた二つのトルク変更がクランク速度を変えます。バルブタイミング自体に時間スケジュールはありません。JSON/CLI、MCP、アセット再生は、63 のレポート境界すべてで一致します。ビルドは `CrankTimedCylinder.powerasset` をエクスポートします。Studio は、有効開度チャンネルから模式的なマーカーをアニメーションします。エディター/Play/IL2CPP の実行は未着手のままです。

Cantera の[内燃機関リアクターの例](https://cantera.org/stable/examples/python/reactors/ic_engine.html)は、クランク角ポート制御の概念上の参照です。その固定速度の仮定、バルブ則、例のパラメーターは、Power! のソルバーのキャリブレーションや検証としては採用されません。この実装は、プロジェクトの保存的なクランク結合と双方向ノズル則を使います。別の[予混合燃焼](PREMIXED_COMBUSTION.ja.md)が、燃料と化学エネルギーの会計を加えています。サンプルパラメーターはすべて `unverified` のままです。完全なエンジン挙動と、実測された車両キャリブレーションは未解決のままです。
