# 連成クラッチシミュレーション

[English](CLUTCH_NETWORK.md) · [简体中文](CLUTCH_NETWORK.zh-CN.md) · [Français](CLUTCH_NETWORK.fr.md) · [Русский](CLUTCH_NETWORK.ru.md) · **日本語** · [한국어](CLUTCH_NETWORK.ko.md) · [Deutsch](CLUTCH_NETWORK.de.md) · [Español](CLUTCH_NETWORK.es.md) · [Italiano](CLUTCH_NETWORK.it.md) · [Português](CLUTCH_NETWORK.pt-BR.md)

マネージドの `clutch` コンポーネントは、2 つの回転ノード、または 1 つのローターと接地を結びます。既存の電気機械/気筒の求解に加わり、生成した摩擦熱を熱ノードまたは外部熱台帳へ送ります。JSON、CLI、MCP、アセット v10、Studio は同じ定義を使います。これはトランスミッションの結合要素を実装します。完全な DCT/AT トポロジー、ポンプ/ピストン動特性、ECU/TCU 協調は、別の作業のままです。[油圧ネットワーク](HYDRAULIC_NETWORK.ja.md)は、圧力で作動するクラッチの変種を駆動するようになりました。[マップ化されたコンバーター](CONVERTER_NETWORK.ja.md)は、この求解を共有し、ロックアップには別の並列クラッチを使います。

[ドライクラッチの物理契約](CLUTCH_PHYSICS.ja.md)は、Coulomb 則と、一定負荷のもとでの厳密で独立した 2 慣性の参照を定義します。以下のグラフソルバーは、その法則を連成ネットワークへ拡張します。エンジントルクやモーター電流を、クラッチへの一方向入力として凍結することはしません。

## 定義とチャンネル

```json
{
  "id": 16,
  "kind": "clutch",
  "node_a": 1,
  "node_b": 4,
  "heat_node": 5,
  "input_channel": 104,
  "initial_input": { "value": 0, "unit": "fraction" },
  "parameters": {
    "static_capacity": { "value": 100, "unit": "nm" },
    "sliding_capacity": { "value": 30, "unit": "nm" },
    "ratio": 1
  }
}
```

`node_a` は回転ノードです。`node_b` は別の回転ノードか、接地ブレーキでは省略または零です。`ratio` は有限で非零です。接地には 1 が必要です。静止容量は滑り容量以上で、どちらもポート A での有限かつ非負のトルクです。`initial_input` は `[0,1]` の明示的な係合率で、両方の容量をスケールします。任意の入力チャンネルは、正確な外部ティック境界で係合を変えます。省略または零の `heat_node` は熱を外部排出台帳へ送ります。与えられたシンクは熱ノードでなければなりません。温度はこれらの容量を変えません。

Core のファクトリは `ComponentDefinition.Clutch(id, a, b, staticCapacity, slidingCapacity, channel, engagement, ratio, heat)` です。その `Friction` 記述子は、2 つの明示的なトルク量を含みます。コンパイル済みモデルはパラメーターをコピーし、安定した ID で並べ、クラッチがあるときだけフィンガープリントタグ 8 を加えます。各クラッチ位相は、既存の 64 状態の上限に数えます。より前のモデルは、フィンガープリントとリプレイハッシュを保ちます。合わせた忠実度の名前は `hybrid_clutch_powertrain` で、キャリブレーションは引き続き `unverified` です。

| フィールド | 単位 | 意味 |
|---|---|---|
| `slip_speed` | rad/s | 現在の `omega_A - ratio*omega_B` |
| `clutch_mode` | StateCode | 最後に受理した区間の位相。0 は解放、1 はロック、2 は正の滑り、3 は負の滑り |
| `torque` | Nm | 最後の完全な外部ティックにわたる、A での平均反力 |
| `heat_flow` | W | そのティックにわたる、生成された摩擦動力の平均 |
| `friction_heat` | J | 行き先にかかわらず、累積の生成熱 |

初期のトルク/動力/熱は零です。初期位相は、負荷反力を解く前に、係合と相対速度から推定します。位相は解かれた区間を表すので、端点ちょうどへの到達は、次の求解まで接近中の位相を示し得ます。境界の入力は入力状態を直ちに変え、先行する区間の出力履歴は書き換えません。これは `Step` 呼び出しの終端にある入力イベントにも当てはまります。トルクと動力の平均は、受理されたすべての内部区間を含みます。

## 連成積分とイベント

`g = omega_A - r*omega_B` について、ポートトルクは `tau_A = tau`、`tau_B = -r*tau` です。取り除かれる機械動力は `-tau*g` です。この符号の規約は `r` のどちらの符号でも働きます。解放はトルクを零にします。滑りは、滑りに対抗する動摩擦容量を使います。ロックしたクラッチは、静止容量で有界な反力とともに、中点の相対速度を零にします。これで、人工的なダンパーや硬いペナルティばねを入れずに、理想的なロック仕事が零になります。

各内部区間は、既存の陰的中点の電気機械方程式と、保存的な気筒圧力仕事の求解を使います。クラッチの力の応答は、同じ連成線形因子から得ます。射影ガウス–ザイデル求解が有界な静止反力を決め、気筒トルクは現在の力に対して再計算されます。必要な運動が速度許容差を超えると、飽和した静止拘束は解放されます。別の拘束が離脱方向を変えたときは、アクティブセットを再考します。冗長なクラッチループは許されます。個々の反力は一意でないことがあります。安定したコンポーネント順が決定的な配分を選び、テストは結果の運動、容量限界、全運動量、エネルギーを検査します。

滑り区間が相対速度を反転させると、有界な二分法が観測された滑り零の境界を見つけ、完全な状態コピーから区間をリプレイします。次の区間は固着するか、反対の動摩擦反力で離脱します。動特性、熱因子、気筒の力の応答は、候補の時間ごとに再計算されます。可変の因子はすべて、個々のシミュレーションに属します。コンパイル済みモデルは不変のままです。

拘束許容差は `2e-13 + 32*epsilon*(abs(omega_A)+abs(r*omega_B))` rad/s で、`epsilon = 2.2204460492503131e-16` です。捕捉は、その許容差の 16 倍以内の根を受理します。有限の滑りを射影で遠ざけたり、有限の運動エネルギーを捨てたりはしません。区間のトルク掛ける速度の許容差の 2 倍以内にある、ごく小さな負の摩擦仕事は零へクランプします。それより大きい負の仕事は失敗します。保存検査はこの丸めの影響を含みます。根の許容差以内の残差は、2 つ目の偽のイベントを作れません。

求解が許すのは、外側ティックあたりたかだか 32 内部区間、56 回の根の反復、アクティブセットあたり 256 回の拘束反復、`2*clutch_count+2` 回のアクティブセット試行です。非有限な因子、収束しない拘束、未解決のイベント、使い切った予算、既存の気筒/ガス限界は `NumericalFailure` を返します。キャンセルは、有界な拘束/根の作業の間に検査されます。外部ティックを減らし、慣性/比の尺度、冗長な拘束、容量スケジュールを調べてください。失敗した呼び出しを、部分的に完了した係合と解釈しないでください。

生成熱は `-duration*tau*g_mid` として積分され、その後、熱求解または外部熱台帳へ加えられます。受理された区間の源仕事、ガス輸送、化学履歴、壁面交換、熱排出はすべて、既存のエネルギー会計に入ります。クラッチ位相、平均出力、累積熱、補償された熱の和は、物理状態とともにコピーされハッシュされます。失敗またはキャンセルされた複数ティックの呼び出しは、スケジュールされた入力、位相、熱を含む完全な開始状態を復元します。分岐が共有するのはコンパイル済みモデルデータだけです。外部時刻は有界な整数ナノ秒数のままです。内部イベントの時間は、外部から見える分数ティックを導入しません。

非線形の離脱テストは、区間平均のトルク要求を使います。変化する静止荷重が最初に容量を超える、連続時間の正確な瞬間は見つけません。同様に、イベントの囲い込みが扱うのは離散的な中点軌跡です。大きなティックは、端点が反転を隠す速い物理振動を見逃し得ます。遷移のまわりで時間を細かくし、出力を比べてください。滑らかな電気機械動特性は中点精度を保ち、熱/壁の連成は一次のままです。すべての切り替え軌跡について、普遍的な二次は主張しません。

## ラボラトリーとエビデンス

[燃焼クラッチのラボラトリー](../assets/labs/fired-clutch.power.json)は、予混合気筒を別の慣性負荷とクラッチ熱ノードへつなぎます。6 つの正確なティックのイベントが、部分/全係合、負荷トルク、解放、再係合を適用します。パラメーターは合成値です。0.6 秒にわたって、現在の Linux レポートは次を記録します。

| 量 | 結果 |
|---|---|
| エンジン/負荷の最終速度 | 68.58488546 rad/s |
| 負荷と気筒背圧を含む、正味の外部源仕事 | -96.74607609 J |
| 生成されたクラッチ熱 | 191.55570747 J |
| クラッチ熱ノードの最終温度 | 300.95777854 K |
| 放出された燃料熱 | 1,630.91064291 J |
| 最終滑り | 2.84e-14 rad/s、ロック位相 |
| 最終エネルギー残差 | 1.79e-10 J |
| モデルフィンガープリント / 最終状態ハッシュ | `197be44884deee90` / `28bf5335d8e35cde` |

67 のレポート境界はすべて、別のバッチサイズ、移植可能な再生、実際の MCP 子サーバーのリプレイと一致します。レポートは `artifacts/reports/fired-clutch.json` です。`name: "fired-clutch"` で `get_example_model` を要求するか、次を実行します。

```sh
dotnet src/Power.Cli/bin/Release/net10.0/Power.Cli.dll assets/labs/fired-clutch.power.json --output artifacts/reports/fired-clutch.json
```

Core の検査は、係合、制動、反転を `ClutchPair` と比べます。符号付き比と、両方の熱の行き先を含みます。ロックした RL モーターは、解析的に合成した慣性を持つモデルと一致します。ロックして反応するガス気筒も同様に、圧力と燃料消費を含めて、独立した等価慣性モデルと一致します。ばね/ブレーキの振動子は、3 回の反転と、捕捉する 4 つ目の転回点を通じて、解析的な区分正弦運動と一致します。細分化は、半分化ごとに誤差を 3.7 倍より大きく減らします。3 クラッチのループは、冗長な拘束と同時係合を行使します。テストは、成功した加熱/捕捉の前段のあとの完全なロールバック、キャンセル、正確なスケジュール済みリプレイ、不変の所有、分岐の独立性、繰り返しの内部反転イベントを含む割り当てなしの動作も扱います。

アセット v10 は、明示的な容量とすべてのチャンネルを往復します。不正な個数、欠落、重複、種類の違うレコード、誤った単位、不正な限界、偽造されたダウングレードは拒否されます。真正な v6 の燃焼気筒フィクスチャは、ダイジェスト、フィンガープリント、アップグレードされたリプレイを保ちます。厳密な JSON とエージェントのテストは、成功した実行と KPI 合格を区別します。[VALIDATION.ja.md](VALIDATION.ja.md)を参照してください。

ビルドは `FiredClutch.powerasset` をエクスポートします。Studio は、模式的な 2 枚のクラッチプレート、位相の色、名前付きの位相出力を、係合コントロールと熱チャンネルとともに用意します。インポートと Play のライフサイクルテストは用意されています。実際の Unity エディター、レンダリング、Play Mode、IL2CPP のエビデンスは未着手です。.NET 上でホストした Standard アセンブリの検査は、それに代わるものではありません。

## 恒久の歯車結合

[理想歯車と遊星の拘束](GEAR_NETWORK.ja.md)は、自由な中点とクラッチ/気筒の力の応答を、同じ恒久拘束空間へ射影するようになりました。燃焼遊星のラボラトリーは、リングブレーキとサン/リングクラッチを、理想遊星およびファイナルドライブと組み合わせ、昇段と降段をリプレイします。相対速度がすでに恒久的に拘束されているクラッチは、未定義の独立反力として拒否されます。他のクラッチ状態、容量、熱、イベントの契約は変わりません。
