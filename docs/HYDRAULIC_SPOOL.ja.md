# 機械式スプールの計量と圧力調整

[English](HYDRAULIC_SPOOL.md) · [简体中文](HYDRAULIC_SPOOL.zh-CN.md) · [Français](HYDRAULIC_SPOOL.fr.md) · [Русский](HYDRAULIC_SPOOL.ru.md) · **日本語** · [한국어](HYDRAULIC_SPOOL.ko.md) · [Deutsch](HYDRAULIC_SPOOL.de.md) · [Español](HYDRAULIC_SPOOL.es.md) · [Italiano](HYDRAULIC_SPOOL.it.md) · [Português](HYDRAULIC_SPOOL.pt-BR.md)

`hydraulic_spool_valve` は、明示的な `hydraulic_piston` の実際の変位から油圧ポートを計量します。ピストンは質量、掃引流体体積、圧力による力、コンプライアントなストローク端を供給します。別の `linear_spring` が戻り力、予圧、減衰を供給します。複数の計量ランドが同じピストンを参照できます。

## 方程式と境界

閉じた位置と全開位置が、符号付き行程 L を定義します。変位 x について:

```text
opening = clamp((x - closed_position) / L, 0, 1)
d       = pA - pB
Q       = K * opening * d / (d*d + transition_pressure*transition_pressure)^(1/4)
loss    = Q * d >= 0
```

K は m3/(s*sqrt(Pa)) の明示的な全開係数です。遷移圧力は正です。実装は、巨大な圧力差を二乗しないよう分母をスケールします。符号付き行程は両方の開き方向を支えます。閉じたランドは正確に密封します。漏れには明示的な追加経路が必要です。飽和するのは開度だけです。位置、圧力、速度、蓄えられたエネルギーはクランプされません。

ランドは圧力平衡で、軸方向の噴流力は無視されます。計量ポートの圧力差は、ピストンへ余分な軸力を加えません。駆動力を与えるのは、明示的なアクチュエーターの前面/背面チャンバー圧力です。絞り熱とピストン/ばねの仕事は、既存の保存台帳を使います。このモデルが除くのは、シール摩擦、流れの力の運動量効果、キャビテーション、摩耗、温度依存の幾何/粘度です。キャリブレーション済みバルブではなく、宣言された研究用の縮約です。

[MathWorks Spool Orifice (IL)](https://www.mathworks.com/help/hydro/ref/spoolorificeil.html) は、可変の開口面積と、別の軸方向流れの力の選択肢を文書化します。Power! は独自の正規化された線形ランドと、既存の受動絞りの法則を使います。幾何、流体物性の既定値、実装コードはコピーしていません。

## 共有求解と契約

バルブは、流体圧力、ピストン力、機械拘束と同じ連成 Newton 求解の中で `x_old + dx/2` を読みます。解析的導関数は圧力とランド変位の両方を含みます。計量行程の中では `dOpening/dx=1/L` です。その外では導関数は零です。各端点で、ヤコビアンは片側傾きの平均を使います。これで、遅れた開度指令ではなく、同時のフィードバックループが保たれます。

| パラメーター | 意味 |
|---|---|
| `piston_component` | 明示的な油圧ピストンの安定 ID |
| `closed_position`、`full_open_position` | m または mm の別々の位置。どちらもピストンの公称ストロークの中 |
| `coefficient` | `m3_s_sqrt_pa` の非負な全開係数 |
| `transition_pressure` | Pa または bar の正の正則化圧力 |
| `reservoir_pressure` | 油圧 B が省略/零のときに必要なゲージ圧境界 |

油圧の A/B ポートと任意の熱シンクは、絞りの契約に従います。バルブに `input_channel` も `initial_input` もありません。その `opening` チャンネルを観測し、実際のアクチュエーター回路を指令してください。平均流量/動力と累積油圧熱は観測できます。単位、参照されたコンポーネント種別、ストローク限界は、対処可能な検証エラーを生みます。通常のバッチ全体のロールバック、キャンセル、分岐、整数時計、正確な同じランタイムのリプレイ契約は、すべての状態と履歴を含みます。既存の物理モデルのフィンガープリントは変わりません。

アセット v15 は 32 バイトの計量幾何レコードを加えます。JSON、CLI、MCP は同じ定義を保ちます。`get_example_model("spool-regulated-pump")` は、電動ポンプ、機械的に支配されるバイパス、スケジュールされた圧力クラッチの充填/排出を示します。その 200 N の静的な閉じ予圧は、1 mm 圧縮の 200 kN/m リターンスプリングと、明示的な 1000 mm2 のアクチュエーター面積から来ます。回転の駆動/ブレーキは 2 N*m です。3 秒の実験は、より低い圧力のクラッチが捕捉するのに十分な時間を残します。パラメーターは合成値で、`unverified` です。

## エビデンスと性能

検査は、符号付きの計量行程、受動的な双方向流れ、解析的な圧力/位置の導関数、独立した定常圧力の根、別の 3 状態 RK4 過渡、滑らかな二次の細分化、ランドが開く間の減少する誤差、有限ポートの均一化、掃引体積、独立した運動/流体エネルギー、完全なトランザクションを扱います。ウォーム状態のステッピングとスナップショット読み出しは、マネージドバイトを零だけ割り当てます。ランドの傾きと Newton/LU バッファは各シミュレーションに属します。新しい時計やワーカーは加えられません。

測定誤差、ランタイムの範囲、経過時間は [VALIDATION.ja.md](VALIDATION.ja.md) を参照してください。Studio のバルブ/アクチュエーター表示とインポート/Play テストは C# 9 ソースで用意されています。実際の Unity エディターと Player のエビデンスは未着手です。
