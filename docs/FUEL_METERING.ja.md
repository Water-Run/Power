# 有限ガス燃料レールとサイクルドーズ計量

[English](FUEL_METERING.md) · [简体中文](FUEL_METERING.zh-CN.md) · [Français](FUEL_METERING.fr.md) · [Русский](FUEL_METERING.ru.md) · **日本語** · [한국어](FUEL_METERING.ko.md) · [Deutsch](FUEL_METERING.de.md) · [Español](FUEL_METERING.es.md) · [Italiano](FUEL_METERING.it.md) · [Português](FUEL_METERING.pt-BR.md)

`gas_fuel_injector` は、有限で追跡されたガスレールから、互換なガスチャンバーへ燃料を移します。前進クランクのウィンドウは、サイクルあたり要求された燃料質量を一つラッチします。圧力、温度、ノズル面積、利用できるレール在庫が、実際の供給を決めます。制御器は、割当の近くでポートを絞ります。燃料を受け側の状態へ直接加えることはなく、要求されたドーズが供給されたとも仮定しません。

これは、現在の一定物性のガス状混合物モデルを拡張します。別々の空気導入、燃料計量、混合、規定反応を、いまではモデル化できます。液体ガソリンの噴霧、蒸発、ニードル/電気の動力学、液体レール/タンクの物理、詳細な化学種物性、キャリブレーション済みの OEM 噴射/ECU 挙動は実装しません。これらは、完全なエンジン目標へ向けて必要な作業のままです。

## 流れ、成分、エネルギー

源と受け側は、別個の有限な予混合ガスノードです。両方は R、ガンマ、発熱量、量論比を共有します。源は純粋なガス状燃料でも、追跡された燃料を含む混合物でもかまいません。流れは、明示的な面積と流量係数を持つ、既存の圧力依存でチョーク/亜臨界の[ガスオリフィス](GAS_NETWORK.ja.md)則に従います。逆圧の流れは閉じます。受け側のガスはレールを逆充填しません。

割当が対象とするのは**燃料質量**であり、源混合物の総質量ではありません。各ガス前進は、燃料流量を `remaining_cycle_fuel / advance_duration` で制限します。同じ流れの係数が総質量と上流の熱エンタルピーをスケールします。成分分率は実際の上流状態を使います。Heun の段階と、受理された供給履歴は、同じ輸送を使います。したがって、レール圧力が下がったり源の組成が変わったりしても、受け側の燃料、レールの減少、熱エネルギー、化学在庫は整合したままです。

内部の燃料輸送は、外部の `fuel_energy_in` やリザーバーエンタルピーには入りません。蓄えられた源の化学エネルギーは燃料とともに移動し、別の燃焼コンポーネントがそれを消費したときにだけガス熱になります。互換性のない化学、または熱量的なガスパラメーターは、コンパイル時に拒否されます。ドーズ制限は、積分の後に質量やエネルギーを補正するのではなく、受理される流れを変えます。

## サイクルと指令の契約

| データ | 意味 |
|---|---|
| 源 A / 受け側 B | 別個の、有限で追跡されたガス容積 |
| `area`、`discharge_coefficient` | 正の m2/mm2 と、(0,1] の係数 |
| `crank_node` | 明示的な回転タイミング参照。可動クランクチャンバーは自身のクランクを使う |
| `cycle_angle` | 明示的な角度単位付きの 360 度または 720 度 |
| `start_angle`、`duration_angle` | ウィンドウ開始と、1 サイクル以下の正の継続 |
| `maximum_dose` | 正の、サイクルあたり燃料上限、kg |
| 入力 `fuel_dose_per_cycle` | [0,maximum_dose] の要求 kg |

理想的な矩形ウィンドウが開くのは、前進運動の間だけです。受理された最初の開ウィンドウ前進が、要求ドーズをサンプルします。その観測されたサイクル中の書き込みは次のウィンドウに適用されます。要求サイクルのチャンネルは、ラッチされた目標を表示し続けます。ゼロはそのサイクルを無効にします。利用できる圧力や燃料が不足すれば、実際の供給は目標を下回ったままです。成功したステップは、満量のドーズを意味しません。

サイクル序数は、表現可能なクランク角から再構成される、符号付きの有界整数です。より前に観測されたサイクルへ戻っても、その割当はリセットできません。運動を逆転するとウィンドウは閉じます。機械区間あたりの移動は `min(0.25 rad,duration/8)` に制限されます。ウィンドウ端点は、既存の固定ティック/対称分割の近似を使うため、不連続の近くのタイミングには時間刻みの細分化が必要です。正確な連続切替時刻は主張されません。

出力には、現在の計量ウィンドウ開度、直前ティックの平均供給燃料流量、ラッチされた要求ドーズ、観測されたサイクルで供給されたドーズ、累積供給燃料が含まれます。有限レールの圧力、温度、残燃料は、通常のガスチャンネルです。補償を含むすべての割当/序数/供給の履歴は、投機的状態とともにコピーされ、ハッシュされます。キャンセル、遅い失敗、分岐は、完全な状態を保持します。

アセット v17 は、ノズルとタイミングの両方のレコードを保持します。JSON、CLI、MCP は同じモデルを共有します。スキーマとコンパイラは、単位、境界、有限で互換な端点、タイミングの所有を検査します。Core の対象は、依存のない net10.0/netstandard2.1 のままです。

## 実験とエビデンス

`metered-fired-cylinder` は、予混合燃料の吸気を、空気だけの入口と有限なガスレールに置き換えます。理想インジェクターが、規定 Wiebe 燃焼の前に、クランクウィンドウを通して明示的な 8/12/4 mg の要求を供給します。ドーズの変更は、次に観測されるウィンドウでサンプルされます。0.6 秒の実験は 28 mg を供給し、約 27.930 mg を燃焼し、約 1228.918 J を放出します。未燃燃料と境界で失われた燃料は、成分勘定に残ります。すべてのパラメーターは合成値であり、未検証です。

検査は、正確な割当制限付き供給、有限レールの枯渇、逆圧、ウィンドウ途中の指令ラッチ、割当を再発行しない逆転、滑らかな細分化を持つ独立した二容器の質量/エンタルピー ODE、解析的な計量燃焼、完全なトランザクション、状態容量/単位/化学、割り当てなしのステッピングをカバーします。レポート、移植可能アセット、MCP は、すべての境界で一致します。別々の供給チャンネルと燃焼チャンネルが、受理された指令を、実際の燃料と熱から区別します。測定された境界とランタイム/性能のエビデンスは [VALIDATION.ja.md](VALIDATION.ja.md) を参照してください。Studio の表示と Edit/Play テストは C# 9 ソースで用意されています。実際の Unity エディターと Player の受理は未着手のままです。
