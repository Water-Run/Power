# マネージドドライクラッチの物理

[English](CLUTCH_PHYSICS.md) · [简体中文](CLUTCH_PHYSICS.zh-CN.md) · [Français](CLUTCH_PHYSICS.fr.md) · [Русский](CLUTCH_PHYSICS.ru.md) · **日本語** · [한국어](CLUTCH_PHYSICS.ko.md) · [Deutsch](CLUTCH_PHYSICS.de.md) · [Español](CLUTCH_PHYSICS.es.md) · [Italiano](CLUTCH_PHYSICS.it.md) · [Português](CLUTCH_PHYSICS.pt-BR.md)

`Power.Core` は、不変の `DryClutch` 摩擦則と、一定の外部トルクおよび係合のもとにある 2 慣性のための `ClutchPair` 参照積分器を提供します。どちらもサードパーティ依存なしで `net10.0` と `netstandard2.1` にコンパイルされます。

これらの原始素は、すでに統合された[クラッチグラフコンポーネント](CLUTCH_NETWORK.ja.md)に対する独立した参照です。グラフはシャフト、モーター、気筒を連成し、複数のクラッチと熱の経路指定に対応し、内部イベントを通じてバッチ全体のロールバックを保ちます。JSON、CLI/MCP、アセット v8、Studio はそのグラフ定義を使います。ここで述べる独立ペアは一定負荷の参照のままで、コンパイル済みネットワークを自ら進めることはしません。

## 摩擦契約

容量と反力はすべてポート A で表します。符号付き比 `r` は、既存のシャフトコンポーネントと同じ動力の規約を使います。

```text
g       = omega_A - r * omega_B                  [rad/s]
tau_B   = -r * tau_A                            [Nm]
P_heat  = -tau_A * g                            [W]
C_s     = engagement * static_capacity          [Nm]
C_k     = engagement * sliding_capacity         [Nm]
```

係合率は `[0,1]` にあります。静止容量は非負で、滑り容量以上です。どちらも零にできます。有効な静止容量が零だと、クラッチは解放されます。クランプ圧、摩擦係数、プレート形状、温度フェード、摩耗、ドラッグ、アクチュエーター遅れは推定しません。

滑りが非零のとき、`tau_A = -sign(g) * C_k` です。滑りが正確に零のとき、積分する側の系は、相対加速度を零に保つのに必要なトルクを供給しなければなりません。その大きさがたかだか `C_s` なら、クラッチはその反力でロックし、摩擦熱を出しません。そうでなければ、不釣り合い荷重の方向へ `C_k` で滑り始めます。静止限界での等号はロックのままです。この法則に速度の不感帯はなく、小さな相対速度を黙って固着拘束にはしません。

動摩擦と拘束された静止反力をこう理想化して区別するのは、主な参考文献が述べる力学に従います。[Modelica Clutch](https://doc.modelica.org/om/Modelica.Mechanics.Rotational.Components.Clutch.html) と [MathWorks Fundamental Friction Clutch](https://www.mathworks.com/help/sdl/ref/fundamentalfrictionclutch.html) です。Power! の実装は独立に書かれており、明示的なトルク容量を使います。いずれの実装も再現せず、それらのより広い構成モデルを主張しません。

`ClutchMode` は `Disengaged`、`Locked`、`SlippingPositive`、`SlippingNegative` を区別します。速度零でのモードは、外部荷重が静止容量を超えるとき、離脱していく滑り状態になり得ます。`HeatFlowWatts` は瞬間値です。そのような零速度での離脱では、その後の熱は正でも、その値は零です。

## 厳密な一定負荷ペア

2 つの正の慣性 `J_A`、`J_B` と、一定の外部トルク `T_A`、`T_B` について:

```text
J_A * domega_A/dt = T_A + tau_A
J_B * domega_B/dt = T_B - r * tau_A
D                 = 1/J_A + r*r/J_B
b                 = T_A/J_A - r*T_B/J_B
required_tau_A    = -b/D
dg/dt             = b + D*tau_A
```

各滑り位相の加速度は一定です。相対速度が要求された区間の中で零に達すると、ソルバーは正確に `t_zero = -g / (dg/dt)` まで進め、静止反力を評価します。その後、残りをロックするか、逆方向の滑りとして積分します。外力が一定なので、そのような到達はたかだか 1 回です。したがって求解はたかだか 2 位相で、収束ループも時間の細分も要りません。区間の端点ちょうどにあるイベントは、その右側の反力モードを返します。

ロック軌跡は `omega_A = r*omega_B` に従い、次のとおりです。

```text
domega_B/dt = (r*T_A + T_B) / (r*r*J_A + J_B).
```

計算された到達では、運動量を保つ射影が binary64 のイベント丸め残差を除きます。大きな慣性重み付き和を作らず、有界な慣性重みを使います。ロックしたあとは、速度拘束を明示的に構成します。これは解決済みイベントでの丸め補正であり、有限滑りの非弾性な瞬間係合ではありません。角度の進みは、一定加速度の各位相を積分します。外部仕事は `T_A*delta_theta_A + T_B*delta_theta_B`、摩擦熱は `-tau_A*g` の積分です。結果には、A での符号付きトルク力積と、独立に検査できる運動エネルギー変化が含まれます。エネルギー残差は `external_work - heat - delta_kinetic` です。

ペアは、非零で有限な `r` のどちら側の符号も扱います。一般化運動量 `r*J_A*omega_A + J_B*omega_B` が変わるのは `r*T_A + T_B` を通じてだけです。通常の角運動量保存が成り立つのは `r = 1` のときです。比は、支持部がトルク反力を受けられる理想的な機械変圧器を表します。接地ブレーキには `ClutchPair.Brake(J, friction)` を構成します。このときポート B の速度と外部トルクは固定の零で、`r = 1` です。無限大は慣性の番兵には使いません。

## API と失敗時の挙動

```csharp
var pair = new ClutchPair(0.2, 0.8, new DryClutch(20, 10));
var status = pair.Advance(new ClutchPairState(100, 0),
    externalTorqueANewtonMeters: 0,
    externalTorqueBNewtonMeters: 0,
    engagement: 1,
    durationSeconds: 4,
    out var step);
```

この例は 1.6 s 後に両ポートが 20 rad/s へ達し、800 J の熱を生成します。4 秒間の角度の進みは 144 rad と 64 rad です。数値はすべて合成値であり、車両キャリブレーションの主張はありません。

2 つのクラスは不変です。`ClutchPairState` と `ClutchPairStep` は値型です。`Advance` は呼び出し側の状態を変えず、メモリも割り当てません。独立した呼び出し側は同じペアを共有できます。保持される位相履歴や大域のシミュレーション時計はありません。渡された速度と新しい一定負荷が次の区間を決めます。

| 状態 | 意味と回復 |
|---|---|
| `Ok` | 完全で有限な局所結果が得られます。保存とモデルの適合は別に評価してください |
| `InvalidDuration` | 有限で厳密に正の区間を秒で与えてください |
| `InvalidEngagement` | `[0,1]` の有限な割合を与えてください |
| `InvalidState` | 有限な速度を与えてください。接地ブレーキでは速度 B が零でなければなりません |
| `InvalidTorque` | 有限な外部トルクを与えてください。接地ブレーキではトルク B が零でなければなりません |
| `NumericalFailure` | 導出された運動、イベント時刻、またはエネルギーがサポートされる binary64 の範囲を超えています。単位と尺度を調べ、区間を短くするか定式化し直してください |

拒否されたときは出力が `default` になり、部分的に公開された状態はありません。不正な不変パラメーターは、構築時に `ArgumentException` またはその派生を投げます。`DryClutch.Evaluate` も同様に、不正な入力やオーバーフローする瞬間熱を拒否します。零へアンダーフローするイベント時刻は、有限の相対運動エネルギーを黙って捨てずに失敗します。物理結果は浮動小数点の丸めを受けます。有限な入力だけでは、導出量が表現できるとは限りません。

`ZeroSlipTimeSeconds` は、係合した状態で相対速度零へ最初に到達する時刻です。区間がそこから始まるときは零です。そのような到達がないとき、解放運動を含めて、これは null です。固着を意味しません。大きな外部荷重は直ちに反転させ得ます。`SlippingDurationSeconds` は離脱する滑り位相を含み、解放運動は除きます。`EndReaction` は最終状態での瞬間値です。熱、仕事、力積、角度の進みは区間全体で積分されます。

局所的な秒のパラメーターは、`Simulation` の固定された有界ナノ秒時計を置き換えません。グラフ積分は、正確な外部ティック/イベント境界、状態ハッシュ、分岐の独立性、キャンセル、複数ティックにわたる完全なロールバックを保ちます。

## エビデンスと限界

[ClutchChecks.cs](../tests/Power.Tests/ClutchChecks.cs) は、同じ 10 グループを両方の Core ターゲットアセンブリに対して実行します。

- 閉形式の 2 慣性同期時間、速度、角度の進み、力積、運動量、失われた運動エネルギー。全係合と部分係合を含みます。
- 厳密な静止荷重の分担、境界を含む離脱しきい値、より低い動摩擦容量、不感帯のない非零滑り、動摩擦容量が零の静止ラッチ。
- 区間内および端点での反転に加え、過大荷重での接地制動、保持、離脱。
- 正負の比、一般化運動量、独立に計算したエネルギー変化。2,000 組の決定的な組み合わせが、慣性、比、速度、外部荷重、容量、時間を掃引します。
- 一定外力のもとでのハイブリッドイベントを通じた分割不変性。変化する正弦荷重の中点サンプリングは、独立した解析的な速度・角度・熱の積分へ収束します。これは、その荷重サンプリング例の二次の挙動を証明します。グラフには、別の連成およびハイブリッド収束検査があります。
- 不正な入力、オーバーフロー、解決できないイベント、失敗時の既定出力、独立した反復評価、10,000 回の成功区間でのゼロ割り当て。

ペアは熱を生成エネルギーとして返します。グラフコンポーネントはそれを熱ノードまたは外部台帳へ送ります。どちらの API も、DCT/AT トポロジー、歯車選択、トルクコンバーター、油圧アクチュエーター、ECU/TCU 協調、クラッチ材質の同定、実測キャリブレーションは実装しません。それらの境界は[ロードマップ](ROADMAP.ja.md)に残っています。
