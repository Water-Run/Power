# Power! 개발 로드맵

[English](ROADMAP.md) · [简体中文](ROADMAP.zh-CN.md) · [Français](ROADMAP.fr.md) · [Русский](ROADMAP.ru.md) · [日本語](ROADMAP.ja.md) · **한국어** · [Deutsch](ROADMAP.de.md) · [Español](ROADMAP.es.md) · [Italiano](ROADMAP.it.md) · [Português](ROADMAP.pt-BR.md)

목표는 완전한 Power! 파워트레인 플랫폼입니다. 현대적인 C# 물리, Unity 3D 스튜디오, 그리고 에이전트의 직접 조작입니다. 통과한 합성 실험실은 유계 수치 결과를 확립합니다. 엔진, 변속기, 제어, 차량 교정, 데스크톱 수용은 각각 자신의 증거가 필요합니다.

## 다음 관리형 작업

유한 탱크에 기하학적 용량, 통기/기체 공간 동역학, 실측 펌프 충액/조압과 정밀 자기/전자 구동을 추가합니다. 유한 컴플라이언트 공급 질량과 압력 에너지, 실제 니들 운동, 샘플링 도즈 피드백, 필름 보충, 증발은 구현되어 있습니다. [니들 계약](NEEDLE_ACTUATION.ko.md)과 [유계 폐쇄 예측](CLOSURE_PREDICTION.ko.md)을 참고하세요. 수신기는 선언된 무시 가능 액체 체적 경계 아래에서 여전히 변위 압력 일을 내보냅니다. 분해된 분무/변위는 검증된 기하와 운동량/일 결합으로 그것을 대체해야 합니다. 공급, 증기 가용성, 규정 반응은 분리된 상태로 유지하고, 해석적/보존/수렴 증거를 유지합니다. [펌프 공급 액체 연료 레일](PUMP_FED_FUEL.ko.md)

그다음 점화/제어, 흡기/배기 동역학, 엔진 기계 손실을 확장합니다. 현재 Wiebe 연소는 규정된 것이며, 예측 연소, 노킹, 배출, OEM 교정을 확립하지 않습니다. [기체 계량 계약](FUEL_METERING.ko.md)은 독립적으로 지원되는 경로로 남습니다.

[일곱 전진/후진 DCT 그래프](DUAL_CLUTCH_TRANSMISSION.ko.md) 위에 상세 싱크로나이저/도그/클러치 구동을 쌓습니다. [Ravigneaux 그래프](RAVIGNEAUX_TRANSMISSION.ko.md) 위에 [실측 유성 물성과 물림 거동](RESOLVED_PLANETS.ko.md), 완전한 [펌프 공급 피스톤 구동](AT_HYDRAULIC_ACTUATION.ko.md), 그리고 결합 컨버터, 기어, 클러치, 유압 원시 요소를 쓰는 AT 제어를 쌓습니다. [샘플링 DCT 제어](DCT_CONTROL.ko.md) 위에서 토크 블렌딩 변속과 유계 ECU/TCU 조율로 나아갑니다. 토크 요청, 센서/액추에이터, 복구 가능한 결함을 포함합니다. 실측 물성/제어 데이터가 있을 때 일정 펌프 손실, 배터리, 밸브/어큐뮬레이터 모델을 확장합니다. 제공된 연구 값은 검증되지 않은 상태로 남습니다.

## 스튜디오와 실측 수용

`POWER_UNITY_EDITOR`를 고정된 편집기로 설정하고 `unity-test`를 실행합니다. 실제 가져오기/Play/렌더링 증거를 얻은 뒤 Player/IL2CPP 증거를 얻습니다. 일반 채널 선택, 그래프 편집, 저장은 별도의 스튜디오 기능으로 남습니다. CLI, MCP, Unity는 계속 같은 모델 의미론을 소비해야 합니다.

EA211 DJS + DQ200과 PSA EC5 + AT8은 완전한 파워트레인 경계, 차량 적용 범위, 증거 매니페스트를 유지합니다. 누락된 OEM 측정은 조용한 기본값으로 대체되지 않습니다. 기능 완료, 수치 정확성, 실측 차량 신뢰성은 별도의 수용이 필요합니다.

[Zig 아카이브](NATIVE_ZIG.ko.md)는 원래 C 개정 `c342d4c`를 포함해 원래 해시와 Git 출처를 `legacy/native/migration-manifest.json`에 유지합니다. 활성 C#/Unity 응용 프로그램과는 별개로 남습니다. 네이티브 이식이 관리형 기능 이식이나 파워트레인 수용을 완료하지는 않습니다. 측정이 그것을 정당화하고 코어 계약이 안정적일 때 추가 병렬성, 희소 해석 또는 Burst를 도입합니다.

## 유압 AT 피드백

`at_controller`는 [-1,4] 범위의 정수 목표 단을 받으며 0은 중립입니다. 다섯 쌍의 충전/배출 밸브와 선택적인 토크 컨버터 록업을 관리합니다. 경로 순서는 캐리어 입력, 작은 선기어 입력, 큰 선기어 입력, 캐리어 브레이크, 큰 선기어 브레이크, 마지막으로 록업입니다.

예제 `controlled-hydraulic-ravigneaux`와 `controlled-fired-hydraulic-ravigneaux`는 요청 채널 900과 컨트롤러 ID 1400을 사용합니다. 변경되지 않은 128 상태 한도 안에서 99와 122개의 보고 상태를 보존합니다. v27는 경로, 게인과 클록을 저장하고 v1-v26를 읽습니다.

연구용 제어이며 매개변수는 `unverified`입니다. ECU 토크 협조, 상세 센서/밸브, 전체 차량 고장과 OEM 보정은 아직 미완성입니다. managed 및 Standard 검사는 실제 Unity Editor/Play/Player/IL2CPP 검증을 입증하지 않습니다.

## 펌프 공급 액체 연료 레일

`liquid_rail_feed`는 액체 인젝터를 기존 용적 펌프와 명시적인 물질/열 경계에 연결합니다. 유압 출구 노드는 레일 컴플라이언스와 초기 절대압에 일치해야 합니다. 펌프와 인젝터가 이 압력 노드를 소유하고 다른 미추적 유체 경로는 거부됩니다.

v27은 공급 연결과 원천 온도를 저장하고 v1-v26를 읽습니다. 축/압력 해석 교환, 독립 동시 ODE 세분화, 열 혼합, 질량/연료/에너지/체적 원장, 역류와 완전 rollback을 각각 확인합니다.

기하학적 용량, 통기/기체 공간/슬로싱, 캐비테이션, 실측 충액/효율/조압과 분해 분무는 미완성입니다. 매개변수는 `unverified`이며 실제 Unity Editor/Play/Player/IL2CPP와 OEM 보정은 미검증입니다.

[PUMP_FED_FUEL.ko.md](PUMP_FED_FUEL.ko.md)

## 유한 액체 연료 탱크

`liquid_fuel_tank`는 연결 인젝터의 밀도, 필름 열 기준과 발열량으로 유한 액체 질량과 열 에너지를 저장합니다. 공급은 `tank_component`로 선택하고 `supply_temperature`를 생략합니다. 각 탱크는 연료 물성이 같은 한 공급에 속합니다.

탱크 열/화학 에너지는 전체 저장 원장에 포함됩니다. 내부 전달은 외부 질량이나 화학 공급을 추가하지 않습니다. 명시적 펌프 입구 지정 압력은 압력 일 경계를 유지합니다. 가스 흡배기는 화학 경계 에너지를 운반할 수 있습니다.

기하학적 용량, 통기/기체 공간/슬로싱, 캐비테이션, 실측 충액/효율/조압과 분해 분무는 미완성입니다. 매개변수는 `unverified`이며 실제 Unity Editor/Play/Player/IL2CPP와 OEM 보정은 미검증입니다.
