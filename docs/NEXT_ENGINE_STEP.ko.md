# 엔진 개발 재개 노트

[English](NEXT_ENGINE_STEP.md) · [简体中文](NEXT_ENGINE_STEP.zh-CN.md) · [Français](NEXT_ENGINE_STEP.fr.md) · [Русский](NEXT_ENGINE_STEP.ru.md) · [日本語](NEXT_ENGINE_STEP.ja.md) · **한국어** · [Deutsch](NEXT_ENGINE_STEP.de.md) · [Español](NEXT_ENGINE_STEP.es.md) · [Italiano](NEXT_ENGINE_STEP.it.md) · [Português](NEXT_ENGINE_STEP.pt-BR.md)

개발은 소유자의 요청으로 2026-09-14에 재개되었습니다. 독립 가스 원시 요소와 컴파일된 Core 네트워크는 이제 구현되어 있습니다. 아래 2026-09-22 통합 체크포인트가 남은 범위를 갱신합니다. 앞선 밀폐 실린더 기준선은 Windows, macOS, Linux에서 관리형 검증을 통과했습니다. 실제 Unity 편집기와 Player 증거는 아직 남아 있습니다. [검증](VALIDATION.ko.md)을 참고하세요.

**2026-09-14의 후속 체크포인트:** [Core 가스 네트워크](GAS_NETWORK.ko.md)는 이제 고정 체적 가스 노드, 저장소 유동 제한, 제어되는 개방, 열 링크, 채널, 장부, 분기, 롤백을 구현합니다. 유계 Heun 방법은 매끄러운 흐름에 대한 해석적 증거와 세분화 증거를 갖추고, 명시적 벽 결합과 보존적인 평형 근처 제한기를 둡니다. 이것은 제안된 암시적 방법이 아닙니다.

**2026-09-22 통합:** JSON/스키마, 자산 v3, CLI/MCP 탐색과 예제, 이식 가능한 리플레이, Unity 개략 뷰가 구현되었습니다. 변경 전 v1/v2 판독기와 픽스처는 유지됩니다. Unity 편집기/Play 검증은 아직 남아 있습니다. 이후의 [가동 실린더 증분](MOVING_CYLINDER.ko.md)은 JSON, 자산, 에이전트를 통해 가스 교환과 크랭크 일을 추가합니다. 이후의 [크랭크각 타이밍 증분](VALVE_TIMING.ko.md)은 같은 인터페이스를 통해 명시적 360/720도 프로파일, 역전, 유계 로브 분해능을 추가합니다. 최신 엔진 체크포인트는 [예혼합 연소](PREMIXED_COMBUSTION.ko.md)를 포함합니다. 수송되는 연료/공기/생성물, 제한 반응물, 화학 에너지 수지가 있습니다. 상세 열화학, 연료 계량, 점화 제어는 엔진 작업으로 남아 있습니다.

Core 네트워크는 이제 명시적 가스 질량과 내부 에너지 상태를 제공합니다. 가동 실린더 컴포넌트는 이제 그것들을 보존적 압력 일과 함께 크랭크 의존 챔버에 결합합니다. 현재의 밀폐 실린더는 각도와 불변 초기 엔트로피에서 가스 상태를 유도하므로, 가스 교환이나 벽 가열을 나타낼 수 없습니다. 그 컴포넌트는 해석적 벤치마크로 남습니다. 유한 챔버, 저장소, 가스 실린더, 제어되는 오리피스, 가스-열 링크는 이제 컴파일된 그래프 안에 함께 있습니다.

원래 증분 계약(완료된 Core 작업과 남은 통합을 구분하려면 위의 체크포인트를 사용하세요):

- 가스 유동 제한은 안정적인 가스 노드 ID를 참조합니다. 미래의 가스 실린더는 움직이는 체적 끝점을 명시적으로 정의해야 합니다. 가스 실린더는 회전 노드에도 연결됩니다. 열 링크는 유한 가스 체적을 열 노드에 연결합니다. 더미 기계 노드를 요구하지 않는 가스 전용 네트워크를 지원합니다.
- 질량과 내부 에너지를 독립적으로 추적하고, 양수인 유한 상태를 검증합니다. 질량과 상류 엔탈피를 함께 전달합니다. 저장소 교환은 외부 질량과 에너지 장부에서 추적합니다. 내부 전달은 상쇄되어야 합니다. 조성/화학종 혼합이 구현될 때까지, 연결된 가스는 같은 기체 상수와 gamma로 제한합니다.
- 부호 있는 질량 흐름, 가스 상태, 열 흐름, 질량 잔차 채널을 노출합니다. 오리피스 개방은 `[0,1]` 안의 명시적 무차원 분율을 사용하며, 직접 입력과 예약 입력에 같은 검증을 적용합니다.
- 연결된 쌍의 등압 상태로 구간을 잡는, 유계 쌍별 암시적 전달 해석을 조사합니다. 가스 실린더 압력 일은 기존 크랭크 해석을 통해 결합합니다. 후방 오일러 흐름을 쓰는 분할 방법은 가스 교환에 대해 1차가 됩니다. 보존만으로 정확성이 증명되지는 않습니다. 이 제안된 방법을 채택하기 전에 검증합니다.
- 완전한 배치 롤백, 상태 해시와 분기의 보정항, 취소, 불변 컴파일 모델, 성공적인 스텝 동안의 할당 0을 유지합니다. 솔버 실패는 실행 가능한 안내를 반환해야 합니다.
- JSON 스키마, 이식 가능한 자산, 기능 탐색, 예제, 보고서, Unity 뷰를 함께 확장합니다. 새 자산 버전이 필요하면 v1/v2 판독기를 유지하고 실제 변경 전 픽스처를 테스트합니다. 솔버 의미론이 변하지 않는 곳에서는 기존 모델 지문을 유지합니다.

필요한 증거에는 초킹 및 아임계 노즐 흐름, 해석적 단열 용기 블로다운, 저장소 충전 엔탈피, 닫힌 네트워크의 질량/에너지 보존, 압력 균등화, 가스/벽 열교환, 스텝 세분화, 역류, 닫힌 밸브 격리, 결합된 크랭크 일, 잘못된 토폴로지/입력 거부, 실패 배치 복구, 분기, 완전한 CLI/MCP/자산 리플레이가 포함됩니다.

연구 출발점: 이상 압축성 노즐 흐름은 [NASA 질량 흐름 초킹](https://www.grc.nasa.gov/www/k-12/BGP/mflchk.html), 제어 체적 경계와 벽 개념은 [Cantera 반응기 상호 작용](https://www.cantera.org/stable/reference/reactors/interactions.html)입니다. 이 참고 자료는 런타임 의존성이 아니며, Power!가 제안한 솔버의 검증도 아닙니다.

진본 변경 전 실린더 v2 자산은 이제 [호환 픽스처](../tests/Power.Tests/Fixtures/README.md)에 소스 커밋과 SHA-256과 함께 유지됩니다. 활성 테스트는 v3로 올린 뒤의 지문과 리플레이를 검증합니다. 새 인코더로 그것을 다시 생성하지 마세요.

완전한 엔진 동작, 예측 연소/열화학, 기계식 밸브 트레인 동역학, 변속기, 제어, 교정된 차량 샘플은 열려 있습니다. 모든 샘플 증거 경계를 유지하세요. 보관된 네이티브 프로토타입은 [네이티브 경계](NATIVE_ZIG.ko.md) 아래에서 **Zig**로 포트되었습니다. 활성 C#/Unity 구현은 그대로 있습니다.
