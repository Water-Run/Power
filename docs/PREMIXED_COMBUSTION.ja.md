# 予混合燃焼と燃料エネルギーの会計

[English](PREMIXED_COMBUSTION.md) · [简体中文](PREMIXED_COMBUSTION.zh-CN.md) · [Français](PREMIXED_COMBUSTION.fr.md) · [Русский](PREMIXED_COMBUSTION.ru.md) · **日本語** · [한국어](PREMIXED_COMBUSTION.ko.md) · [Deutsch](PREMIXED_COMBUSTION.de.md) · [Español](PREMIXED_COMBUSTION.es.md) · [Italiano](PREMIXED_COMBUSTION.it.md) · [Português](PREMIXED_COMBUSTION.pt-BR.md)

`premixed_combustion` は、規定された Wiebe 燃焼プロファイルを、クランクと有限ガスチャンバーへ結合します。燃料、新鮮空気、不活性生成物はガスネットワークを通して輸送されます。反応は、利用できる制限反応物を消費し、蓄えられた化学エネルギーを熱的なガスエネルギーへ変換します。圧力仕事は、可動気筒と同じクランクソルバーを駆動します。Core、JSON、CLI、MCP、アセット v6 がこれらの定義を共有します。

これは集中定数で物性が一定の予混合モデルです。接続されたネットワーク内のすべての成分は、一つの R とガンマを共有します。三つの質量区分は、詳細な化学種、可変熱容量、反応速度論、火炎伝播、自己着火、ノッキング、排出物、燃料の蒸発、噴射を表しません。元の燃焼例は、すでに混合されたガス状の入口を使います。[サイクル燃料計量](FUEL_METERING.ja.md)は、別の有限ガスレールと空気導入をサポートします。液体噴霧と蒸発は、モデルの外のままです。規定された燃焼と、合格する保存則テストは、実測のエンジン性能を確立せず、完全なパワートレイン目標も完了しません。

## 組成とポート

ガスノードは、既存の `gas` オブジェクトに任意で `premixed` を加えます。

```json
"gas": {
  "gas_constant": { "value": 287, "unit": "j_kg_k" },
  "gamma": 1.35,
  "premixed": {
    "lower_heating_value": { "value": 44000000, "unit": "j_kg" },
    "stoichiometric_air_fuel_ratio": 14.7,
    "initial_fractions": { "fuel": 0.04, "fresh_air": 0.96 }
  }
}
```

発熱量と量論空燃質量比は、正で有限でなければなりません。燃料と新鮮空気の分率は非負で、和は高々 1 です。残りは不活性生成物です。新鮮空気は、酸化剤とその希釈剤をあわせて表します。燃料 1 kg とともに新鮮空気 `r` kg を消費すると、生成物 `1+r` kg ができます。過剰な新鮮空気や燃料は利用可能なままです。生成物は再び反応できません。

予混合ノード上の各リザーバー絞りは、同じ二つのフィールドを使って、明示的な `reservoir_fractions` を指定しなければなりません。分率が許されるのは、他のコンポーネントや内部絞りではありません。流入では境界がその組成を供給し、流出では有限体積の実際の組成を取り除きます。接続された有限ガス容積は、追跡、R、ガンマ、LHV、量論比を共有しなければなりません。互換性のない接続や、追跡されていない接続は拒否されます。化学在庫がポートで消えることはできません。

ガスソルバーは、各成分を、総ガスと同じ符号付き質量流束と上流分率で輸送します。非負の成分質量を発展させ、総質量をそれらの和から再構成します。予混合ステップは、流入と流出の総質量速度がほぼ打ち消し合うときでも、総流出流量で制限されます。圧力の均等化やリザーバーの逆流によって、化学在庫が作られることはありません。

予混合ガスは、宣言された状態予算に、格納される成分値を三つ加えます。燃焼コンポーネントは、不可逆な角度フロンティアを一つ加えます。すべて既存の 64 状態の上限内に収まります。補償された境界台帳と反応台帳は、ロールバック、ハッシュ、分岐に参加します。

## 燃焼則とクランク履歴

コンポーネントは `node_a`（クランク）を `node_b`（予混合ガス）へ接続します。可動チャンバーは自身の幾何クランクを使わなければならず、各チャンバーが許す燃焼コンポーネントは高々一つです。固定容器は、解析実験のために独立したクランクを使ってもかまいません。

```json
{
  "id": 15,
  "kind": "premixed_combustion",
  "node_a": 1,
  "node_b": 2,
  "input_channel": 103,
  "initial_input": { "value": 1, "unit": "fraction" },
  "parameters": {
    "cycle_angle": { "value": 720, "unit": "deg" },
    "start_angle": { "value": 340, "unit": "deg" },
    "duration_angle": { "value": 80, "unit": "deg" },
    "shape_exponent": 3,
    "burn_coefficient": 6.9
  }
}
```

サイクルは明示的に 360 度または 720 度です。開始角は実際のクランクに対する相対で、気筒の幾何位相によって暗黙にずらされることはありません。継続角は [1e-6 rad, サイクル角] の中にあります。形状指数 `n` は [1,16]、係数 `a` は (0,50] です。開始はサイクルを法として正規化されます。すべての角度は単位を必要とします。燃焼開始からの前進進行 `z` を [0,1] にクリップすると、積分されたハザードは `H(z) = a z^n` です。完全なサイクルごとに `a` が寄与します。

新たに横断された前進角度について:

```text
hazard = burn_multiplier * delta(H)
limiting_fuel = min(fuel_mass, fresh_air_mass / stoichiometric_air_fuel_ratio)
burned_fuel = limiting_fuel * (1 - exp(-hazard))
consumed_air = stoichiometric_air_fuel_ratio * burned_fuel
created_products = burned_fuel + consumed_air
released_heat = LHV * burned_fuel
```

閉じた充填で乗数が 1 のとき、燃焼した分率は、初期の制限燃料量の `1-exp(-a z^n)` です。継続角の境界で 1 に**強制されません**。一つの完全な燃焼ウィンドウの後にも、`exp(-a)` が未燃のまま残ります。小さな露出は、桁落ちを避けるために `expm1` を使います。アクティブなウィンドウの間に入る新鮮な充填は、よく混合された反応物に加わります。隠れた、無制限のサイクルあたり熱源はありません。

任意の入力チャンネルは `burn_multiplier` で、ハザードをスケールする [0,1] の分数です。ゼロは反応を無効にします。開いた入口から燃料が入ることを止めません。この入力は、インジェクター指令でも予測点火制御でもありません。

各コンポーネントは、到達した最大のクランク角を格納し、開始角度で初期化されます。反応が起こるのは、そのフロンティアを超えたときだけです。停止、逆回転、または以前訪れた角度の再追跡では、熱を再び放出できません。無効化された前進移動もフロンティアを動かすため、再び有効にしても、取りこぼした熱は放出されません。燃焼ウィンドウの内側から開始すると、残りの前進露出だけを消費します。大きな逆転の後、燃焼はクランクが以前の最大を超えるまで抑制されたままです。双方向のエンジン点火と、制御器による再有効化は、将来の制御作業のままです。

## エネルギーと数値結合

ガス内部エネルギーは熱的なままです。`U = m cv T` です。化学エネルギーは別に `E_chemical = m_fuel LHV` です。リザーバーの総エンタルピーは、`mdot cp T` と輸送された化学エネルギーの両方を含みます。大域の貯蔵エネルギー変化は化学在庫を含むため、燃焼は内部変換であり、追加の外部源仕事ではありません。

```text
energy_residual = mechanical/electrical source work + reservoir total enthalpy
                  - rejected heat - change(total stored energy)
```

`net_fuel_energy_in` は、境界台帳の化学部分を別に公開します。これは正味の流入であり、モデルを出る未燃燃料を含みます。総燃料供給量でも、定常状態の燃料消費指標でもありません。`fuel_residual` と `fresh_air_residual` は、初期在庫、正味の境界輸送、現在の在庫、累積反応を比較します。`mass_residual` は引き続き総ガス質量をカバーします。成分の変換は質量を保存します。

可動チャンバーでは、熱の予見が試行中の新しいクランク角に依存し、非線形クランク求解に参加します。ティック中の総熱を `Q`、`r = (V_old/V_new)^(gamma-1)` とすると:

```text
U_after = (U_before + Q/2) r + Q/2
adiabatic_work = (U_before + Q/2) (1-r)
crank_work = adiabatic_work - back_pressure * (V_new - V_old)
```

離散圧力トルクは同じ仕事を使うため、ガスエネルギー、化学エネルギー、クランク仕事は一致します。燃料が消費されるのは、求解が候補状態で成功した後だけです。ガス輸送は、引き続きクランク仕事/反応のまわりの対称な半ステップを使います。壁温度は外側ティックにわたって固定されたままです。壁結合は 1 次です。

有効な燃焼について、ティックあたりの角度移動と端点速度の移動は、`min(0.25 rad, duration_angle/32)` 以内に収まる必要があり、対応する binary64 の角度分解能ガードがあります。放出熱は、一つのティックで燃焼前の熱エネルギーの 25% を超えてはなりません。これらは、受理される仕事と分解能の境界であり、精度の保証ではありません。ガスのサブステップと気筒の反復限界とあわせて適用されます。`numerical_failure` では `step_ns` を減らし、スケジュールされたイベントを新しいティックに揃え、モデル/セッションを作り直します。失敗またはキャンセルされた呼び出しは、状態、入力、フロンティア、化学台帳、再生カーソルを一切コミットしません。

## 出力、互換性、エビデンス

予混合ノードは、KPI フィールド `fuel_mass`、`fresh_air_mass`、`product_mass`、`chemical_energy` を加えます。燃焼コンポーネントは、累積の `fuel_burned`（kg）と `heat_released`（J）を加えます。KPI フィールド `burn_frontier` は、訪れた最大のクランク角（チャンネル量 `burn_frontier_angle`、rad）を公開するので、逆転後に抑制された燃焼を検査できます。大域チャンネルは、化学エネルギー、正味の燃料エネルギー入力、燃料残差、新鮮空気残差を加えます。発見が返すチャンネル量は権威です。たとえばノードの燃料質量は `unburned_fuel_mass` と名付けられます。通常のガス内部エネルギーと流量の出力は、熱的な意味と符号付き流量の意味を保ちます。

予混合モデルは、フィンガープリントタグ 7 と、正規化された反応/組成パラメーターを加えます。それ以前の非反応のフィンガープリントとステッピングは変わりません。アセット v6 は、組成、リザーバー分率、燃焼のレコードを加えます。本物の v1–v5 フィクスチャは互換性を保ちます。新しい忠実度は `premixed_gas_transport` と `premixed_wiebe_combustion` です。

テストは、閉じた容器の解析的な燃料/空気消費と温度、制限反応物、リザーバーの順方向/逆方向輸送、閉じたネットワークの成分保存、独立した反応クランク/ガス ODE の収束、停止/逆転/無効化された燃焼、不正な契約、バッチのロールバック、キャンセル、分岐、ステッピング/スナップショットのゼロ割り当てをカバーします。[燃焼気筒のラボラトリー](../assets/labs/fired-cylinder.power.json)は、繰り返される吸気/圧縮/燃焼/膨張/排気の相を通して負荷を駆動し、63 の JSON/CLI/MCP/アセットのレポート境界すべてで同一にリプレイします。数値エビデンスと実際の実行範囲は [VALIDATION.ja.md](VALIDATION.ja.md) に記録されています。

[Cantera の理想気体リアクター方程式](https://www.cantera.org/stable/reference/reactors/ideal-gas-reactor.html)が、制御体積の質量/化学種/エネルギーの文脈を与えます。[Ansys の SI エンジン例](https://chemkin.docs.pyansys.com/version/stable/examples/advanced/SI_engine_optimization.html)は、明示的な燃焼タイミングと Wiebe パラメーターを使います。これらの参照は契約の動機です。それらの詳細な化学、二領域モデル、例のパラメーターは、コピーされず、この一定物性ソルバーの検証としても主張されません。どちらのパッケージにも実行時依存はありません。サンプルパラメーターはすべて `unverified` のままです。
