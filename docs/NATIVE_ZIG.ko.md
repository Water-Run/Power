# 네이티브 Zig 경계

[English](NATIVE_ZIG.md) · [简体中文](NATIVE_ZIG.zh-CN.md) · [Français](NATIVE_ZIG.fr.md) · [Русский](NATIVE_ZIG.ru.md) · [日本語](NATIVE_ZIG.ja.md) · **한국어** · [Deutsch](NATIVE_ZIG.de.md) · [Español](NATIVE_ZIG.es.md) · [Italiano](NATIVE_ZIG.it.md) · [Português](NATIVE_ZIG.pt-BR.md)

소유자는 2026-09-10에 네이티브 언어 이식을 재개했습니다. `legacy/native` 아래의 네이티브 프로토타입은 테스트와 호스트를 포함해 Zig로 이식되었습니다. 이들은 별도 연구 런타임으로 남습니다. `Power.Core`와 `Power.Assets`는 의존성 없는 관리형 계약과 이중 대상을 유지하고, Unity는 계속 관리형 어셈블리를 로드합니다.

## 상호 운용

네이티브 공유 라이브러리는 버전이 있는 `pwr_get_api` 진입점, 고정 폭 스칼라 필드, 구조체 크기, 정수 나노초 시간, 세대 핸들, 호출자 소유 스냅샷 버퍼, 함수 테이블을 유지합니다. Zig `extern struct` 선언과 `.c` 호출 규약이 기존 바이너리 ABI를 표현합니다. 이 저장소에 C 소스나 헤더는 필요하지 않습니다. .NET 빌드 도구의 C# P/Invoke 실험 실행기는 이 경계의 소비자로 남습니다. 네이티브 엔진, 배기, 변속기 프로토타입은 관리형 모델 스키마나 공개 네이티브 기능에 조용히 추가되지 않고, 내부 Zig API로 남습니다.

이식은 방정식, 모델 제한, 안정 ID, 진단, 배치 롤백, 에너지와 질량 장부, 회귀 시나리오를 유지해야 합니다. 네이티브 프로토타입의 충실도와 `unverified` 샘플 교정은 변하지 않습니다. 네이티브 검증은 실제 Unity 편집기, Play Mode, IL2CPP 증거와 별개이며, 완전한 파워트레인 목표의 완료와도 별개입니다.

## 출처

원래 C 구현은 Git 커밋 `c342d4c05c9d0b14cae0ce1a85e3f2100dfd7bb3`에서 복원할 수 있습니다. 소스 파일 경로와 해시는 `legacy/native/migration-manifest.json`에 기록되어 있습니다. Zig 포트는 원래 저작권과 GPL-3.0-or-later 및 Unity 링킹 예외 고지를 유지합니다. 역사적 설계·연구 문서는 원래 인용을 유지합니다. 그 C 시대 설명은 새 빌드를 설명하지 않습니다.

쓰이지 않던 LuaInstaller 런처와 그 패키징 README는 2026-09-11에 퇴역했습니다. 원래 경로와 해시는 같은 매니페스트에 포함되며 같은 소스 개정을 가리킵니다. 런처는 구현되지 않은 `power_native` 브리지에 의존했고, 동작하는 빌드의 일부가 된 적이 없습니다. 현재 CLI와 모델 작업은 기존 C#/JSON 및 Zig 호스트와 C# 빌드 도구의 P/Invoke ABI 호스트를 사용합니다. 역사적 문서의 Lua 제안은 출처 기록이지, 현재 의존성이나 구현 요구 사항이 아닙니다.

## 빌드와 유지보수

컴파일러는 `.zig-version`에서 Zig 0.15.2로 고정되어 있습니다. 빌드 도구의 `install-zig` 명령(`tools/Build.cs` 안)은 공식 [Zig 다운로드 메타데이터](https://ziglang.org/download/index.json)와 커밋된 플랫폼별 아카이브 해시를 사용합니다. 빌드에는 C 변환기, 헤더, CMake, C 소스 컴파일이 필요하지 않습니다. Linux에는 libc가 필요하지 않고, macOS는 OS가 제공하는 `libSystem`을 사용합니다. 포트는 처음에 한 번 번역된 뒤, 공유 바이너리 레이아웃을 가진 유지 대상 Zig 모듈로 나뉘었습니다. 메모리, 수학 함수, 원자적 연산은 Zig와 플랫폼 OS API를 사용합니다. 안전 검사는 ReleaseSafe 빌드에서 계속 켜져 있습니다.

Zig 소스는 모든 플랫폼에서 LF 체크아웃을 사용합니다. macOS에서 검증 도구는 Zig 빌드 하위 프로세스에서만 `DEVELOPER_DIR=/dev/null`을 설정해 Apple SDK 탐색을 끕니다. 이렇게 하면 Zig에 포함된 Darwin 링커 스텁이 선택되고, `libSystem` 스텁이 arm64e 대상을 쓰는 Zig 0.15.2의 [Xcode 26.4 및 이후 SDK와의 비호환](https://github.com/ghostty-org/ghostty/issues/11991)을 피합니다. 시스템 Xcode 선택은 바뀌지 않습니다. 이 네이티브 대상에는 Apple 프레임워크나 SDK 헤더가 필요하지 않습니다.

`dotnet run --file tools/Build.cs -- verify`는 관리형 검증을 실행한 뒤 직렬 네이티브 검증을 실행합니다. `native-verify`는 네이티브 부분만 실행합니다. `native-verify` 구현(`tools/Build.cs` 안)은 C/C++ 소스와 헤더, 그리고 Lua 소스·바이트코드·패키지를 거부합니다. 컴파일러 고정과 서식을 검사하고, 라이브러리와 두 Zig 호스트를 빌드하고, Zig 스위트와 C# P/Invoke ABI 호스트 스위트를 실행하며, 전기—열 실험을 원래 C 기준선 픽스처와 비교합니다. Linux에서는 `pwr_get_api`만 공개로 내보내고 라이브러리에 미해결 외부 기호가 없는지도 검사합니다.

기준선 비교는 모델 지문, 단위, 채널 매핑, 11개 샘플 시각, 물리 값을 유지합니다. 툴체인 간 값은 명시적 절대/상대 허용 오차를 사용합니다. 리플레이 해시는 같은 바이너리 안에서 일치해야 합니다. `artifacts/reports` 아래 보고서는 실행, KPI/리플레이 결과, 검증되지 않은 교정을 구분합니다. 무시된 컴파일러 캐시와 비공개 제3자 참조 체크아웃은 저장소 소스가 아닙니다.

## 아카이브 테스트 수정

오래된 테스트 진입점 세 개는 `CHECK` 매크로가 실패해도 0을 반환했습니다. 포트는 이 실패를 전파합니다. 엔진 스위트는 이전에는 마지막 22 Nm 부하 샘플이 회전 제한 연료 차단에 있을 수 있어, 숨은 실패에서 멈췄습니다. 그 시나리오는 명시적 리미터 테스트로 유지됩니다. 연속 연소는 합성 32 Nm 시험 부하를 사용합니다. 배압 비교는 이제 공유된 운전 상태에서 시작하고, 속도를 비교하기 전에 해석적 펌핑 토크 증분을 검사해 시동/스톨 혼동을 피합니다. 엔진 방정식이나 생산 교정 값은 바뀌지 않았습니다. 자동 파워트레인 커버리지는 이제 리플레이, 에너지 차분, 브라운아웃, 롤백도 실행합니다. 예전 CMake 빌드는 그 모듈 전체를 빠뜨렸습니다.
