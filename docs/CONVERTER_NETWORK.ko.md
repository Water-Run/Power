# 준정상 토크 컨버터 네트워크

[English](CONVERTER_NETWORK.md) · [简体中文](CONVERTER_NETWORK.zh-CN.md) · [Français](CONVERTER_NETWORK.fr.md) · [Русский](CONVERTER_NETWORK.ru.md) · [日本語](CONVERTER_NETWORK.ja.md) · **한국어** · [Deutsch](CONVERTER_NETWORK.de.md) · [Español](CONVERTER_NETWORK.es.md) · [Italiano](CONVERTER_NETWORK.it.md) · [Português](CONVERTER_NETWORK.pt-BR.md)

`torque_converter`는 축, 모터, 실린더, 클러치, 이상 기어와 같은 풀이에 참여합니다. 펌프와 터빈은 명시적 관성을 가진 서로 다른 회전 노드입니다. 스테이터는 정지한 접지입니다. 그 반력은 관측할 수 있지만 일은 하지 않습니다. 유체 손실은 선택적 열 노드나 외부 열 방출 장부로 갑니다. 별도의 병렬 `clutch`가 록업을 제공합니다. 실험실의 모든 매개변수는 합성값이며 `unverified`입니다.

## 명시적 맵과 방정식

맵 네 개가 필요합니다. `pump_positive`, `pump_negative`, `turbine_positive`, `turbine_negative`입니다. 절대 속도가 더 큰 부재가 기준 구동 부재입니다. 정확히 같으면 펌프가 기준이 됩니다. 그 부재의 부호가 양/음 맵을 고릅니다. 이것은 역회전 중을 포함한 수학적 기준 부재 규약입니다. 사용할 수 없는 후진이나 타행 특성을 추론하지 않습니다.

구동 속도 `wD`와 종동 속도 `wF`에 대해 `s = wF/wD`는 `[-1,1]`에 있습니다. 각 맵은 무차원 `speed_ratio`, `torque_ratio` R, `nm_s2_rad2` 단위의 `capacity_coefficient` C를 가진 명시적 점 2–32개를 담습니다. C는 속도의 제곱에 곱합니다. 역 K-factor가 아닙니다. R과 C는 선형으로 보간되며 외삽되지 않습니다. 두 속도가 모두 0이면 반력은 0이고 모드는 0입니다.

```text
Tdriver   = -C(s) * wD * abs(wD)
Tfollower =  R(s) * C(s) * wD * abs(wD)
Tstator   = -(Tpump + Tturbine)
Qdot      = C(s) * abs(wD)^3 * (1 - s*R(s))
```

컴파일은 `[-1,1]`을 덮는 엄격히 증가하는 절점, 비음수 C/R, 그리고 모든 구간에서 `s*R(s) <= 1`을 요구합니다. 절점만 검사하는 것으로는 충분하지 않습니다. R이 s에 대해 선형이면 효율은 이차입니다. 내부 최댓값도 함께 검사합니다. 기울기는 유한해야 합니다. `s=1`에서 C는 0, R은 1이어야 하며, 같은 방향의 같은 속도에서 유체 토크는 0입니다. `s=-1`에서 펌프 양/터빈 음 맵과 펌프 음/터빈 양 맵은 서로 맞는 물리 반력을 주어야 합니다. 이것은 역회전 중 기준 부재가 바뀔 때 점프를 막습니다. 끝점 비교는 `64*epsilon*(abs(a)+abs(b))`의 반올림 허용 오차만 허용합니다. 맵 배열은 소유되고 불변입니다. 정규화된 계수는 모델 지문에 들어갑니다.

이 제한은 Power!의 현재 수동 부호 맵 모델을 정의합니다. 임의의 측정 컨버터 곡선을 모두 다룬다고 주장하지는 않습니다. 맵 기반 구동/타행의 일반 규약은 [MathWorks Torque Converter](https://www.mathworks.com/help/sdl/ref/torqueconverter.html)와 그 [2모드 예제](https://de.mathworks.com/help/sdl/ug/torque-converter-two-mode.html)에 문서화되어 있습니다. 아래의 부호 있는 맵 네 개, 보간 검증, 솔버는 Power!의 설계입니다. 그 자료에서 소스 코드나 측정 매개변수 집합을 복사하지 않았습니다.

## 결합 적분과 한계

컨버터 반력은 구간 중점 속도를 씁니다. 실린더가 있으면, 결합 뉴턴 시스템이 이산 크랭크각 일과 두 컨버터 포트 속도를 함께 풉니다. 모든 단위 토크 응답에는 전기기계 시스템과 영구 기어 사영이 포함됩니다. 클러치 제약 반복은 이 같은 비선형 풀이를 호출합니다. 포획과 반전 세분은 구간 응답을 다시 만듭니다. 실린더나 클러치 적분 뒤에 지연된 컨버터 토크를 적용하지는 않습니다.

비선형 풀이는 반복 24회와, 반복마다 절반으로 줄이는 선 탐색 12회를 갖습니다. 실린더 각 잔차 허용 오차는 `2e-14 rad`입니다. 컨버터 속도 잔차는 `2e-12 + 64*epsilon*(abs(value)+abs(free_prediction)) rad/s`를 씁니다. 해석적 조각 맵 야코비안과 유한 차분 실린더 일 미분이 결합 시스템을 만듭니다. 기존의 0.25 rad 실린더 이동, 밸브/연소 해상도, 클러치 반복/이벤트, 기어 제약 한계는 그대로 적용됩니다. 기존의 32 노드, 64 컴포넌트, 64 상태 예산 안에서 컨버터는 최대 여덟 개까지 지원됩니다. 각 컨버터는 논리적인 관측 이력 상태를 네 개 더합니다. 평균 토크 두 개, 평균 열 동력, 누적 열입니다. 보정된 열 합도 복사/해시/롤백에 참여합니다.

수용된 구간의 열은 `-h*(Tp*wp_mid + Tt*wt_mid)`이므로, 제거된 기계 일이 기록된 열입니다. 풀이된 속도의 반올림 허용 오차를 넘는 음의 열은 구간을 거부합니다. 반올림 크기의 음의 잔여만 0으로 클램프합니다. 토크와 열 동력은 수용된 내부 구간에 걸쳐 지속 시간으로 가중한 뒤 전체 틱으로 나눕니다. 시험적인 이벤트 시도는 열이나 반력을 커밋하지 않습니다. 실패하거나 취소된 배치에서는 컨버터, 클러치, 기어, 가스, 연소 이력, 입력, 전역 장부 상태가 모두 롤백됩니다. 분기는 자신의 작업 공간을 소유합니다. 검사는 무할당 포획을 다룹니다.

중점 적분은 매끄러운 단독 컨버터 운동에 대해 2차입니다. 결합된 점화 모델은 명시적 벽 온도 결합과 구간 평균 클러치 브레이크어웨이를 유지하므로, 모든 전환에 걸쳐 균일한 2차를 주장하지 않습니다. 수치 실패나 정확도 조사에는 틱을 세밀하게 하세요. 세션을 다시 만들기 전에 맵 기울기, 관성/속도 척도, 클러치 제약을 검사하세요. 유효한 맵이 선택한 모든 시간 간격을 풀 수 있다는 보장은 아닙니다.

## 공유 모델과 관측 계약

JSON은 필수 `node_a`(펌프), `node_b`(터빈), `parameters` 아래의 배열 네 개, 선택적 `heat_node`를 씁니다. 컨버터 입력 채널, 캐리어 포트, 암시적 맵 기본값은 받지 않습니다. `ComponentDefinition.TorqueConverter`는 같은 Core 모델을 노출합니다. 맵 오류는 컴포넌트 ID와 `converter.pump_positive` 또는 `converter.counter_rotation` 같은 조치할 수 있는 필드를 담습니다.

| 필드 | 의미 | 단위 |
|---|---|---|
| `torque` | 마지막으로 완료된 틱의 평균 펌프 토크 | Nm |
| `torque_at_b` | 마지막으로 완료된 틱의 평균 터빈 토크 | Nm |
| `torque_at_c` | 마지막으로 완료된 틱의 평균 정지 스테이터 반력 | Nm |
| `heat_flow` | 마지막으로 완료된 틱의 평균 유체 열 동력 | W |
| `fluid_heat` | 수용된 누적 유체 열 | J |
| `speed_ratio` | 현재의 종동/구동 부호 있는 속도비. 정지 중이면 0 | fraction |
| `converter_drive` | 0 정지, 1 펌프 양, 2 펌프 음, 3 터빈 양, 4 터빈 음 | state code |

평균 토크/동력은 0에서 시작합니다. 경계 입력 업데이트는 이전 틱의 평균 출력을 다시 쓰지 않습니다. 여기서 `torque_at_c`는 스테이터 반력의 이름입니다. 이 컴포넌트에는 세 번째 로터가 없습니다. 컨버터가 있는 모델은 `quasisteady_converter_powertrain`을 공개하고 지문 태그 10을 더합니다. 컨버터가 없는 모델의 지문과 궤적은 바뀌지 않습니다. 이식 가능한 자산 v10은 맵 네 개를 모두 유지합니다. v1–v9 판독기와 진본 픽스처도 남아 있습니다.

## 실험실과 증거

MCP 예제 `fired-converter`를 요청하거나 다음을 실행하세요.

```sh
dotnet src/Power.Cli/bin/Release/net10.0/Power.Cli.dll assets/labs/fired-converter.power.json --output artifacts/reports/fired-converter.json
```

0.8초 실험실은 600 rpm 펌프와 300 rpm 터빈에서 시작해, 유성의 선과 3:1 종감속에 공급합니다. 링 제동은 감속을 고르고, 선/링 클러치는 직결을 고릅니다. 독립적으로 예정된 록업, 해제, 재포획이 유체 경로와 마찰 경로를 다룹니다. 이것은 예정된 이벤트이지, 자동 변속기 제어기가 아닙니다.

50,000 ns 틱에서 보고서 경계 87개가 모두 CLI, 이식 가능한 자산, MCP를 통해 정확히 리플레이됩니다. 모델 지문은 `839d03901973668d`이고 최종 상태 해시는 `834a679376b7a6fd`입니다. 최종 펌프/터빈 속도는 약 73.37748 rad/s, 부하 속도는 6.988331 rad/s, 유체 열은 24.27663 J, 록업 열은 22.84709 J입니다. 변속 클러치와 브레이크는 157.18199 J와 83.42289 J를 더합니다. 공유 열 노드는 301.438643 K에 도달합니다. 총 에너지 잔차는 약 `3.30e-11 J`입니다. 이 수들은 합성 과도 상태를 설명합니다.

독립 검사는 해석적 `C(s)=k(1-s), R=1` 두 관성 해, 해석적 스톨 감쇠, 2차 세밀화, 열 및 외부 열 경로, 스테이터 평형, 후진/타행/역회전 상태, 공유 컨버터 포트, 기어 반사, 록업, 전체 배치 롤백, 취소, 분기, 할당 없음을 다룹니다. 점화 모델 세밀화는 최종 속도, 유체 열, 록업 열의 무차원 결합 거리를 3,125 ns 실행과 비교하며, 틱 크기 다섯 개를 씁니다. 절대 차이도 각각 0.0002 rad/s 또는 J 아래로 제한합니다. 이벤트 근처에서는 개별 열 오차가 반분할마다 줄어들 필요는 없습니다. 이 검사는 단독 해석 차수와 별개입니다. 부호 맵 소유/검증과, 다시 서명된 잘못된 이식 가능 레코드에는 전용 검사가 있습니다.

[유압 네트워크](HYDRAULIC_NETWORK.ko.md)는 이제 압력에서 유도된 록업 및 변속 용량을 공급합니다. 유체 각운동량, 컨버터 충전/압력 동역학, 회전/프리휠 스테이터 기구, 온도 의존 물성, 펌프/조절기와 피스톤 동역학, 완전한 DCT/AT 토폴로지, ECU/TCU 협조는 열려 있습니다. 완전한 엔진 거동, OEM 측정, 차량 교정도 열려 있습니다. Studio에는 개략적인 유체 포트와 준비된 검사가 있습니다. 실제 편집기/Play/IL2CPP 증거는 별개이며 이 환경에서는 사용할 수 없습니다.
