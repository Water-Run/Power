Power! には、マネージドのシミュレーションコア、共有モデルドキュメントと移植可能なアセット、ヘッドレス CLI、MCP エージェントサービス、準備済みの Unity スタジオがあります。合成ラボラトリーは、エンジン、トランスミッション、油圧、電気の挙動を実行します。完全なパワートレイン、協調した ECU/TCU 制御、実測キャリブレーション、受け入れ済みの Unity デスクトップアプリケーションは、未完成のままです。

コアと Assets は `net10.0` と `netstandard2.1` の両方を対象にします。コアに Unity、トランスポート、モデルプロバイダー、サードパーティの依存はありません。Unity Assets のスクリプトは C# 9 を使います。Unity がロードするのは、外部 SDK がビルドした .NET Standard アセンブリです。.NET 10/C# 14 のソースをコンパイルすることはありません。

## エビデンスと限界

必須の直列コマンド `dotnet run --file tools/Build.cs -- verify` は両アセンブリ対象、実際の MCP プロセス、全ラボ、Zig アーカイブと C# ABI を検証します。件数、結果とログのパスは [VALIDATION.md](VALIDATION.md) にあります。.NET 10 上の Standard アセンブリ検証は Unity ランタイムの受け入れ証拠にはなりません。

燃料供給には[有限タンク](LIQUID_FUEL_TANK.ja.md)と[追跡可能なリリーフ戻り](LIQUID_FUEL_RETURN.ja.md)が含まれ、質量、熱/化学エネルギーと圧力仕事の収支を保持します。[油圧 AT コントローラー](AT_CONTROL.ja.md)はアクチュエーター圧力を調整し、物理的な変速段/ロックアップを確認します。独立参照と完全なトランザクションが研究モデルを支えます。完全な ECU/TCU 協調と実測ハードウェア挙動は未完成です。

現在の環境では `POWER_UNITY_EDITOR` が未設定です。Studio のインポート、再生と準備済みテストには、実際の Editor/Play、描画と Player/IL2CPP の証拠が必要です。

全パラメーターは引き続き `unverified` です。EA211 DJS + DQ200 と PSA EC5 + AT8 は [assets/samples](../assets/samples) に完全な境界と証拠マニフェストを保持します。欠落した OEM 測定値は補完しません。ライセンスと歴史的ソース来歴を保持しています。

CLI `list-labs`、MCP サンプル検出と直列検証は[共通ラボカタログ](../assets/labs/catalog.json)を使用します。検証は全ラボのソースが含まれることを確認します。

## 次の開発順序

1. 圧力依存の相平衡、キャビテーション、実測ポンプ充液/調圧、精密な磁気/電子駆動を拡張します。 有限な液体容積と噴霧運動量が分解されたら、宣言された書き出し押しのけ仕事の境界を置き換えます。供給された液体、蒸発した燃料、反応は別々に観測できるままにし、独立した参照を残します。
2. 点火制御、吸排気の動特性、機械損失、より豊富な熱化学でエンジンを拡張します。完全なエンジン目標を保ちます。
3. DCT 駆動と実測の遊星歯車/AT 油圧を拡張し、既存のサンプル DCT・AT 制御で ECU/TCU のトルク要求と変速を協調させます。実測センサー、アクチュエーターと回復可能な故障を追加します。
4. ピン留めされたエディターで `unity-test` を実行し、Player/IL2CPP のエビデンスを取得します。チャンネル選択、グラフ編集、保存は、別の機能として完成させます。
5. キャリブレーション済みサンプルやリリース準備を宣言する前に、2 つの対象パワートレインについて、実測マップ、OEM データ、不確かさバジェットを取得します。
