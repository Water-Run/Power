コアと Assets は `net10.0` と `netstandard2.1` の両方を対象にします。コアに Unity、トランスポート、モデルプロバイダー、サードパーティの依存はありません。Unity Assets のスクリプトは C# 9 を使います。Unity がロードするのは、外部 SDK がビルドした .NET Standard アセンブリです。.NET 10/C# 14 のソースをコンパイルすることはありません。

## エビデンスと限界

[AT 油圧駆動グラフ](AT_HYDRAULIC_ACTUATION.ja.md) は、共有のシャフト駆動ポンプから、5 つのレンジ要素すべてと、任意のコンバーターロックアップへ供給します。明示的な充填/排出経路、有限なピストン運動、戻しばね、パッドから導かれる容量は、油圧の押しのけ仕事と、実際の捕捉/解放の挙動を保持します。規定バルブは、センサー確認済みの AT 制御でも、実測のバルブボディ受け入れでもありません。完全なパワートレイン挙動と実測の受け入れは、未完成のままです。

必要な逐次コマンド `dotnet run --file tools/Build.cs -- verify` は、Windows x64 でローカルに合格しています。対象は、.NET 10 上でホストされる両方のアセンブリターゲット、実際の MCP 子プロセス、すべてのラボラトリーレポート、Zig アーカイブ、C# ABI です。現在の件数、ログパス、スキーマ検査、数値結果、保持された CI 来歴は [VALIDATION.md](VALIDATION.ja.md) にあります。.NET 10 上の .NET Standard アセンブリテストは、Unity ランタイム互換を確立しません。

[液体フィルムの増分](FUEL_FILM.ja.md) には、加熱/飽和/ドライアウトの解析検査、独立した同時 ODE 参照、質量/化学/熱の保存、移植可能なリプレイ、完全なセッショントランザクションがあります。対称なフィルム順序は、壁を共有するフィルムに 2 次の滑らかな精細化を与えます。他の壁面熱源への結合は、既存の 1 次の明示壁限界を保持します。厳密なリプレイは、時間刻みの精度、KPI の合格、キャリブレーション済み物理とは別です。

[Ravigneaux 研究グラフ](RAVIGNEAUX_TRANSMISSION.ja.md) は、単一/二重ピニオン拘束、5 つの摩擦経路、4 つの前進レンジ、リバースを追加します。独立した自由質量、反映慣性、ブレーキ捕捉の参照が、ポート反力と熱を検査します。共有トルクと燃焼/コンバーターの実験は、完全なリプレイと明示的な研究境界を保ちます。縮小経路は遊星自転を省きます。詳細な油圧、AT 制御、OEM トポロジー/キャリブレーションは未完成のままです。[分解オプション](RESOLVED_PLANETS.ja.md) は、4 つの実際の噛み合い、2 つの絶対自転ローター、明示的な軌道慣性を追加します。独立した 6 ローターの質量、角運動量、捕捉の参照が、それらのエネルギーを保持します。詳細な歯/潤滑/荷重分担の挙動には、まだエビデンスが必要です。

[サンプリング DCT コントローラー](DCT_CONTROL.ja.md) は、駆動/セレクター指令を所有し、無負荷経路をプリセレクトし、物理的な同期/ロックを待ち、排他的で段階的な解放/係合を行います。整数の段要求、ニュートラル中断、方向/タイムアウト/持続ロックの故障、新しい要求による回復は、観測できます。確認済みの段は、以前の確認のあとでも、過渡滑りのあいだ一時的にゼロになり得ます。制御された長い歯車運転は、トランザクションな補償座標を使い、厳密な位相許容差は変わりません。明示的な状態上限は 128 です。ノードとコンポーネントの上限は 32/64 のままで、70 状態の燃焼/コントローラー構成を許せます。トルクを完全にブレンドする変速、アクチュエーター、包括的な ECU/TCU 故障は、まだ開いています。

[デュアルクラッチの増分](DUAL_CLUTCH_TRANSMISSION.ja.md) は、7 つの前進経路、偶数経路のリバースアイドラー、3 つの出力/ファイナルドライブ分岐、明示的な摩擦セレクターを組み立てるようになりました。独立した符号付き/反映慣性と、プリセレクトの力積/熱の参照が、動力経路を検証します。トルク実験と燃焼実験は、通常のグラフ/アセット/エージェントの各層を通じてリプレイします。有界で正規化された線形ロックのフォールバックが、以前失敗していた 6/7 の引き継ぎを解き、既存の軌跡を回帰として残します。規定された選択/引き継ぎは、完全な TCU でも、詳細なドッグ/ボルクリング/アクチュエーター挙動でもありません。パラメーターと OEM サンプルは未検証のままです。

[クロージャ補償の増分](CLOSURE_PREDICTION.ja.md) は、状態を確定せずに、入力を保持した有界なプラントの未来をリプレイします。残るニードル流量を予測し、物理ティック格子の上で電圧除去を計画します。孤立したドーズ追従は改善しますが、実際の閉じ/反発と、燃料/エネルギーの履歴は、変わらない物理機構のままです。読み取り専用の予測、整数境界、ホライズンの精細化、ゼロ割り当て、完全なトランザクションは検証済みです。予測は他の指令を保持し、将来の外部入力イベントを省きます。そのモデルと有限ホライズンは明示的な限界であり、キャリブレーションや完全な ECU 受け入れではありません。

[ニードルの増分](NEEDLE_ACTUATION.ja.md) は、磁束エネルギーと相反力を、実際のニードル質量、ばね/減衰、弾性ストッパへ結合します。整数サンプリングは、供給ドーズのフィードバックからコイル電圧を所有します。流体は、閉じ遅れと反発を通る物理的なリフトに支配されたままで、目標へ切り取られることはありません。独立した磁気/RL/運動の参照、源/相/電気/熱の台帳、移植可能/MCP のリプレイ、完全なコントローラートランザクションは合格しています。過剰供給と、実験境界に残る液体は観測できます。これらの結果は、キャリブレーション済みのドーズ追従や、完全なインジェクター電子/磁気を確立しません。

[液体噴射の増分](LIQUID_FUEL_INJECTION.ja.md) は、乾いたフィルムから始まり、有限で柔軟な源から引きます。レール圧力/仕事の解析、独立した同時精細化、完全な源/フィルム/化学/熱の台帳、実際の MCP リプレイ、投機的なクラッチロールバックは合格しています。レール圧力エネルギーは蓄えられます。ノズル熱と、書き出された受け側圧力仕事は、別のままです。液体容積を無視できる受け側の縮小は明示であり、追加のガス容積仕事やクランク仕事として数えません。 形状容量、通気/気相空間/揺動、キャビテーション、実測充液/効率/調圧、解像噴霧は未完了です。パラメーターは `unverified` で、実際の Unity Editor/Play/Player/IL2CPP と OEM 校正は未検証です。

`film-fired-cylinder` は、最初に宣言された液体在庫を含みます。規定反応の前に、その在庫を加熱して蒸発させます。液体インジェクターは実装しません。準備済みのスタジオマーカーとテストは、同じ定義を使います。`POWER_UNITY_EDITOR` は未設定なので、実際の Editor/Play、レンダリング、Player/IL2CPP は未検証のままです。

研究パラメーターはすべて `unverified` のままです。EA211 DJS + DQ200 と PSA EC5 + AT8 は、完全なパワートレイン境界とエビデンスマニフェストを [assets/samples](../assets/samples) に保持します。欠けている OEM 計測は、欠けたままです。ライセンスと歴史的なソース来歴は保持されます。

## 次の開発順序

1. 有限タンクに形状容量、通気/気相空間の動特性、実測ポンプ充液/調圧、精密な磁気/電子駆動を追加します。 有限な液体容積と噴霧運動量が分解されたら、宣言された書き出し押しのけ仕事の境界を置き換えます。供給された液体、蒸発した燃料、反応は別々に観測できるままにし、独立した参照を残します。
2. 点火制御、吸排気の動特性、機械損失、より豊富な熱化学でエンジンを拡張します。完全なエンジン目標を保ちます。
3. 検証済みの DCT 研究経路を、詳細なアクチュエーション、実測の遊星物性/損失、完全な AT 油圧/制御で拡張し、検証済みの歯車、クラッチ、コンバーター、油圧原始素から ECU/TCU の変速/トルク協調を築きます。有界なコントローラー状態、センサー/アクチュエーター挙動、故障回復を追加します。
4. ピン留めされたエディターで `unity-test` を実行し、Player/IL2CPP のエビデンスを取得します。チャンネル選択、グラフ編集、保存は、別の機能として完成させます。
5. キャリブレーション済みサンプルやリリース準備を宣言する前に、2 つの対象パワートレインについて、実測マップ、OEM データ、不確かさバジェットを取得します。

## 油圧 AT フィードバック

`at_controller` は [-1,4] の整数目標段を受け取り、ゼロはニュートラルです。五組の充填/排油弁と任意のトルクコンバーターのロックアップを管理します。経路の順序はキャリア入力、小サン入力、大サン入力、キャリアブレーキ、大サンブレーキ、最後にロックアップです。

例 `controlled-hydraulic-ravigneaux` と `controlled-fired-hydraulic-ravigneaux` は要求チャンネル 900 とコントローラー ID 1400 を使います。変更していない 128 状態の上限内で 99 と 122 の報告状態を保ちます。v27 は経路、ゲイン、時計を保存し、v1-v26 を読みます。

研究用の制御であり、パラメーターは `unverified` のままです。ECU トルク協調、詳細なセンサー/弁、包括的な車両故障、OEM 校正は未完成です。managed と Standard の検査は実際の Unity Editor/Play/Player/IL2CPP の受入を証明しません。

## ポンプ供給の液体燃料レール

`liquid_rail_feed` は液体噴射器を既存の容積ポンプと明示的な物質/熱境界に結びます。油圧出口ノードはレールのコンプライアンスと初期絶対圧に一致する必要があります。ポンプと噴射器がこの圧力ノードを所有し、未追跡の他の流体経路は拒否されます。

v27 は補給接続と源温度を保存し v1-v26 を読みます。軸/圧力の解析交換、独立した同時 ODE 細化、熱混合、質量/燃料/エネルギー/体積台帳、逆流と完全 rollback は別々に検査します。

形状容量、通気/気相空間/揺動、キャビテーション、実測充液/効率/調圧、解像噴霧は未完了です。パラメーターは `unverified` で、実際の Unity Editor/Play/Player/IL2CPP と OEM 校正は未検証です。

## 有限液体燃料タンク

`liquid_fuel_tank` は対応する噴射器の密度、フィルム熱基準、発熱量を使い、有限液体質量と熱エネルギーを保存します。補給は `tank_component` で選び、`supply_temperature` を省略します。各タンクは燃料物性が一致する一つの補給に属します。

タンクの熱/化学エネルギーは全貯蔵台帳に入ります。内部移送は外部質量や化学供給を追加しません。明示したポンプ入口規定圧は圧力仕事境界を保持します。ガス吸排気は化学境界エネルギーを運ぶ場合があります。

形状容量、通気/気相空間/揺動、キャビテーション、実測充液/効率/調圧、解像噴霧は未完了です。パラメーターは `unverified` で、実際の Unity Editor/Play/Player/IL2CPP と OEM 校正は未検証です。
