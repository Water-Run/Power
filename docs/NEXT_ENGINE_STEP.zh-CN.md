开发应所有者要求于 2026-09-14 恢复。独立气体原语与编译后的核心网络现已实现。下方 2026-09-22 集成检查点更新了剩余范围。此前的封闭气缸基线已在 Windows、macOS 与 Linux 上通过托管验证。真实的 Unity 编辑器与 Player 证据仍待完成;参见 [验证记录](VALIDATION.zh-CN.md)。

**2026-09-14 的后续检查点:** [核心气体网络](GAS_NETWORK.zh-CN.md) 现已实现定容气体节点、储气库节流、受控开度、热链、通道、账本、分支与回滚。有界 Heun 方法对光滑流动有解析与细化证据,并带有显式壁面耦合与近平衡守恒限制器。它不是所提议的隐式方法。

**2026-09-22 集成:** JSON/schema、资产 v3、CLI/MCP 发现与示例、可移植回放以及 Unity 示意视图均已实现。变更前的 v1/v2 读取器与夹具予以保留。Unity 编辑器/Play 验证仍待完成。随后的 [运动气缸增量](MOVING_CYLINDER.zh-CN.md) 通过 JSON、资产与智能体加入换气与曲轴功。随后的 [曲轴转角定时增量](VALVE_TIMING.zh-CN.md) 通过同一批接口加入显式的 360/720 度曲线、反转与有界凸轮分辨率。最新的发动机检查点包含 [预混燃烧](PREMIXED_COMBUSTION.zh-CN.md),带有输运的燃油/空气/产物、限制反应物与化学能记账。详细热化学、燃油计量与点火控制仍是发动机工作。

核心网络现在提供显式的气体质量与内能状态。运动气缸元件把它们耦合到随曲轴变化的气室,并带有守恒的压力功。当前封闭气缸由转角与不可变初始熵导出气体状态,不能表示换气或壁面加热。该元件仍是解析基准;有限气室、储气库、气缸、受控孔口与气体到热节点的连接现在在编译图中并存。

原始增量契约(用上方检查点区分已完成的核心工作与剩余集成):

- 气体节流引用稳定的气体节点 ID;未来的气缸必须显式定义其运动容积端点。气缸还连接到一个转动节点;热链把有限气体容积连到一个热节点。支持纯气体网络,不要求虚设的机械节点。
- 独立追踪质量与内能,并做正有限状态校验。质量与上游焓一起传递。在外部质量与能量账本中追踪储气库交换;内部传递必须抵消。在实现组分/物种混合之前,把相连气体限制为相同的气体常数与 gamma。
- 暴露有符号质量流、气体状态、热流与质量残差通道。孔口开度使用 `[0,1]` 内的显式无量纲分数,直接输入与排程输入使用同一套校验。
- 研究一种有界的成对隐式传递求解,由相连一对的等压状态括住。通过现有曲轴求解耦合气缸压力功。带后向欧拉流动的分裂方法对换气将是一阶的;仅有守恒并不能证明精度。采用所提议的方法之前先验证它。
- 保留完整批量回滚、状态哈希与分支中的修正项、取消、不可变编译模型,以及成功步进期间的零分配。求解器失败必须返回可操作的指导。
- 一起扩展 JSON schema、可移植资产、能力发现、示例、报告与 Unity 视图。如果需要新的资产版本,保留 v1/v2 读取器,并测试真实的变更前夹具。求解器语义不变时,保留现有模型指纹。

所需证据包括临界与亚临界喷嘴流动、解析绝热容器放气、储气库充气焓、封闭网络的质量/能量守恒、压力均衡、气体/壁面热交换、步长细化、反向流动、关阀隔离、耦合曲轴功、畸形拓扑/输入拒绝、失败批次恢复、分支,以及完整的 CLI/MCP/资产回放。

研究起点:[NASA 质量流壅塞](https://www.grc.nasa.gov/www/k-12/BGP/mflchk.html) 说明理想可压缩喷嘴流动,[Cantera 反应器相互作用](https://www.cantera.org/stable/reference/reactors/interactions.html) 说明控制容积边界与壁面概念。这些参考文献不是运行时依赖,也不构成对 Power! 所提议求解器的验证。

一份真实的变更前气缸 v2 资产现保留在 [兼容性夹具](../tests/Power.Tests/Fixtures/README.md) 中,带有其源提交与 SHA-256。现行测试在升级到 v3 后验证其指纹与回放;不要用新编码器重新生成它。

完整发动机行为、预测燃烧/热化学、机械配气机构动力学、变速器、控制与标定车辆样本仍未完成。保留全部样本证据边界。归档的原生原型已移植到 [原生边界](NATIVE_ZIG.zh-CN.md) 下的 **Zig**;现行 C#/Unity 实现保持原位。
