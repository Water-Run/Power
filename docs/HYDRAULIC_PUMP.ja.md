# シャフト駆動の油圧供給

[English](HYDRAULIC_PUMP.md) · [简体中文](HYDRAULIC_PUMP.zh-CN.md) · [Français](HYDRAULIC_PUMP.fr.md) · [Русский](HYDRAULIC_PUMP.ru.md) · **日本語** · [한국어](HYDRAULIC_PUMP.ko.md) · [Deutsch](HYDRAULIC_PUMP.de.md) · [Español](HYDRAULIC_PUMP.es.md) · [Italiano](HYDRAULIC_PUMP.it.md) · [Português](HYDRAULIC_PUMP.pt-BR.md)

マネージドグラフは、理想的な可逆押しのけポンプと、準定常の一方向圧力リリーフに対応します。[燃焼ポンプのラボラトリー](../assets/labs/fired-pump.power.json)は、クランクをコンプライアントな供給ライン、変速バルブ、圧力作動クラッチへつなぎます。そのパラメーターは合成値で、`unverified` です。

## 方程式と動力

押しのけ容積 `D > 0` の単位は m³/rad です。正の軸速度は、入口から出口へ基準体積を送ります。

```
Q = D * omega
shaft reaction = -D * (p_out - p_in)
shaft-to-fluid power = Q * (p_out - p_in) = -shaft reaction * omega
```

逆流と油圧モータリングは許されます。推定されるチェックバルブ、漏れ、摩擦、効率マップはありません。慣性は明示的な軸ノードに属します。有限の入口は、出口へ送った体積をちょうど失います。リザーバー入口は `p_in * Q` を外部油圧仕事へ寄与します。軸から流体への仕事は内部移送であり、大域の源仕事には加えません。

リリーフは、明示的な線形の超過圧力特性を使います。

```
Q_A_to_B = G * max(p_A - p_B - p_crack, 0)
heat = Q_A_to_B * (p_A - p_B)
```

`G >= 0` の単位は m³/(s·Pa) で、`p_crack >= 0` は差圧です。しきい値未満では正確に密封します。有限の流量には過圧が必要です。圧力が設定値へクランプされることはありません。これは構成関係の近似であり、スプール機構や、適合されたバルブ開口面積曲線ではありません。圧力降下の全体が熱を生成し、クラッキング圧の部分も含みます。

理想ポンプの方程式は、[MathWorks の固定押しのけポンプの説明](https://www.mathworks.com/help/hydro/ref/fixeddisplacementpumpil.html)の損失零の極限に従います。しきい値の挙動は[圧力リリーフバルブの説明](https://www.mathworks.com/help/hydro/ref/pressurereliefvalveil.html)と整合します。Power! の線形な超過圧力の法則は、明示的により単純なモデル化の選択です。これらの参考文献が供給するのは方程式と範囲であり、OEM パラメーターの計測やソースコードではありません。

## 共有契約

`hydraulic_pump` は、回転の `node_a`、油圧出口 `node_b`、`parameters.inlet_node`（零はリザーバーを選ぶ）を必要とします。入口は出口と異ならなければなりません。パラメーターは、`m3_rad` の正の `displacement` と、入口が零のときだけの `pa` または `bar` の明示的な `reservoir_pressure` を含みます。入力、熱シンク、遊星の `node_c` はありません。

`hydraulic_relief` は、油圧 `node_a`、任意の油圧 `node_b`（零/省略はリザーバーを選ぶ）、任意の熱 `heat_node`、パラメーター `coefficient`、`cracking_pressure`、リザーバーだけの `reservoir_pressure` を使います。開度入力はありません。バルブスケジュールは、引き続き別の制御された絞りを使います。

ポンプ出力は、直前ティックの平均 `volume_flow`、軸反力 `torque`、符号付き `hydraulic_power`、累積の符号付き `hydraulic_work` です。初期履歴は零です。入力の変更は、受理された平均を変えません。大域の `hydraulic_work` は外部リザーバー仕事のままです。リリーフ出力は、絞りの流量、平均熱動力、累積流体熱を再利用します。すべての入力、履歴、補償項は、分岐、ハッシュ、キャンセル、バッチ全体のロールバックに加わります。アセット v11 は新しい定義と、v1–v10 のすべてのリーダーを保持します。エージェント 0.13.0 は `shaft_driven_hydraulics` と `fired-pump` を表明します。

## 数値エビデンスと限界

ポンプ速度、チャンバー圧力、コンバーターポート速度、気筒仕事は、歯車で射影された機械応答を使い、1 つの Newton 系を共有します。圧力クラッチの容量は、有界な拘束反復の中で更新されます。受理された流体移送は、両方のポートと基準体積の台帳を更新します。ポンプのないモデルでは既存の独立した油圧経路が保たれ、以前のリプレイハッシュも保たれます。

連成 Newton 求解が許すのは 24 回の反復と 12 回の直線探索の半分化です。油圧の圧力残差許容差は `2e-7 Pa + 64*epsilon*(|p_mid|+|p_old|)` です。機械とクラッチの許容差は既存の契約を保ちます。非有限な状態、受理された負のゲージ圧、使い切ったソルバー予算は、呼び出し全体を拒否します。再試行の前に `step_ns` を減らし、圧力、コンプライアンス、押しのけ容積、慣性、クラッチの尺度を調べてください。キャビテーションクランプはありません。

テストは、解析的な軸/コンプライアンス振動と二次の細分化、閉じた入口の保存、逆方向のモータリング、歯車を介したポンプ反力、解析的なリリーフ減衰、調圧された定常軸負荷、独立した解析的な圧力依存の滑りクラッチ解を扱います。捕捉、分岐、キャンセル、遅発の失敗、再試行、割り当てなしのステッピングが検査されます。移植可能/MCP のリプレイは、89 の燃焼ポンプ境界をすべて比べます。不正な契約とバージョンのダウングレードは拒否されます。

0.8 s の燃焼実験では、軸が流体へ 53.94250162 J を送り、外部油圧仕事は零、リリーフは 45.02640514 J を散逸します。初期油圧エネルギーは明示的に 3 J です。最終ライン圧は 1.06972624 MPa、クランク/タービン速度は 69.75553569 rad/s、負荷速度は 6.64338435 rad/s です。全エネルギー残差は約 `1.07e-9 J`、基準体積残差は `3.05e-20 m³` です。フィンガープリントは `d0bd8f29a706fd89`、最終ハッシュは `572150ab5d66a2f6` です。

実測損失マップ、押しのけ容積制御、電池と電圧制御の動特性、スプールとピストンの行程/慣性、ガスアキュムレーター、キャビテーション、温度依存の物性、ECU/TCU 協調は未解決です。このチェックポイントは、完全な DCT/AT、キャリブレーション済みの車両性能、Unity エディター/Player の受理を確立しません。

## 明示的な漏れ、軸摩擦、電気供給

`HydraulicPumpAssembly` は、再利用できる一定係数のポンプ縮約を供給します。m³/rad の押しのけ容積 D、m³/(s·Pa) の漏れコンダクタンス G、N·m·s/rad の粘性軸摩擦 B を受理します。D は正でなければなりません。G と B は非負かつ有限でなければなりません。公称効率や油の物性は推定されません。

差圧 `dp = p_out - p_in` について:

```text
net inlet-to-outlet flow = D*omega - G*dp
shaft reaction          = -D*dp - B*omega
leakage heat power      = G*dp^2
shaft friction heat     = B*omega^2
absorbed shaft power    = net fluid power + leakage heat + shaft friction heat
```

符号は、どちらの向きのポンプ作用と油圧モータリングも、停止したポンプを通る漏れも支えます。漏れは、押しのけ流量を超えても、受動的な出口から入口への経路のままです。一定コンダクタンスの漏れ縮約は、[MathWorks のポンプ参考文献](https://www.mathworks.com/help/hydro/ref/fixeddisplacementpumpil.html)にある解析的な損失の記述に従います。線形粘性抵抗は明示的な Power! の構成関係としての選択です。その参考文献の圧力依存摩擦モデルでも、OEM 効率マップでもありません。

`TryEvaluate` は、瞬間の正味流量、合計軸反力、符号付きの軸/流体動力、2 つの非負の損失動力を返します。負のゲージ圧、非有限な入力、オーバーフローは拒否し、部分的な反力は返しません。

`CreateComponents` は、明示的で別々の ID を持つ不変リストを返します。理想的な `hydraulic_pump`、出口から入口への固定開度の `hydraulic_resistance`、ポンプ軸から接地への剛性零の `shaft` です。熱シンクを指定するか、損失を外部熱排出へ入れてください。モデルコンパイラはポート、領域、単位、大域 ID を検査します。通常のコンポーネントは、連成中点求解、トランザクション、チャンネル、JSON スキーマ、アセット v11 を保ちます。隠れたアセンブリ状態や新しい形式はありません。ポンプチャンネルは理想分枝を記述します。アセンブリの吐出を得るには漏れ流量を引いてください。合計軸負荷を解釈するときは軸抵抗を含めてください。理想ポンプ仕事を、外部源仕事と内部移送の両方として数えないでください。

`fired-pump-losses` は、漏れと抵抗を既存の燃焼トランスミッションへつなぎます。別のポンプ熱ノードが両方の損失を受けます。損失零の極限は、`fired-pump` の共有するすべての観測量を、物理許容差の範囲で再現します。一定の G と B は研究入力であり、`unverified` のままです。

`electric-pump` は、12 V の RL 直流モーターを別のポンプ軸へつなぎ、明示的な逆起電力、インダクタンス、トルク、銅損熱を持ちます。コンプライアントな供給ライン、リリーフ、スケジュールされた充填/排出バルブが、駆動される軸と負荷の間のクラッチを作動します。電圧の変化とバルブイベントは正確なティックを使います。ポンプにクランク接続はなく、外部油圧仕事は零です。電気仕事は大域の源仕事に含まれます。駆動される軸と負荷トルクは、別の外部動力境界です。規定された電圧とバルブ指令は、電池、ECU/TCU、閉ループレギュレーターを実装しません。

解析的な減衰のある軸/圧力運動と、独立に積分した 3 状態の RL モーター/軸/圧力 ODE が、滑らかな二次の細分化を検査します。閉じた入口、リザーバー仕事、符号付きの動作、受動損失、熱の経路指定、ゼロ割り当て、分岐、キャンセル、遅発の失敗のロールバックは、両方の Core アセンブリに対して検査されます。JSON、移植可能アセット、MCP は、89 の燃焼損失境界と 106 の電気レポート境界をすべて比べます。用意された Unity のインポート/Play テストには、別のエディター実行が必要です。

## サンプリング圧力調整

`pressure_controller` は油圧ゲージ圧のノードを読み、既存の直流モーター電圧チャンネルを所有します。これは離散 PI 制御器で、`v_pa` の明示的な比例ゲイン、`v_pa_s` の積分ゲイン、電圧の限界、初期積分電圧を持ちます。設定値入力は圧力単位です。整数の `sample_period_ns` は 1 ns..1 s で、モデルティックの正確な倍数でなければなりません。ゲインと圧力設定値は非負です。電圧限界は有限で、厳密に増加します。調整は推定されません。

```text
error = setpoint - sampled_pressure
I_candidate = I + Ki * sample_period_s * error
raw_voltage = Kp * error + I_candidate
if raw_voltage exceeds a limit and the integral increment pushes farther outside:
    retain the preceding integral state
command = clamp(Kp * error + accepted_integral, minimum_voltage, maximum_voltage)
```

条件付き積分は、[MathWorks の制御参考文献](https://www.mathworks.com/help/simulink/slref/anti-windup-control-using-a-pid-controller.html)が述べる、クランプによるアンチワインドアップ戦略です。上の Power! の正確な離散遷移は、宣言されたモデルであり、コピーされた実装コードや OEM 調整のエビデンスではありません。飽和だけでは追従は確立しません。到達できない目標は、実行とリプレイに成功しつつ KPI に失敗し得ます。

サンプルは時刻零と、設定された周期の絶対倍数で起きます。最初のサンプルは、明示的に与えられた初期積分を保ちます。後のサンプルは周期を使います。指令はサンプルの間保持されます。正確なティックのイベントは、同じティックのサンプルより前に適用されます。呼び出しの端点にあるイベントは、スナップショットの前に設定値を更新します。その端点でのサンプリングが起きるのは、次の物理ティックが始まるときだけです。内部のクラッチ捕捉/反転の区間は、余分な制御器更新を引き起こしません。

コンパイラは、対象が直流モーターの電圧入力で所有者が正確に 1 つであること、センサーが油圧であること、初期モーター電圧が限界内であることを検査します。所有された電圧チャンネルはコンポーネント定義に残りますが、外部入力リストにはありません。直接の書き込みとスケジュールされた電圧の上書きは拒否されます。代わりに制御器の `pressure_setpoint` 入力を変えてください。他のモーター、ポンプ、バルブのチャンネルは既存の意味を保ちます。複数の独立したループが圧力センサーを共有できます。

観測チャンネルは `sampled_pressure`、`pressure_error`、`integral_voltage`、`command_voltage` です。圧力/誤差の履歴は零から始まります。初期指令はモーターの設定電圧で、初期積分は明示的です。履歴が記述するのは最新のサンプルであり、連続的に再計算された圧力誤差ではありません。4 つの制御器状態と保持されたモーター入力はすべて、ハッシュ、分岐、完全なバッチロールバックに加わります。サンプリングと成功したステッピングは、ウォームアップ後にマネージドメモリを割り当てません。非有限な PI 算術は呼び出し全体を拒否します。ゲイン、設定値、積分の尺度を調べてください。

制御器は、物理的な蓄積エネルギーや動力境界を加えません。その指令は既存モーターの電圧境界を変え、その電流、仕事、銅損熱は連成求解と保存台帳に残ります。制御器のないモデルはフィンガープリントとステッピングを保ちます。制御されたモデルはフィンガープリントタグ 13 を加えます。アセット v12 は完全な制御器定義を保持します。真正な v11 のポンプフィクスチャは、アップグレード後も元のダイジェスト、フィンガープリント、同じランタイムのリプレイを保ちます。

`pressure-regulated-pump` は 5 ms の制御器と 100 µs の物理ティックを使い、スケジュールされたクラッチの充填/排出の外乱と、300/350/200 kPa の目標を持ちます。ゲイン、アクチュエーター限界、他のすべてのパラメーターは `unverified` のままです。一致する JSON、アセット、MCP のレポート境界は 757 です。テストは、別のサンプリング制御器/RK4 プラントを比べ、固定した制御器周期での物理ティック細分化、正確な時計/端点の規則、飽和からの回復、単位/所有の診断、制御器状態のロールバック、分岐、ゼロ割り当て、完全な電気/油圧の仕事台帳を検査します。

これが供給するのは 1 つの圧力フィードバックループです。電池と PWM/電流ループの動特性、センサーのフィルタ/遅れ/量子化、バルブ/スプール/ピストンの動特性、ECU/TCU 協調、完全な DCT/AT、故障、実測キャリブレーションは、別の未完了の作業のままです。

## 有限電池の供給とデューティー調整

`battery` ノードは 2 つの状態を所有します。充電割合 z と分極電圧 v_p です。その貯蔵は C または Ah の明示的な充電容量 Q（1 Ah = 3600 C）です。初期状態は `fraction` の SOC、位置は V の初期分極電圧です。電池レコードは、空/満の開回路電圧、直列抵抗 R0、分極抵抗 Rp、静電容量 Cp、熱シンクまたは外部熱排出を供給します。開回路電圧は SOC についてアフィンです。

```text
E(z)       = V_empty + (V_full - V_empty)*z
z'         = -I_battery / Q
v_p'       = I_battery / Cp - v_p/(Rp*Cp)
V_bus      = E(z) - v_p - R0*I_battery
U_chemical = Q*(V_empty*z + (V_full - V_empty)*z^2/2)
U_polar    = Cp*v_p^2/2
heat power = R0*I_battery^2 + v_p^2/Rp
```

正の電流は放電し、負の電流は充電します。トポロジーは[電池等価回路の説明](https://www.mathworks.com/help/simscape-battery/ref/batteryequivalentcircuit.html)に従います。アフィンな開回路電圧と一定パラメーターは、明示的な Power! の縮約であり、温度/経年の表、実測化学、容量劣化、BMS ではありません。SOC は [0,1] に留まります。充電在庫を超えること、または負のバス電圧を得ることは、バッチ全体を拒否します。黙ったクランプや、作られた予備はありません。バッチを短くするか、放電/充電を止めるか、宣言された別の初期条件を与えてください。

`battery_motor` は回転軸を電池バスへつなぎ、明示的なモーター抵抗、インダクタンス、トルク/逆起電力係数、初期電流を保ちます。その平均化された双方向デューティー入力は [-1,1] です。モーター電圧はデューティー掛けるバス電圧、電池側電流はデューティー掛けるモーター電流です。その電力移送は内部であり、`source_work` には加えません。モーターの誘導エネルギーと、電池の分極/化学エネルギーは、蓄えられた全エネルギーに加わります。銅損、直列、分極の熱は、明示的なシンクへ送られます。これは理想的な平均化コンバーターであり、PWM スイッチング、コンバーター損失、コンタクター、電流制御ループではありません。

`resistive_load` は、明示的な正の抵抗、[0,1] の任意の開度入力、熱シンクを供給します。開度はコンダクタンスをスケールします。開度零は正確に切断します。合計負荷コンダクタンス G とモーター側バス電流 I_m について:

```text
V_bus     = (E(z) - v_p - R0*I_m)/(1 + R0*G)
I_battery = I_m + G*V_bus
load heat = opening*V_bus^2/R_load
```

共有された電池抵抗がすべての消費者を連成します。連成中点行列は、充電、分極、モーター電流、機械応答を含みます。シミュレーションが所有する因子は、デューティー、アクセサリー開度、または内部区間の時間が変わると更新されます。歯車、気筒、コンバーター、クラッチの応答は、この同じ因子を使います。電力のないより古いモデルは、以前のソルバー経路とフィンガープリントを保ちます。アフィンな化学エネルギーと RC エネルギーは二次なので、中点の電気移送には独立した保存検査があります。同じ物理がモーター回生を支えます。

`pressure_duty_controller` は、既存の整数時計の PI/クランプ遷移を使います。ゲインは `fraction_pa` と `fraction_pa_s`、明示的なデューティー限界は [-1,1] 以内、初期積分デューティーを持ちます。`battery_motor` のデューティーチャンネルを所有します。エージェントは `pressure_setpoint` を変えます。デューティーの直接上書きは `controlled_input` を返します。`sampled_pressure`、`pressure_error`、`integral_duty`、`command_duty` を読んでください。保持されたデューティー、充電、分極、制御メモリは、スナップショット、分岐、キャンセル、完全なロールバックを共有します。サンプリングと成功したステッピングは割り当てなしのままです。

`battery-regulated-pump` は、有限電池の供給、アクセサリー負荷パルス、5 ms のデューティーレギュレーターを、圧力クラッチのラボラトリーと組み合わせます。その 50 C の容量は小さな合成テスト在庫であり、車両電池の計測ではありません。15 s で SOC は 0.8 から約 0.627 へ下がり、圧力は 200 kPa の目標に対して約 200.828 kPa で終わります。761 の JSON/アセット/MCP 境界はすべて一致します。テストは別に、解析的な RC 緩和、抵抗負荷の在庫、独立したモーター/回路の RK4 積分、物理ティックの細分化、符号付きデューティーと回生、並列巻線の等価、歯車/クラッチ/ポンプの連成、遅発の枯渇ロールバック、分岐、キャンセル、ゼロ割り当てを検査します。

電池の BMS/化学/経年と温度フィードバック、故障/コンタクター、PWM/電流制御、センサー動特性、アクチュエーター機構、完全な ECU/TCU、キャリブレーションは未解決です。電池パラメーターとすべてのラボラトリー入力は `unverified` のままです。
