# Power! 开发路线图

[English](ROADMAP.md) · **简体中文** · [Français](ROADMAP.fr.md) · [Русский](ROADMAP.ru.md) · [日本語](ROADMAP.ja.md) · [한국어](ROADMAP.ko.md) · [Deutsch](ROADMAP.de.md) · [Español](ROADMAP.es.md) · [Italiano](ROADMAP.it.md) · [Português](ROADMAP.pt-BR.md)

目标是完整的 Power! 动力总成平台:现代 C# 物理、Unity 3D 工作室,以及智能体的直接操作。通过的合成实验室只确立一项有界数值结果;发动机、变速器、控制、车辆标定与桌面验收各自需要自己的证据。

## 里程碑

| 里程碑 | 已有基础 | 仍需完成的工作 |
|---|---|---|
| 托管核心 | 双目标、无依赖的物理、拓扑、单位、整数时间、回放与原子事务 | 长期集成动力总成验证 |
| 智能体接口 | 由 schema 定义的 MCP 工具、结构化诊断、修订号、分支、取消与紧凑报告 | 面向剩余完整动力总成范围的建模/控制工作流 |
| Unity 工作室 | 共享模型导入、实验室回放、3D 示意元件与已准备的测试 | 真实的编辑器/Play/Player/IL2CPP 证据与桌面打包 |
| 建模工作台 | 可移植资产 v25、v1-v24 读取器,以及共享的 JSON/CLI/MCP 定义 | 图编辑、保存与可选通道曲线 |
| 发动机物理 | 独立的气体质量/能量、滑块—曲柄功、定时气门、预设燃烧、气体与液体燃油计量、有限柔性油轨、油膜蒸发与物理针阀驱动 | 油轨泵送/加注、更精细的电磁/电子/喷雾行为、有限液体体积耦合、点火控制、详细进/排气、机械损失、热化学与实测标定 |
| 变速器 | 耦合离合器、齿轮/行星排、映射式变矩器/锁止、液压,以及带已分解行星自转/轨道惯量的七前进/倒挡 DCT 与四前进/倒挡 Ravigneaux 路径 | 啮合柔性/损失与载荷分配、DCT 执行、完整 AT 压力/换挡控制与实测油路、实测图谱、阀门/密封/空化行为,以及更丰富的变矩器动力学 |
| 控制与电气集成 | 采样压力 PI、针阀闭合控制与传感器确认的分阶段 DCT 交接、有界电压/占空比、执行器所有权、电池等效电路与附件 | 协调的 ECU/TCU 循环、传感器/执行器、扭矩请求、故障、BMS,以及实测热/电行为 |
| 车辆证据与发布 | 边界与溯源完整的研究样本 | 两套完整实测动力总成、不确定度预算、稳定性、桌面验收与分发 |

## 下一项托管工作

在 [低压喷射契约](LIQUID_FUEL_INJECTION.zh-CN.md) 上继续油轨泵送/加注,以及更精细的电磁/电子驱动。有限柔性源质量与压力能、真实针阀运动、采样剂量反馈、油膜补充与蒸发已经实现。参见 [针阀契约](NEEDLE_ACTUATION.zh-CN.md) 与 [有界闭合预测](CLOSURE_PREDICTION.zh-CN.md)。接收端仍在声明的可忽略液体体积边界下导出位移压力功;分解后的喷雾/位移必须用经过验证的几何与动量/功耦合替换它。保持供给、蒸气可用性与预设反应彼此分开,并保留解析、守恒与收敛证据。

然后扩展点火/控制、进/排气动力学与发动机机械损失。当前的 Wiebe 燃烧是预设的,并不确立预测燃烧、爆震、排放或 OEM 标定。[气体计量契约](FUEL_METERING.zh-CN.md) 仍是一条独立的受支持路径。

在 [七前进/倒挡 DCT 图](DUAL_CLUTCH_TRANSMISSION.zh-CN.md) 上构建详细的同步器/接合齿/离合器执行。在 [Ravigneaux 图](RAVIGNEAUX_TRANSMISSION.zh-CN.md) 上结合 [实测行星属性与啮合行为](RESOLVED_PLANETS.zh-CN.md)、完整的 [泵驱动活塞执行](AT_HYDRAULIC_ACTUATION.zh-CN.md),并用耦合的变矩器、齿轮、离合器与液压原语做 AT 控制。在 [采样 DCT 控制](DCT_CONTROL.zh-CN.md) 上走向扭矩混合换挡与有界 ECU/TCU 协调,包括扭矩请求、传感器/执行器与可恢复故障。有实测属性/控制数据时,再扩展恒定泵损耗、电池与阀门/蓄能器模型;所给研究值仍为未核实。

## 工作室与实测验收

把 `POWER_UNITY_EDITOR` 设为锁定的编辑器并运行 `unity-test`。先取得真实的导入/Play/渲染证据,再取得 Player/IL2CPP 证据。通用通道选择、图编辑与保存仍是单独的工作室功能。CLI、MCP 与 Unity 必须继续使用同一套模型语义。

EA211 DJS + DQ200 与 PSA EC5 + AT8 保留完整的动力总成边界、车辆适用性与证据清单。缺失的 OEM 测量不会被静默默认值替换。功能完成、数值正确与实测车辆可信度需要分开验收。

[Zig 存档](NATIVE_ZIG.zh-CN.md) 在 `legacy/native/migration-manifest.json` 中保留原始哈希与 Git 溯源,包括原始 C 修订 `c342d4c`。它与现行 C#/Unity 应用保持分离。原生迁移并不完成托管功能迁移或动力总成验收。只有当测量证明有必要时,并且核心契约保持稳定,才引入额外并行、稀疏求解或 Burst。

## 液压 AT 反馈控制

`at_controller` 接受 [-1,4] 范围内的整数目标挡位；零表示空挡。它管理五组充油/泄压阀以及可选的变矩器锁止支路。支路顺序为行星架输入、小太阳轮输入、大太阳轮输入、行星架制动、大太阳轮制动，最后是锁止。

示例 `controlled-hydraulic-ravigneaux` 和 `controlled-fired-hydraulic-ravigneaux` 使用请求通道 900、控制器 ID 1400。两者分别保留 99 和 122 个报告状态，未改变 128 状态上限。资产 v25 保留支路、增益和时钟，并可读取 v1-v24。

这是研究控制，参数仍为 `unverified`。协调 ECU 扭矩融合、详细传感器/阀模型、完整车辆故障及 OEM 标定仍待完成。托管和 Standard 检查不能证明实际 Unity Editor/Play/Player/IL2CPP 验收。
