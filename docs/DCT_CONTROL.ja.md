# サンプリングされたデュアルクラッチの同期と段階的引き継ぎ

[English](DCT_CONTROL.md) · [简体中文](DCT_CONTROL.zh-CN.md) · [Français](DCT_CONTROL.fr.md) · [Русский](DCT_CONTROL.ru.md) · **日本語** · [한국어](DCT_CONTROL.ko.md) · [Deutsch](DCT_CONTROL.de.md) · [Español](DCT_CONTROL.es.md) · [Italiano](DCT_CONTROL.it.md) · [Português](DCT_CONTROL.pt-BR.md)

`dct_controller` は、[7 前進/リバースの研究グラフ](DUAL_CLUTCH_TRANSMISSION.ja.md)の 2 つの駆動クラッチと 8 つのセレクターチャンネルを所有します。整数の要求段の指令は、確定した実際の段、選ばれた経路、変速位相、測定された同期誤差、制御器の故障とは別です。

これは、明示的なトルク中断を持つ、センサー駆動の研究用状態機械です。完全な TCU/ECU のトルクブレンド、詳細なドグ/ボークリングまたはクラッチアクチュエーターの挙動、キャリブレーション済みの変速戦略、完全な車両故障管理は確立しません。

## 状態と物理的な確認

| 位相 | 保持される指令の方針と遷移 |
|---|---|
| ニュートラル | 両方の駆動クラッチとセレクターが解放されている |
| 準備 | 先行する駆動が係合したまま、対象の反対側経路は無負荷でプリセレクトされる |
| 解放 | 先行する駆動の開度がランプで下がる。対象の駆動は解放されたまま |
| 同期 | 両方の駆動が解放された状態で、対象セレクターが全開までランプする。測定された滑りと物理的なロックを待つ |
| 係合 | 対象の駆動がランプで上がる。もう一方の駆動は解放されたまま |
| 駆動 | 対象の駆動/セレクターが確定している。隣接する無負荷経路のプリセレクトは許される |
| 故障 | 両方の駆動とすべてのセレクターが解放される。ニュートラルか別の要求まで故障を保持する |

対象は、引き継ぎの進行中にラッチされます。それより後の非ニュートラル要求は、その引き継ぎのあとで処理されます。ニュートラルは、到来したサンプルで中止します。同じ入力軸経路の変更は、セレクターを変える前にその駆動を解放します。反対の入力軸経路の変更は、駆動の解放の前に、無負荷の対象を準備できます。各経路が指令するセレクターはたかだか 1 つで、指令された駆動クラッチの重なりは使いません。

セレクターの開度ランプは、設定された係合時間を使います。セレクターが準備できるのは、全指令のあと、測定された滑りが与えられた許容差以内にあり、物理的な `Locked` モードであるときだけです。駆動が確定するのは、全係合指令、小さな駆動滑り、物理的なロックのあとだけです。指令の受理は、瞬間的な比や物理的な段の完了を告げません。

非アクティブなプリセレクトは、確定した経路を短時間乱し得ます。駆動または選ばれた経路が物理的にロックしていない間、スナップショット上の実際の段は零です。持続的な喪失は別に計時されます。制御器は、1 つの過渡サンプルを持続的な故障と混同しません。そのタイマーは、位相の変化と回復でリセットされます。

## 要求段、方向、故障

要求段は `[-1,7]` の整数で、零がニュートラル、-1 がリバースです。静的、即時、スケジュールされた入力の検証は分数を拒否します。源の指令は明示的な `state_code` 単位を使います。通常のクラッチ割合が段番号として解釈されることはありません。

同期のタイムアウトは、観測可能な無負荷の故障を返します。与えられた速度限界を超える正の車両運動に対するリバース要求、または負の運動に対する前進要求は、方向変更の故障として阻止されます。確定した駆動/セレクターのロックの持続的な喪失は、同じ与えられたタイムアウトと、別の故障コードを使います。これらの制御器の結果は物理的な方針状態であり、数値失敗や、暗黙に成功した変速 KPI ではありません。

| 故障コード | 意味 |
|---:|---|
| 0 | 故障なし |
| 1 | 同期/係合のタイムアウト |
| 2 | 車両運動によって阻止された方向変更の要求 |
| 3 | 確定したロックの持続的な喪失 |

ニュートラルは故障を消し、トレインを解放します。別の妥当な要求は新しい試行を始められます。同じ失敗した対象を繰り返し送っても、サンプルごとにタイムアウトはリセットされません。より高いレベルの故障判断、妥当性検査、センサー故障、運転者/車両の安全機能は、別の作業のままです。

## 定義と所有

制御器は、エンジン A ノード、車両ノード、奇数/偶数の駆動クラッチ ID、前進 1–7/リバースの順の 8 つのセレクター、要求段の入力を宣言します。10 個のアクチュエーターチャンネルはすべて別々で、初期は解放され、所有者は 1 つでなければなりません。コンパイラは、通常のクラッチ種別、軸/ハブ/ファイナルドライブのトポロジー、奇数/偶数の割り当て、リバースアイドラー経路、安定した参照を検証します。セレクターのリストは、不変の定義/コンパイル済みデータへコピーされます。

明示的なタイミングは、サンプル、解放、係合、同期タイムアウトのナノ秒です。サンプリングは物理ティックに揃います。他の時間は正のサンプル倍数で、たかだか 10 秒です。同期許容差と方向の速度限界は `rad_s` または `rpm` を使います。OEM 値、アクチュエーターマップ、損失曲線は黙って供給されません。

エージェントは要求段を書きます。駆動/セレクターへの直接書き込みは `controlled_input` を返し、正しい指令名/チャンネルを示し、リビジョン/状態は変えません。読み出しは、現在の要求、確定した段、指令された奇数/偶数の選択、位相、対象セレクターの滑り、故障を公開します。これらの状態コードと物理チャンネルは、異なる意味を保ちます。

## 整数時計と完全なトランザクション

サンプルは有界な整数のシミュレーション時刻で動きます。入力の書き込みは制御メモリを進めません。保持された割合は通常の物理ソルバーへ適用されます。慣性、歯車反力、同期熱、駆動熱は既存の台帳に残ります。制御器の状態は、ラッチされた/アクティブな段、選択、位相/故障、位相時計、測定誤差、持続ロックのタイマーを含みます。分岐、キャンセル、遅れて失敗したバッチ、投機的な区間は、そのメモリと保持されたすべての指令を一緒にコピー/ハッシュ/ロールバックします。成功したステッピングとスナップショットは、マネージドメモリを割り当てません。

制御された長い段の実行は、中点速度からの補償座標増分を使います。その補償はトランザクション的でハッシュされます。厳密な位相許容差は変わりません。これは、新しい、負荷のある長い同期シナリオが露わにした累積丸めを解消します。より前のモデル経路は、先行する積分とリプレイの挙動を保ちます。

報告される状態の上限は明示的に **128** で、32 ノードと 64 コンポーネントは変わりません。これで、以前の 64 状態の限界を超える、完全な研究用の燃焼/DCT/制御器の合成ができます。正確な境界でのコンパイル/ステッピングと、上限を超える物理/制御器モデルは検査されます。ビルド/テストは逐次のままです。

## 移植可能で共有される実験

アセット v22 は、DCT 制御器ごとに、型付きの 104 バイトの経路/タイミング/許容差レコードを 1 つ加えます。v1–v21 のリーダー、安定した先行 ID、有界な個数/長さ、ダイジェスト、型付きの所有、単位、物理コンパイルの検査を保ちます。制御器モデルはフィンガープリントタグ 26 を加えます。要求/実際/選択/位相/誤差/故障のフィールドは、先行 ID を変えずに追加されます。真正な v21 のグラフフィクスチャは、ダイジェストと、同じランタイムでアップグレードされたリプレイを保ちます。

`controlled-dual-clutch` は、7 つの経路すべてと選ばれた降段を通じて段要求を出します。公称時間を仮定せず、物理的な完了を通じて、最後の引き継ぎと非アクティブなプリセレクトを観測します。`controlled-fired-dual-clutch` は、同じサンプリング方針を、開放気筒の予混合燃焼と組み合わせます。JSON、CLI、移植可能なリプレイ、実際の MCP 子サーバーが定義を共有します。

[VALIDATION.ja.md](VALIDATION.ja.md) は、状態/インターロック、故障/回復、所有、整数入力、不変の経路、容量、長い位相の保存、保存則、完全なリプレイのエビデンスを記録します。パラメーターはすべて `unverified` のままです。トルクブレンド、完全なアクチュエーター/センサー/ECU の挙動、完全な AT、実際の Unity、キャリブレーション済みの対象パワートレインは未完了です。
