# 개발 상태

[English](DEVELOPMENT_STATUS.md) · [简体中文](DEVELOPMENT_STATUS.zh-CN.md) · [Français](DEVELOPMENT_STATUS.fr.md) · [Русский](DEVELOPMENT_STATUS.ru.md) · [日本語](DEVELOPMENT_STATUS.ja.md) · **한국어** · [Deutsch](DEVELOPMENT_STATUS.de.md) · [Español](DEVELOPMENT_STATUS.es.md) · [Italiano](DEVELOPMENT_STATUS.it.md) · [Português](DEVELOPMENT_STATUS.pt-BR.md)

Power!에는 관리형 시뮬레이션 코어, 공유 모델 문서와 이식 가능한 자산, 헤드리스 CLI, MCP 에이전트 서비스, 준비된 Unity 스튜디오가 있습니다. 합성 실험실은 엔진, 변속기, 유압, 전기 거동을 실행합니다. 완전한 파워트레인, 조율된 ECU/TCU 제어, 실측 교정, 수용된 Unity 데스크톱 응용 프로그램은 아직 끝나지 않았습니다.

코어와 Assets는 `net10.0`과 `netstandard2.1`을 모두 대상으로 합니다. 코어에는 Unity, 전송, 모델 공급자, 제3자 의존성이 없습니다. Unity Assets 스크립트는 C# 9를 사용합니다. Unity는 외부 SDK가 빌드한 Standard 어셈블리를 로드합니다. .NET 10/C# 14 소스를 컴파일하지는 않습니다.

## 증거와 한계

[AT 유압 구동 그래프](AT_HYDRAULIC_ACTUATION.ko.md)는 공유 축 구동 펌프에서 다섯 레인지 요소 전부와 선택적 컨버터 록업을 공급합니다. 명시적 충전/배출 경로, 유한 피스톤 운동, 복귀 스프링, 패드에서 유도된 용량은 유압 변위 일과 실제 포획/해제 거동을 유지합니다. 규정 밸브는 센서로 확인된 AT 제어도, 실측 밸브 바디 수용도 아닙니다. 완전한 파워트레인 거동과 실측 수용은 아직 끝나지 않았습니다.


필요한 직렬 `dotnet run --file tools/Build.cs -- verify`는 Windows x64에서 로컬로 통과합니다. .NET 10에서 호스트되는 두 어셈블리 대상, 실제 MCP 자식 프로세스, 모든 실험실 보고서, Zig 아카이브, C# ABI를 다룹니다. 현재 개수, 로그 경로, 스키마 검사, 수치 결과, 유지된 CI 출처는 [VALIDATION.ko.md](VALIDATION.ko.md)에 있습니다. .NET 10에서의 Standard 어셈블리 테스트가 Unity 런타임 호환을 확립하지는 않습니다.

[액체 필름 증분](FUEL_FILM.ko.md)에는 이제 해석적 가열/포화/건조 검사, 독립적인 동시 ODE 기준, 질량/화학/열 보존, 이식 가능한 리플레이, 완전한 세션 트랜잭션이 있습니다. 대칭 필름 순서는 벽을 공유하는 필름에 2차의 매끄러운 세분화를 줍니다. 다른 벽 열원과의 결합은 기존의 1차 명시적 벽 한계를 유지합니다. 정확한 리플레이는 시간 스텝 정확도, KPI 통과, 교정된 물리와 별개입니다.

[Ravigneaux 연구 그래프](RAVIGNEAUX_TRANSMISSION.ko.md)는 단일/이중 피니언 제약, 다섯 마찰 경로, 네 전진 레인지, 후진을 더합니다. 독립적인 자유 질량, 반사 관성, 브레이크 포획 기준이 포트 반력과 열을 검사합니다. 공유 토크와 점화/컨버터 실험은 완전한 리플레이와 명시적 연구 경계를 보존합니다. 축소 경로는 유성 자전을 생략합니다. 상세 유압, AT 제어, OEM 토폴로지/교정은 아직 끝나지 않았습니다. [분해 옵션](RESOLVED_PLANETS.ko.md)은 네 개의 실제 물림, 두 개의 절대 자전 로터, 명시적 궤도 관성을 더합니다. 독립적인 여섯 로터 질량, 각운동량, 포획 기준이 그 에너지를 유지합니다. 상세 이빨/윤활/하중 분담 거동에는 여전히 증거가 필요합니다.

[샘플링 DCT 제어기](DCT_CONTROL.ko.md)는 이제 구동/셀렉터 명령을 소유하고, 무부하 경로를 사전 선택하고, 물리적 동기화/잠금을 기다리며, 배타적인 단계적 해제/체결을 수행합니다. 정수 기어 요청, 중립 중단, 방향/시간 초과/지속 잠금 결함, 새 요청 회복을 관측할 수 있습니다. 확인된 기어는 이전 확인 뒤에도 과도 슬립 동안 일시적으로 0일 수 있습니다. 제어되는 긴 기어 주행은 트랜잭션 보정 좌표를 사용하며, 엄격한 위상 허용 오차는 변하지 않습니다. 명시적 상태 한계는 128입니다. 노드와 컴포넌트 한계는 32/64로 남아, 70상태의 점화/제어기 구성을 허용합니다. 완전한 토크 블렌딩 변속, 액추에이터, 포괄적인 ECU/TCU 결함은 열려 있습니다.

[듀얼 클러치 증분](DUAL_CLUTCH_TRANSMISSION.ko.md)은 이제 일곱 전진 경로, 짝수 경로 후진 아이들러, 세 개의 출력/종감속 분기, 명시적 마찰 셀렉터를 조립합니다. 독립적인 부호/반사 관성과 사전 선택 충격량/열 기준이 동력 경로를 검증합니다. 토크와 점화 실험은 모든 보통 그래프/자산/에이전트 계층을 통해 리플레이됩니다. 유계 정규화 선형 잠금 대체가 이전에 실패하던 6/7단 인계를 풀면서, 기존 궤적은 회귀로 유지합니다. 규정된 선택/인계는 완전한 TCU도, 상세 도그/보크 링/액추에이터 거동도 아닙니다. 매개변수와 OEM 샘플은 검증되지 않은 상태로 남습니다.

[폐쇄 보상 증분](CLOSURE_PREDICTION.ko.md)은 상태를 커밋하지 않고 유계의 유지 입력 플랜트 미래를 리플레이합니다. 잔여 니들 흐름을 예측하고 물리 틱 격자에서 전압 제거를 계획합니다. 고립된 도즈 추적은 개선되고, 실제 닫힘/반발과 연료/에너지 이력은 변하지 않은 물리 기구로 남습니다. 읽기 전용 예측, 정수 한계, 지평 세분화, 할당 0, 완전한 트랜잭션이 검증되었습니다. 예측은 다른 명령을 유지하고 미래의 외부 입력 이벤트를 생략합니다. 그 모델과 유한 지평은 교정이나 완전한 ECU 수용이 아니라 명시적 한계입니다.

[니들 증분](NEEDLE_ACTUATION.ko.md)은 자속 에너지와 상반력을 실제 니들 질량, 스프링/감쇠, 탄성 정지에 결합합니다. 정수 샘플링은 공급된 도즈 피드백에서 코일 전압을 소유합니다. 유체는 닫힘 지연과 반발을 지나는 물리적 양정에 의해 지배됩니다. 목표에 잘리지 않습니다. 독립적인 자기/RL/운동 기준, 공급/상/전기/열 장부, 이식 가능/MCP 리플레이, 완전한 제어기 트랜잭션이 통과합니다. 실험 경계의 과잉 공급과 남은 액체는 관측 가능한 상태로 남습니다. 이 결과가 교정된 도즈 추적이나 완전한 인젝터 전자/자기를 확립하지는 않습니다.

[액체 분사 증분](LIQUID_FUEL_INJECTION.ko.md)은 이제 마른 필름에서 시작해 유한 컴플라이언트 공급원에서 끌어옵니다. 해석적 레일 압력/일, 독립적인 동시 세분화, 완전한 공급/필름/화학/열 장부, 실제 MCP 리플레이, 시험적 클러치 롤백이 통과합니다. 레일 압력 에너지는 저장됩니다. 노즐 열과 내보내진 수신기 압력 일은 구분된 상태로 남습니다. 기하학적 용량, 통기/기체 공간/슬로싱, 캐비테이션, 실측 충액/효율/조압과 분해 분무는 미완성입니다. 매개변수는 `unverified`이며 실제 Unity Editor/Play/Player/IL2CPP와 OEM 보정은 미검증입니다.

`film-fired-cylinder`는 처음에 선언된 액체 재고를 담습니다. 규정 반응 전에 그 재고를 가열하고 증발시킵니다. 액체 인젝터를 구현하지는 않습니다. 준비된 스튜디오 표식과 테스트는 같은 정의를 소비합니다. `POWER_UNITY_EDITOR`가 설정되어 있지 않으므로, 실제 편집기/Play, 렌더링, Player/IL2CPP는 검증되지 않은 상태로 남습니다.

모든 연구 매개변수는 `unverified`로 남습니다. EA211 DJS + DQ200과 PSA EC5 + AT8은 [assets/samples](../assets/samples)에 완전한 파워트레인 경계와 증거 매니페스트를 유지합니다. 누락된 OEM 측정은 누락된 상태로 남습니다. 라이선스와 역사적 소스 출처는 보존됩니다.

## 다음 개발 순서

1. 유한 탱크에 기하학적 용량, 통기/기체 공간 동역학, 실측 펌프 충액/조압과 정밀 자기/전자 구동을 추가합니다. 유한 액체 체적과 분무 운동량이 분해되면, 선언된 내보내기 변위 일 경계를 대체합니다. 공급된 액체, 증발된 연료, 반응을 따로 관측할 수 있게 유지하고, 독립 기준을 유지합니다.
2. 점화 제어, 흡기/배기 동역학, 기계 손실, 더 풍부한 열화학으로 엔진을 확장합니다. 완전한 엔진 목표를 유지합니다.
3. 검증된 DCT 연구 경로를 상세 구동, 실측 유성 물성/손실, 완전한 AT 유압/제어로 확장한 뒤, 검증된 기어, 클러치, 컨버터, 유압 원시 요소에서 ECU/TCU 변속/토크 조율을 구성합니다. 유계 제어기 상태, 센서/액추에이터 거동, 결함 회복을 더합니다.
4. 고정된 편집기로 `unity-test`를 실행한 뒤 Player/IL2CPP 증거를 얻습니다. 채널 선택, 그래프 편집, 저장을 별도 기능으로 완성합니다.
5. 교정된 샘플이나 릴리스 준비를 선언하기 전에, 두 목표 파워트레인에 대한 실측 맵, OEM 데이터, 불확실성 예산을 얻습니다.

## 유압 AT 피드백

`at_controller`는 [-1,4] 범위의 정수 목표 단을 받으며 0은 중립입니다. 다섯 쌍의 충전/배출 밸브와 선택적인 토크 컨버터 록업을 관리합니다. 경로 순서는 캐리어 입력, 작은 선기어 입력, 큰 선기어 입력, 캐리어 브레이크, 큰 선기어 브레이크, 마지막으로 록업입니다.

예제 `controlled-hydraulic-ravigneaux`와 `controlled-fired-hydraulic-ravigneaux`는 요청 채널 900과 컨트롤러 ID 1400을 사용합니다. 변경되지 않은 128 상태 한도 안에서 99와 122개의 보고 상태를 보존합니다. v27는 경로, 게인과 클록을 저장하고 v1-v26를 읽습니다.

연구용 제어이며 매개변수는 `unverified`입니다. ECU 토크 협조, 상세 센서/밸브, 전체 차량 고장과 OEM 보정은 아직 미완성입니다. managed 및 Standard 검사는 실제 Unity Editor/Play/Player/IL2CPP 검증을 입증하지 않습니다.

## 펌프 공급 액체 연료 레일

`liquid_rail_feed`는 액체 인젝터를 기존 용적 펌프와 명시적인 물질/열 경계에 연결합니다. 유압 출구 노드는 레일 컴플라이언스와 초기 절대압에 일치해야 합니다. 펌프와 인젝터가 이 압력 노드를 소유하고 다른 미추적 유체 경로는 거부됩니다.

v27은 공급 연결과 원천 온도를 저장하고 v1-v26를 읽습니다. 축/압력 해석 교환, 독립 동시 ODE 세분화, 열 혼합, 질량/연료/에너지/체적 원장, 역류와 완전 rollback을 각각 확인합니다.

기하학적 용량, 통기/기체 공간/슬로싱, 캐비테이션, 실측 충액/효율/조압과 분해 분무는 미완성입니다. 매개변수는 `unverified`이며 실제 Unity Editor/Play/Player/IL2CPP와 OEM 보정은 미검증입니다.

## 유한 액체 연료 탱크

`liquid_fuel_tank`는 연결 인젝터의 밀도, 필름 열 기준과 발열량으로 유한 액체 질량과 열 에너지를 저장합니다. 공급은 `tank_component`로 선택하고 `supply_temperature`를 생략합니다. 각 탱크는 연료 물성이 같은 한 공급에 속합니다.

탱크 열/화학 에너지는 전체 저장 원장에 포함됩니다. 내부 전달은 외부 질량이나 화학 공급을 추가하지 않습니다. 명시적 펌프 입구 지정 압력은 압력 일 경계를 유지합니다. 가스 흡배기는 화학 경계 에너지를 운반할 수 있습니다.

기하학적 용량, 통기/기체 공간/슬로싱, 캐비테이션, 실측 충액/효율/조압과 분해 분무는 미완성입니다. 매개변수는 `unverified`이며 실제 Unity Editor/Play/Player/IL2CPP와 OEM 보정은 미검증입니다.
