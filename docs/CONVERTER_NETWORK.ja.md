# 準定常トルクコンバーターネットワーク

[English](CONVERTER_NETWORK.md) · [简体中文](CONVERTER_NETWORK.zh-CN.md) · [Français](CONVERTER_NETWORK.fr.md) · [Русский](CONVERTER_NETWORK.ru.md) · **日本語** · [한국어](CONVERTER_NETWORK.ko.md) · [Deutsch](CONVERTER_NETWORK.de.md) · [Español](CONVERTER_NETWORK.es.md) · [Italiano](CONVERTER_NETWORK.it.md) · [Português](CONVERTER_NETWORK.pt-BR.md)

`torque_converter` は、シャフト、モーター、気筒、クラッチ、理想歯車と同じ求解に加わります。ポンプとタービンは、明示的な慣性を持つ別々の回転ノードです。ステーターは静止した接地です。その反力は観測できますが、仕事はしません。流体損失は、任意の熱ノードまたは外部の熱排出台帳へ入ります。別の並列 `clutch` がロックアップを供給します。ラボラトリーのパラメーターはすべて合成値で、`unverified` です。

## 明示的なマップと方程式

4 つのマップが必要です。`pump_positive`、`pump_negative`、`turbine_positive`、`turbine_negative` です。絶対速度が大きい方の部材が基準の駆動側です。正確な同値ではポンプが勝ちます。その部材の符号が、正/負のマップを選びます。これは、逆回転の間を含む、数学的な基準部材の規約です。利用できないリバースやコースティング特性を推定しません。

駆動側速度 `wD` と従動側速度 `wF` について、`s = wF/wD` は `[-1,1]` にあります。各マップは 2–32 個の明示的な点を含み、無次元の `speed_ratio`、`torque_ratio` R、`nm_s2_rad2` の `capacity_coefficient` C を持ちます。C は速度の二乗に掛けるものであり、K ファクターの逆数ではありません。R と C は線形に補間され、決して外挿されません。両方の速度が零なら、反力は零、モードは零です。

```text
Tdriver   = -C(s) * wD * abs(wD)
Tfollower =  R(s) * C(s) * wD * abs(wD)
Tstator   = -(Tpump + Tturbine)
Qdot      = C(s) * abs(wD)^3 * (1 - s*R(s))
```

コンパイルは、`[-1,1]` を張る厳密に増加する節点、非負の C/R、すべての区間を通じて `s*R(s) <= 1` であることを要求します。節点だけを調べるのでは不十分です。R が s について線形だと効率は二次になり、区間内部の最大も検査されます。傾きは有限でなければなりません。`s=1` では C が零、R が 1 で、同じ向きの等速では流体トルクが零になります。`s=-1` では、ポンプ正/タービン負とポンプ負/タービン正のマップが、一致する物理反力を与えなければなりません。これで、逆回転の間に基準部材が変わるときの跳びを防ぎます。端点比較が許す丸め許容差は `64*epsilon*(abs(a)+abs(b))` だけです。マップ配列は所有され、不変です。正規化された係数はモデルフィンガープリントに入ります。

これらの制限は、Power! の現在の受動的な符号付きマップモデルを定義します。任意の実測コンバーター曲線を覆うとは主張しません。一般的なマップに基づく駆動/コースティングの規約は、[MathWorks Torque Converter](https://www.mathworks.com/help/sdl/ref/torqueconverter.html) とその [2 モードの例](https://de.mathworks.com/help/sdl/ug/torque-converter-two-mode.html) に文書化されています。4 つの符号付きマップ、補間の検証、以下のソルバーは Power! の設計です。それらの参考文献からソースコードや実測パラメーターセットはコピーしていません。

## 連成積分と限界

コンバーター反力は区間の中点速度を使います。気筒があるとき、連成 Newton 系がそれらの離散クランク角仕事と、両方のコンバーターポート速度を解きます。すべての単位トルク応答は、電気機械系と恒久歯車の射影を含みます。クラッチ拘束の反復は、この同じ非線形求解を呼びます。捕捉と反転の分割は、区間応答を再生成します。気筒またはクラッチの積分のあとに適用される、遅延したコンバータートルクはありません。

非線形求解は 24 回の反復と、反復あたり 12 回の半分化する直線探索を持ちます。気筒角度の残差許容差は `2e-14 rad` です。コンバーター速度の残差は `2e-12 + 64*epsilon*(abs(value)+abs(free_prediction)) rad/s` を使います。解析的な区分マップのヤコビアンと、有限差分の気筒仕事導関数が、連成系を作ります。既存の 0.25 rad の気筒行程、バルブ/燃焼の分解能、クラッチの反復/イベント、歯車拘束の限界は引き続き適用されます。既存の 32 ノード、64 コンポーネント、64 状態の予算の中で、コンバーターはたかだか 8 つです。各コンバーターは 4 つの論理的な観測履歴状態を加えます。2 つの平均トルク、平均熱動力、累積熱です。補償された熱の加算も、コピー/ハッシュ/ロールバックに加わります。

受理された区間の熱は `-h*(Tp*wp_mid + Tt*wt_mid)` なので、取り除かれた機械仕事が記録される熱です。解かれた速度の丸め許容差を超える負の熱は、区間を拒否します。丸めの大きさの負の残差だけが零へクランプされます。トルクと熱動力は、受理された内部区間にわたって時間で重み付けされ、その後フルティックで割られます。投機的なイベント試行は、熱や反力を決して確定しません。失敗またはキャンセルされたバッチでは、コンバーター、クラッチ、歯車、ガス、燃焼履歴、入力、大域台帳の状態がすべてロールバックします。分岐は自分の作業領域を所有します。テストは割り当てなしの捕捉を行使します。

中点積分は、滑らかな単独のコンバーター運動に対して二次です。連成した燃焼モデルは、明示的な壁温連成と区間平均のクラッチ離脱を保つので、すべての遷移を通じて一様な二次は主張しません。数値失敗や精度の検討ではティックを細かくしてください。セッションを作り直す前に、マップの傾き、慣性/速度の尺度、クラッチ拘束を調べてください。妥当なマップは、選ばれたすべてのタイムステップが解ける保証ではありません。

## 共有モデルと観測の契約

JSON は必須の `node_a`（ポンプ）、`node_b`（タービン）、`parameters` の下の 4 つの配列、任意の `heat_node` を使います。コンバーターの入力チャンネル、キャリアポート、暗黙のマップ既定値は受理しません。`ComponentDefinition.TorqueConverter` は同じ Core モデルを公開します。マップのエラーはコンポーネント ID と、`converter.pump_positive` や `converter.counter_rotation` のような対処可能なフィールドを運びます。

| フィールド | 意味 | 単位 |
|---|---|---|
| `torque` | 最後の完全なティックの平均ポンプトルク | Nm |
| `torque_at_b` | 最後の完全なティックの平均タービントルク | Nm |
| `torque_at_c` | 最後の完全なティックの、静止ステーターの平均反力 | Nm |
| `heat_flow` | 最後の完全なティックの平均流体熱動力 | W |
| `fluid_heat` | 累積の受理された流体熱 | J |
| `speed_ratio` | 現在の従動/駆動の符号付き速度比。停止時は零 | fraction |
| `converter_drive` | 0 は停止、1 はポンプ正、2 はポンプ負、3 はタービン正、4 はタービン負 | state code |

平均トルク/動力は零から始まります。境界の入力更新は、先行ティックの平均出力を書き換えません。ここでの `torque_at_c` はステーター反力の名前です。このコンポーネントに 3 つ目のローターはありません。コンバーターを含むモデルは `quasisteady_converter_powertrain` を表明し、フィンガープリントタグ 10 を加えます。コンバーターのないモデルのフィンガープリントと軌跡は変わりません。移植可能アセット v10 は 4 つのマップをすべて保持します。v1–v9 のリーダーと真正なフィクスチャは残ります。

## ラボラトリーとエビデンス

MCP の例 `fired-converter` を要求するか、次を実行します。

```sh
dotnet src/Power.Cli/bin/Release/net10.0/Power.Cli.dll assets/labs/fired-converter.power.json --output artifacts/reports/fired-converter.json
```

0.8 s のラボラトリーは、600 rpm のポンプと 300 rpm のタービンから始まり、遊星のサンと 3:1 のファイナルドライブへ供給します。リングブレーキは減速を選び、サン/リングクラッチは直結を選びます。独立してスケジュールされたロックアップ、解放、再捕捉が、流体と摩擦の経路を行使します。これらは規定イベントであり、自動変速の制御器ではありません。

50,000 ns ティックでは、87 のレポート境界がすべて、CLI、移植可能アセット、MCP を通じて正確にリプレイします。モデルフィンガープリントは `839d03901973668d`、最終状態ハッシュは `834a679376b7a6fd` です。最終のポンプ/タービン速度はおよそ 73.37748 rad/s、負荷速度は 6.988331 rad/s、流体熱は 24.27663 J、ロックアップ熱は 22.84709 J です。変速クラッチとブレーキは 157.18199 J と 83.42289 J を加えます。共有熱ノードは 301.438643 K に達します。全エネルギー残差は約 `3.30e-11 J` です。これらの数値は合成過渡を記述します。

独立したテストは、解析的な `C(s)=k(1-s), R=1` の 2 慣性解、解析的なストール減衰、二次の細分化、熱および外部熱の経路指定、ステーターの釣り合い、リバース/コースティング/逆回転の状態、共有されたコンバーターポート、歯車の換算、ロックアップ、バッチ全体のロールバック、キャンセル、分岐、ゼロ割り当てを扱います。燃焼モデルの細分化は、最終速度、流体熱、ロックアップ熱における無次元の合成距離を、3,125 ns の実行に対して、5 つのティックサイズで検査します。絶対差も、それぞれ 0.0002 rad/s または J 未満に制限します。個々の熱誤差は、イベントの近くで毎回の半分化ごとに減少する必要はありません。この検査は、単独の解析的次数とは別です。符号付きマップの所有/検証と、署名を付け直した不正な移植可能レコードには、専用の検査があります。

[油圧ネットワーク](HYDRAULIC_NETWORK.ja.md)は、圧力から導いたロックアップと変速容量を供給するようになりました。流体角運動量、コンバーターの充填/圧力動特性、回転/フリーホイールするステーター機構、温度依存の物性、ポンプ/レギュレーターとピストンの動特性、完全な DCT/AT トポロジー、ECU/TCU 協調は未解決です。完全なエンジン挙動、OEM 計測、車両キャリブレーションも未解決です。Studio には模式的な流体ポートと用意されたテストがあります。実際のエディター/Play/IL2CPP のエビデンスは別であり、この環境では利用できません。
