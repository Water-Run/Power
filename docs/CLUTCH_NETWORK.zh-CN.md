# 耦合离合器仿真

[English](CLUTCH_NETWORK.md) · **简体中文** · [Français](CLUTCH_NETWORK.fr.md) · [Русский](CLUTCH_NETWORK.ru.md) · [日本語](CLUTCH_NETWORK.ja.md) · [한국어](CLUTCH_NETWORK.ko.md) · [Deutsch](CLUTCH_NETWORK.de.md) · [Español](CLUTCH_NETWORK.es.md) · [Italiano](CLUTCH_NETWORK.it.md) · [Português](CLUTCH_NETWORK.pt-BR.md)

托管的 `clutch` 组件连接两个转动节点,或把一个转子接到地面。它参与现有的机电/气缸求解,并把产生的摩擦热送到热节点或外部热账本。JSON、CLI、MCP、资产 v10 与 Studio 使用同一套定义。这实现的是变速器耦合元件;完整的 DCT/AT 拓扑、泵/活塞动力学和 ECU/TCU 协调仍是分开的工作。[液压网络](HYDRAULIC_NETWORK.zh-CN.md)现在驱动一种压力驱动的离合器变体。[映射式液力变矩器](CONVERTER_NETWORK.zh-CN.md)现在共享这一求解,并用一个分开的并联离合器做锁止。

[干式离合器物理契约](CLUTCH_PHYSICS.zh-CN.md)定义库仑定律,以及恒定载荷下精确、独立的双惯量参考。下面的图求解器把该定律扩展到耦合网络。它不把发动机扭矩或电机电流冻结成离合器的单向输入。

## 定义与通道

```json
{
  "id": 16,
  "kind": "clutch",
  "node_a": 1,
  "node_b": 4,
  "heat_node": 5,
  "input_channel": 104,
  "initial_input": { "value": 0, "unit": "fraction" },
  "parameters": {
    "static_capacity": { "value": 100, "unit": "nm" },
    "sliding_capacity": { "value": 30, "unit": "nm" },
    "ratio": 1
  }
}
```

`node_a` 是转动节点。`node_b` 是另一个转动节点,省略或为零时表示接地制动。`ratio` 有限且非零;接地时必须为一。静态容量至少等于滑摩容量,二者都是端口 A 处有限、非负的扭矩。`initial_input` 是 `[0,1]` 内的显式接合比例,同时缩放两个容量。可选输入通道在精确的外部节拍边界上改变接合。省略或为零的 `heat_node` 把热量送到外部排热账本;给出的汇必须是热节点。温度不改变这些容量。

Core 工厂是 `ComponentDefinition.Clutch(id, a, b, staticCapacity, slidingCapacity, channel, engagement, ratio, heat)`。其 `Friction` 描述符包含这两个显式扭矩量。编译模型复制参数,按稳定 ID 排序,并且只在存在离合器时加入指纹标签 8。每个离合器阶段计入现有的 64 状态上限。更早的模型保留其指纹与回放哈希。组合保真度名称为 `hybrid_clutch_powertrain`,标定仍为 `unverified`。

| 字段 | 单位 | 含义 |
|---|---|---|
| `slip_speed` | rad/s | 当前的 `omega_A - ratio*omega_B` |
| `clutch_mode` | StateCode | 最近一次接受区间的阶段:0 分离,1 锁止,2 正滑差,3 负滑差 |
| `torque` | Nm | 最近一个完整外部节拍上 A 处的平均反作用 |
| `heat_flow` | W | 该节拍上的平均摩擦功率 |
| `friction_heat` | J | 累计产生的热量,与去向无关 |

初始扭矩/功率/热量为零;初始阶段在求解载荷反作用之前,由接合与相对速度推断。阶段描述的是已求解区间,因此恰好落在端点的到达在下一次求解之前仍可能显示接近中的阶段。边界输入立即改变输入状态,不改写前一区间的输出历史。这也适用于 `Step` 调用结束处的输入事件。扭矩与功率平均包含每一个被接受的内部区间。

## 耦合积分与事件

对 `g = omega_A - r*omega_B`,端口扭矩为 `tau_A = tau`、`tau_B = -r*tau`。被移除的机械功率是 `-tau*g`;这一符号约定对 `r` 的任一符号都成立。分离时扭矩为零。滑摩使用与滑差相反的动摩擦容量。锁止的离合器施加零中点相对速度,反作用以静态容量为界。这样理想锁止功为零,且不插入人为阻尼器或很硬的惩罚弹簧。

每个内部区间使用现有的隐式中点机电方程,以及守恒的气缸压力功求解。离合器力响应来自同一套耦合线性因子。投影 Gauss–Seidel 求解在为当前力重新计算气缸扭矩的同时,确定有界静态反作用。当所需运动超过速度容差时,饱和的静态约束释放。若另一个约束改变了脱离方向,活动集会被重新考虑。允许冗余离合器回路;它们各自的反作用可以不唯一。稳定的组件顺序选出确定的分配,测试则检查由此得到的运动、容量极限、总动量与能量。

若滑摩区间的相对速度反向,有界二分定位观察到的滑差为零的边界,并从完整状态副本重放该区间。下一区间或者黏着,或者以相反的动摩擦反作用脱离。每个候选时长都会重新计算动力学、热因子和气缸力响应;所有可变因子属于该次仿真。编译模型保持不可变。

约束容差为 `2e-13 + 32*epsilon*(abs(omega_A)+abs(r*omega_B))` rad/s,其中 `epsilon = 2.2204460492503131e-16`。捕获接受该容差 16 倍以内的根。它不把有限滑差投影掉,也不丢弃有限动能。区间扭矩乘速度容差两倍以内的微小负摩擦功被钳位为零;更大的负功则失败。守恒检查包含这一舍入效应。根容差以内的残差不能制造第二个虚假事件。

每次外部节拍至多允许 32 个内部区间、56 次求根迭代、每个活动集 256 次约束迭代,以及 `2*clutch_count+2` 次活动集尝试。非有限因子、未收敛约束、未解析事件、预算耗尽或既有的气缸/气体限制返回 `NumericalFailure`。在有界的约束/求根工作期间检查取消。请减小外部节拍,并检查惯量/速比尺度、冗余约束和容量时序;不要把失败的调用理解成部分完成的接合。

产生的热量按 `-duration*tau*g_mid` 积分,然后加入热求解或外部热账本。所有被接受区间的源功、气体输运、化学历史、壁面交换和热排放都进入现有能量记账。离合器阶段、平均输出、累计热量和补偿热和与物理状态一起复制并哈希。失败或取消的多节拍调用恢复完整的起始状态,包括已排程输入、阶段和热量。分支只共享编译模型数据。外部时间仍是有界整数纳秒计数;内部事件时长不引入对外可见的分数节拍。

非线性脱离检验使用区间平均扭矩需求。它不定位变化的静态载荷首次超过容量的精确连续时间时刻。同样,事件夹逼针对的是离散中点轨迹;过大的节拍可能漏掉端点掩盖了反向的快速物理振荡。请在过渡附近细化时间并比较输出。光滑的机电动力学保持中点精度,热/壁面耦合仍是一阶,且不对所有切换轨迹作统一的二阶声称。

## 实验室与证据

[fired-clutch 实验室](../assets/labs/fired-clutch.power.json)把预混气缸接到分开的惯性负载和离合器热节点。六个精确节拍事件施加部分/全接合、负载扭矩、分离和再接合。参数是合成的。在 0.6 秒内,当前 Linux 报告记录:

| 量 | 结果 |
|---|---|
| 发动机/负载最终转速 | 68.58488546 rad/s |
| 净外部源功,含负载与气缸背压 | -96.74607609 J |
| 产生的离合器热 | 191.55570747 J |
| 离合器热节点最终温度 | 300.95777854 K |
| 释放的燃油热 | 1,630.91064291 J |
| 最终滑差 | 2.84e-14 rad/s,锁止阶段 |
| 最终能量残差 | 1.79e-10 J |
| 模型指纹 / 最终状态哈希 | `197be44884deee90` / `28bf5335d8e35cde` |

全部 67 个报告边界与交替批次大小、可移植回放以及实际 MCP 子服务器回放一致。报告为 `artifacts/reports/fired-clutch.json`。以 `name: "fired-clutch"` 请求 `get_example_model`,或运行:

```sh
dotnet src/Power.Cli/bin/Release/net10.0/Power.Cli.dll assets/labs/fired-clutch.power.json --output artifacts/reports/fired-clutch.json
```

Core 检查把接合、制动和反向与 `ClutchPair` 比较,包括有符号速比和两种热量去向。锁止的 RL 电机与解析合并惯量的模型一致;锁止的反应气体气缸同样与其独立的等效惯量模型一致,包括压力与燃油消耗。弹簧/制动振荡器在三次反向和一个发生捕获的第四转折点上与解析的分段正弦运动一致,每次减半细化使误差降低超过 3.7 倍。三离合器回路检验冗余约束和同时接合。测试还覆盖成功加热/捕获前缀之后的完整回滚、取消、精确排程回放、不可变所有权、分支独立性,以及无分配运行,包括重复的内部反向事件。

资产 v10 往返保留显式容量和全部通道。畸形计数,缺失、重复和类型错误的记录,错误单位,无效极限和伪造降级都会被拒绝。一份真实的 v6 点火气缸夹具保留其摘要、指纹和升级后的回放。严格 JSON 与智能体测试区分执行成功和 KPI 通过。参见 [VALIDATION.md](VALIDATION.zh-CN.md)。

构建导出 `FiredClutch.powerasset`。Studio 准备两片示意离合器片、阶段颜色和具名阶段输出,以及接合控件和热通道。导入与 Play 生命周期测试已准备。实际的 Unity 编辑器、渲染、Play Mode 与 IL2CPP 证据仍未完成;.NET 托管的 Standard 程序集检查不能替代它。

## 永久齿轮耦合

[理想齿轮与行星约束](GEAR_NETWORK.zh-CN.md)现在把自由中点以及离合器/气缸力响应投影到同一永久约束空间。点火行星实验室把齿圈制动和太阳轮/齿圈离合器与理想行星排及主减速组合在一起,回放一次升挡和一次降挡。相对速度已经由永久齿轮完全约束的离合器会被拒绝,因为其独立反作用未定义。其他离合器状态、容量、热与事件契约不变。
