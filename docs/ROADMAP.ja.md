# Power! 開発ロードマップ

[English](ROADMAP.md) · [简体中文](ROADMAP.zh-CN.md) · [Français](ROADMAP.fr.md) · [Русский](ROADMAP.ru.md) · **日本語** · [한국어](ROADMAP.ko.md) · [Deutsch](ROADMAP.de.md) · [Español](ROADMAP.es.md) · [Italiano](ROADMAP.it.md) · [Português](ROADMAP.pt-BR.md)

目標は、完全な Power! パワートレイン基盤です。現代的な C# 物理、Unity 3D スタジオ、そしてエージェントからの直接操作です。合成ラボラトリーに合格しても、確立されるのは有界な数値結果です。エンジン、トランスミッション、制御、車両キャリブレーション、デスクトップの受け入れは、それぞれ独自のエビデンスが必要です。

## 次のマネージド作業

圧縮性ダクトを互換性のある軸駆動室とニードル／ノズル境界に接続し、圧力仕事と相の仮定を明示します。その後、相緩和／滑り、点火、吸排気、機械損失、ECU/TCU 協調制御を進めます。実測校正と実 Unity の受入検証は別に行います。 [圧縮性平衡燃料ダクト](EQUILIBRIUM_FUEL_DUCT.ja.md)

次に、点火/制御、吸排気の動特性、エンジンの機械損失を拡張します。現在の Wiebe 燃焼は規定であり、予測燃焼、ノッキング、排出、OEM キャリブレーションを確立しません。[気体計量の契約](FUEL_METERING.ja.md) は、独立してサポートされる経路のままです。

[7 前進/リバースの DCT グラフ](DUAL_CLUTCH_TRANSMISSION.ja.md) の上に、詳細なシンクロナイザー/ドッグ/クラッチのアクチュエーションを築きます。[Ravigneaux グラフ](RAVIGNEAUX_TRANSMISSION.ja.md) の上に、[実測の遊星物性と噛み合い挙動](RESOLVED_PLANETS.ja.md)、完全な [ポンプ供給ピストン駆動](AT_HYDRAULIC_ACTUATION.ja.md)、そして連成したコンバーター、歯車、クラッチ、油圧原始素を使う AT 制御を築きます。[サンプリング DCT 制御](DCT_CONTROL.ja.md) の上に、トルクをブレンドする変速と、有界な ECU/TCU 協調を築きます。トルク要求、センサー/アクチュエーター、回復可能な故障を含みます。実測の物性/制御データが得られるときに、一定のポンプ損失、電池、バルブ/アキュムレーターのモデルを拡張します。与えられた研究値は未検証のままです。

燃料域ポンプは物理ニードルと凍結蒸気質量分率の流出を介して、有限液体体積の燃焼受容室へ供給します。全在庫に相変化、排除仕事、噴流運動エネルギー、静止壁力積を含みます。 [軸駆動の相変化燃料ポンプ](FUEL_CHAMBER_PUMP.ja.md)

## スタジオと実測の受け入れ

`POWER_UNITY_EDITOR` をピン留めされたエディターに設定し、`unity-test` を実行します。実際のインポート/Play/レンダリングのエビデンスを取り、続いて Player/IL2CPP のエビデンスを取ります。一般的なチャンネル選択、グラフ編集、保存は、別のスタジオ機能のままです。CLI、MCP、Unity は、同じモデル意味論を使い続ける必要があります。

EA211 DJS + DQ200 と PSA EC5 + AT8 は、完全なパワートレイン境界、車両への適用、エビデンスマニフェストを保持します。欠けている OEM 計測を、黙った既定値で置き換えることはありません。機能の完成、数値的な正しさ、実測車両としての信頼は、別々の受け入れが必要です。

[Zig アーカイブ](NATIVE_ZIG.ja.md) は、元のハッシュと Git 来歴を `legacy/native/migration-manifest.json` に保持します。元の C リビジョン `c342d4c` を含みます。これは、現行の C#/Unity アプリケーションとは別のままです。ネイティブの移行は、マネージド機能の移行や、パワートレインの受け入れを完成させません。計測がそれを正当化し、コア契約が安定したままであるときに、追加の並列性、疎な求解、または Burst を導入します。
