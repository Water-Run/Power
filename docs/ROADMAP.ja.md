# Power! 開発ロードマップ

[English](ROADMAP.md) · [简体中文](ROADMAP.zh-CN.md) · [Français](ROADMAP.fr.md) · [Русский](ROADMAP.ru.md) · **日本語** · [한국어](ROADMAP.ko.md) · [Deutsch](ROADMAP.de.md) · [Español](ROADMAP.es.md) · [Italiano](ROADMAP.it.md) · [Português](ROADMAP.pt-BR.md)

目標は、完全な Power! パワートレイン基盤です。現代的な C# 物理、Unity 3D スタジオ、そしてエージェントからの直接操作です。合成ラボラトリーに合格しても、確立されるのは有界な数値結果です。エンジン、トランスミッション、制御、車両キャリブレーション、デスクトップの受け入れは、それぞれ独自のエビデンスが必要です。

## 次のマネージド作業

有限タンクに形状容量、通気/気相空間の動特性、実測ポンプ充液/調圧、精密な磁気/電子駆動を追加します。 有限で柔軟な源の質量と圧力エネルギー、実際のニードル運動、サンプリングされたドーズフィードバック、フィルム補給、蒸発は実装済みです。[ニードル契約](NEEDLE_ACTUATION.ja.md) と [有界なクロージャ予測](CLOSURE_PREDICTION.ja.md) を参照してください。受け側は、宣言された「液体容積を無視できる」境界の下で、押しのけ圧力仕事をまだ書き出します。噴霧/押しのけを分解したあとは、検証済みの形状と運動量/仕事の結合で、それを置き換える必要があります。供給、蒸気の可用性、規定反応は分けたままにし、解析・保存・収束のエビデンスを残してください。 [ポンプ供給の液体燃料レール](PUMP_FED_FUEL.ja.md)

次に、点火/制御、吸排気の動特性、エンジンの機械損失を拡張します。現在の Wiebe 燃焼は規定であり、予測燃焼、ノッキング、排出、OEM キャリブレーションを確立しません。[気体計量の契約](FUEL_METERING.ja.md) は、独立してサポートされる経路のままです。

[7 前進/リバースの DCT グラフ](DUAL_CLUTCH_TRANSMISSION.ja.md) の上に、詳細なシンクロナイザー/ドッグ/クラッチのアクチュエーションを築きます。[Ravigneaux グラフ](RAVIGNEAUX_TRANSMISSION.ja.md) の上に、[実測の遊星物性と噛み合い挙動](RESOLVED_PLANETS.ja.md)、完全な [ポンプ供給ピストン駆動](AT_HYDRAULIC_ACTUATION.ja.md)、そして連成したコンバーター、歯車、クラッチ、油圧原始素を使う AT 制御を築きます。[サンプリング DCT 制御](DCT_CONTROL.ja.md) の上に、トルクをブレンドする変速と、有界な ECU/TCU 協調を築きます。トルク要求、センサー/アクチュエーター、回復可能な故障を含みます。実測の物性/制御データが得られるときに、一定のポンプ損失、電池、バルブ/アキュムレーターのモデルを拡張します。与えられた研究値は未検証のままです。

## スタジオと実測の受け入れ

`POWER_UNITY_EDITOR` をピン留めされたエディターに設定し、`unity-test` を実行します。実際のインポート/Play/レンダリングのエビデンスを取り、続いて Player/IL2CPP のエビデンスを取ります。一般的なチャンネル選択、グラフ編集、保存は、別のスタジオ機能のままです。CLI、MCP、Unity は、同じモデル意味論を使い続ける必要があります。

EA211 DJS + DQ200 と PSA EC5 + AT8 は、完全なパワートレイン境界、車両への適用、エビデンスマニフェストを保持します。欠けている OEM 計測を、黙った既定値で置き換えることはありません。機能の完成、数値的な正しさ、実測車両としての信頼は、別々の受け入れが必要です。

[Zig アーカイブ](NATIVE_ZIG.ja.md) は、元のハッシュと Git 来歴を `legacy/native/migration-manifest.json` に保持します。元の C リビジョン `c342d4c` を含みます。これは、現行の C#/Unity アプリケーションとは別のままです。ネイティブの移行は、マネージド機能の移行や、パワートレインの受け入れを完成させません。計測がそれを正当化し、コア契約が安定したままであるときに、追加の並列性、疎な求解、または Burst を導入します。

## 油圧 AT フィードバック

`at_controller` は [-1,4] の整数目標段を受け取り、ゼロはニュートラルです。五組の充填/排油弁と任意のトルクコンバーターのロックアップを管理します。経路の順序はキャリア入力、小サン入力、大サン入力、キャリアブレーキ、大サンブレーキ、最後にロックアップです。

例 `controlled-hydraulic-ravigneaux` と `controlled-fired-hydraulic-ravigneaux` は要求チャンネル 900 とコントローラー ID 1400 を使います。変更していない 128 状態の上限内で 99 と 122 の報告状態を保ちます。v28 は経路、ゲイン、時計を保存し、v1-v27 を読みます。

研究用の制御であり、パラメーターは `unverified` のままです。ECU トルク協調、詳細なセンサー/弁、包括的な車両故障、OEM 校正は未完成です。managed と Standard の検査は実際の Unity Editor/Play/Player/IL2CPP の受入を証明しません。

[AT_CONTROL.ja.md](AT_CONTROL.ja.md)

## ポンプ供給の液体燃料レール

`liquid_rail_feed` は液体噴射器を既存の容積ポンプと明示的な物質/熱境界に結びます。油圧出口ノードはレールのコンプライアンスと初期絶対圧に一致する必要があります。ポンプと噴射器がこの圧力ノードを所有し、未追跡の他の流体経路は拒否されます。

v28 は補給接続と源温度を保存し v1-v27 を読みます。軸/圧力の解析交換、独立した同時 ODE 細化、熱混合、質量/燃料/エネルギー/体積台帳、逆流と完全 rollback は別々に検査します。

形状容量、通気/気相空間/揺動、キャビテーション、実測充液/効率/調圧、解像噴霧は未完了です。パラメーターは `unverified` で、実際の Unity Editor/Play/Player/IL2CPP と OEM 校正は未検証です。

[PUMP_FED_FUEL.ja.md](PUMP_FED_FUEL.ja.md)

## 有限液体燃料タンク

`liquid_fuel_tank` は対応する噴射器の密度、フィルム熱基準、発熱量を使い、有限液体質量と熱エネルギーを保存します。補給は `tank_component` で選び、`supply_temperature` を省略します。各タンクは燃料物性が一致する一つの補給に属します。

タンクの熱/化学エネルギーは全貯蔵台帳に入ります。内部移送は外部質量や化学供給を追加しません。明示したポンプ入口規定圧は圧力仕事境界を保持します。ガス吸排気は化学境界エネルギーを運ぶ場合があります。

形状容量、通気/気相空間/揺動、キャビテーション、実測充液/効率/調圧、解像噴霧は未完了です。パラメーターは `unverified` で、実際の Unity Editor/Play/Player/IL2CPP と OEM 校正は未検証です。

[LIQUID_FUEL_TANK.ja.md](LIQUID_FUEL_TANK.ja.md)

## 追跡可能な燃料リリーフ戻り流れ

`liquid_rail_return` は補給を排他的な一方向 `hydraulic_relief` に結びます。弁はレールをポンプと同じ規定入口圧へ接続します。すべての流体経路を登録し、不適合ポート、重複所有、未追跡経路は拒否します。

`fluid_heat_fraction` は戻り燃料が運ぶ弁損失の割合 [0,1] を明示します。残る熱は宣言した弁熱経路へ流れます。レール/タンク同時熱混合は質量、化学、圧力仕事、熱台帳を保存し、外部源への戻りは境界から質量/エネルギーを出します。
