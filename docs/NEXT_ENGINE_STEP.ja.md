# エンジン開発再開ノート

[English](NEXT_ENGINE_STEP.md) · [简体中文](NEXT_ENGINE_STEP.zh-CN.md) · [Français](NEXT_ENGINE_STEP.fr.md) · [Русский](NEXT_ENGINE_STEP.ru.md) · **日本語** · [한국어](NEXT_ENGINE_STEP.ko.md) · [Deutsch](NEXT_ENGINE_STEP.de.md) · [Español](NEXT_ENGINE_STEP.es.md) · [Italiano](NEXT_ENGINE_STEP.it.md) · [Português](NEXT_ENGINE_STEP.pt-BR.md)

開発は、オーナーの依頼により 2026-09-14 に再開しました。スタンドアロンのガス原始素と、コンパイル済みのコアネットワークは、実装済みです。下の 2026-09-22 統合チェックポイントが、残る範囲を更新します。それに先立つ密閉気筒のベースラインは、Windows、macOS、Linux でマネージド検証に合格しています。実際の Unity Editor と Player のエビデンスは、まだ未了です。[検証](VALIDATION.ja.md) を参照してください。

**2026-09-14 の後続チェックポイント:** [コアのガスネットワーク](GAS_NETWORK.ja.md) は、固定容積のガスノード、リザーバー絞り、制御された開度、熱リンク、チャンネル、台帳、分岐、ロールバックを実装しています。有界な Heun 法には、滑らかな流れについての解析エビデンスと精細化エビデンスがあり、明示的な壁面結合と、保存的な平衡近傍リミッターがあります。これは、提案されていた陰的手法ではありません。

**2026-09-22 の統合:** JSON/スキーマ、アセット v3、CLI/MCP の発見と例、移植可能なリプレイ、Unity の模式図ビューは実装済みです。変更前の v1/v2 リーダーとフィクスチャは保持されます。Unity Editor/Play の検証は未了のままです。後続の [可動気筒の増分](MOVING_CYLINDER.ja.md) は、JSON、アセット、エージェントを通じてガス交換とクランク仕事を追加します。後続の [クランク角タイミングの増分](VALVE_TIMING.ja.md) は、同じインターフェースを通じて、明示的な 360/720 度プロファイル、逆転、有界なローブ分解能を追加します。最新のエンジンチェックポイントには [予混合燃焼](PREMIXED_COMBUSTION.ja.md) が含まれ、輸送される燃料/空気/生成物、制限反応物、化学エネルギーの収支があります。詳細な熱化学、燃料計量、点火制御は、エンジン作業として残っています。

コアネットワークは、明示的なガス質量と内部エネルギーの状態を提供するようになりました。可動気筒コンポーネントは、それらをクランク依存の室へ、保存的な圧力仕事で結合します。現在の密閉気筒は、角度と不変の初期エントロピーからガス状態を導きます。これはガス交換や壁面加熱を表せません。そのコンポーネントは解析ベンチマークのままです。有限の室、リザーバー、ガス気筒、制御されたオリフィス、ガスから熱へのリンクは、コンパイル済みグラフの中で共存するようになりました。

当初の増分契約（完了したコア作業と、残る統合を区別するには、上のチェックポイントを使ってください）:

- ガス絞りは、安定したガスノード ID を参照します。将来のガス気筒は、可動容積の端点を明示的に定義する必要があります。ガス気筒は回転ノードにも接続します。熱リンクは、有限ガス容積を熱ノードへ接続します。ダミーの機械ノードを要求せず、ガスだけのネットワークをサポートします。
- 質量と内部エネルギーを独立に追跡し、正で有限な状態を検証します。質量と上流エンタルピーを一緒に輸送します。リザーバー交換は、外部の質量台帳とエネルギー台帳で追跡します。内部輸送は相殺されなければなりません。組成/化学種の混合が実装されるまで、接続されるガスは同一の気体定数と gamma に制限します。
- 符号付き質量流量、ガス状態、熱流、質量残差のチャンネルを公開します。オリフィス開度は、`[0,1]` の中の明示的な無次元割合を使い、直接入力と予定入力で同じ検証を行います。
- 有界なペアごとの陰的輸送求解を調べます。接続ペアの等圧状態で括ります。ガス気筒の圧力仕事は、既存のクランク求解を通じて結合します。流れに後退 Euler を使う分割法は、ガス交換について 1 次になります。保存だけでは精度を証明できません。採用する前に、この提案手法を検証します。
- 完全なバッチロールバック、状態ハッシュと分岐における補正、キャンセル、不変のコンパイル済みモデル、成功するステップ中のゼロ割り当てを保ちます。ソルバーの失敗は、対処可能な案内を返さなければなりません。
- JSON スキーマ、移植可能なアセット、機能の発見、例、レポート、Unity ビューを一緒に拡張します。新しいアセットバージョンが必要な場合は、v1/v2 リーダーを残し、変更前の本物のフィクスチャをテストします。ソルバーの意味論が変わらないところでは、既存のモデルフィンガープリントを保ちます。

必要なエビデンスには、チョークおよび亜臨界のノズル流、解析的な断熱容器のブローダウン、リザーバー充填のエンタルピー、閉じたネットワークの質量/エネルギー保存、圧力の均等化、ガス/壁面の熱交換、ステップ精細化、逆流、閉弁の隔離、連成したクランク仕事、不正なトポロジー/入力の拒否、失敗バッチの回復、分岐、完全な CLI/MCP/アセットのリプレイが含まれます。

研究の出発点: 理想的な圧縮性ノズル流については [NASA の質量流量チョーキング](https://www.grc.nasa.gov/www/k-12/BGP/mflchk.html)、制御体積の境界と壁の概念については [Cantera のリアクター相互作用](https://www.cantera.org/stable/reference/reactors/interactions.html)。これらの参照は、ランタイム依存ではなく、Power! が提案するソルバーの検証でもありません。

変更前の正規な気筒 v2 アセットは、[互換フィクスチャ](../tests/Power.Tests/Fixtures/README.md) に保持されています。ソースコミットと SHA-256 付きです。現行テストは、v3 へアップグレードしたあとのフィンガープリントとリプレイを検証します。新しいエンコーダーで再生成しないでください。

完全なエンジン挙動、予測的な燃焼/熱化学、機械式動弁系の動特性、トランスミッション、制御、キャリブレーション済み車両サンプルは、まだ開いています。サンプルのエビデンス境界はすべて保ってください。保管されたネイティブプロトタイプは、[ネイティブ境界](NATIVE_ZIG.ja.md) の下で **Zig** へ移植済みです。現行の C#/Unity 実装は、そのまま残ります。
