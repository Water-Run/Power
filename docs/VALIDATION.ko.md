## 그때 기록된 증거

- Core와 Assets는 `net10.0`과 `netstandard2.1` 모두로 컴파일되었습니다.
- 해석 검사는 일정 토크, RL 응답, 열평형을 다뤘습니다. 스텝을 절반으로 줄여 2차 기계 수렴과 1차 열 수렴을 검사했습니다.
- 양과 음의 비에 대해 일반화 운동량, 감쇠 열, 보존을 검사했습니다. 회생 제동은 음의 전류와 소스 일 감소에 대해 검사되었습니다.
- 입력 거부, 이후 틱 오버플로, 사전 취소, 버퍼 용량 검사는 모두 상태와 호출자 데이터가 부분적으로 수정되지 않음을 확인했습니다.
- 모델 설명 소유권, 병렬 독립 인스턴스, 전체 상태 분기, 틱 단위 대 배치 스텝의 일치를 검사했습니다.
- .NET 스레드 할당 카운터가 입력, 스텝, 스냅샷을 합친 코어 핫 경로의 관리형 할당 0을 측정했습니다. 그 수는 컴파일, 보고서, Unity UI를 제외합니다.
- 자산 인코드와 디코드는 소스, 모델, 이벤트를 유지했습니다. 손상된 다이제스트, 위조된 개수, 잘못된 형식 버전, 잘못된 모델 지문, 추가 바이트는 모두 거부되었습니다.
- 예약 입력은 시각 영, 배치의 끝, 표시 배치 안의 이벤트를 다뤘습니다. 이후의 수치 실패는 전체 배치를 롤백했습니다. 자산 재생은 모든 틱이 입력 변경을 실을 때 관리형 할당 0을 측정했습니다. 취소는 이벤트 커서를 유지했습니다.
- JSON 보고서와 가져온 자산은 20 ms 표시 경계에 떨어지지 않는 이벤트를 포함해 모든 보고서 경계에서 상태 해시와 출력 값을 비교했습니다.
- 같은 물리 검사가 Unity용으로 복사된 실제 .NET Standard 2.1 DLL을 불러 대상 프레임워크를 검사했습니다. 호스트는 여전히 .NET 10이므로, 이것은 Mono나 IL2CPP가 통과했음을 보여 주지 않습니다.
- 에이전트 검사는 구조화된 필드 진단, 필터된 스냅샷, 세션 제한, 동시 개정 충돌, 취소, 부모와 자식 분기 격리, 수명 주기, 간결한 보고서를 다뤘습니다.
- 공식 MCP 클라이언트가 실제 서버 자식 프로세스를 시작하고, 도구 12개 탐색, 입력과 출력 스키마, 오류 복구, 세션 작업, 전체 실험, 자산 내보내기를 마쳤습니다. 파일 다이제스트는 Base64 디코드 뒤 검사되었고, 가져온 재생은 MCP 실험의 최종 상태와 비교되었습니다.

기본 전기—열 실험은 10 seconds 동안 실행되고, 5 seconds에 4 V로 떨어졌다가 6 seconds에 24 V로 돌아옵니다. 배치 크기 두 개가 경계 11개에서 비트 단위로 일치합니다. 전형적인 최종 값은 모터 약 `29.74182442 rad/s`, 부하 `9.91394147 rad/s`, 모터 온도 `302.4760663 K`입니다. 에너지 잔차 임계값은 `1e-5 J`입니다. 리플레이 해시는 같은 바이너리, 런타임, 아키텍처에 대해서만 비교됩니다. 교차 런타임 수치는 허용 오차를 사용합니다.

열교환 실험은 노드 42/77, 외부 입력 없음, 7 ms 스텝을 사용하고 7 seconds 동안 실행됩니다. 배치 크기 두 개가 경계 11개에서 일치합니다. 최종 온도는 후방 오일러 이산 해와 `1e-9 K` 미만으로 다르고, 연속 해석 해와 `0.004 K` 미만으로 다르며, 총 에너지 오차는 `1e-7 J` 미만입니다. 두 보고서는 `artifacts/reports/electrothermal.json`과 `thermal-network.json`입니다.

## 재현

```sh
dotnet run --file tools/Build.cs -- verify
```

이 검사는 Release에서 단언을 실행하는 콘솔 수용 프로그램입니다. 비어 있는 `Debug.Assert` 테스트에 의존하지 않습니다. Unity, Python, 원래 C 라이브러리가 필요하지 않습니다. 네이티브 검증 호스트와 Zig 설치기는 2026-09-19에 같은 .NET 빌드 도구로 옮겨졌습니다 (C# P/Invoke). MCP 프로젝트는 공식 NuGet 패키지를 사용하고, `packages.lock.json`이 해석을 고정합니다.

GitHub Actions가 Windows, macOS, Linux에서 같은 관리형 수용을 마쳤습니다. 각 플랫폼에서 30/30, 19/19, 5/5입니다. 증거는 코드 커밋 [`aea6136`](https://github.com/Water-Run/Power/commit/aea6136bbdcbeaea91d63836d947637e7eac730e)과 [실행 34087686661](https://github.com/Water-Run/Power/actions/runs/34087686661)입니다. `artifacts/reports/github-actions-34087686661.log`와 `.json`은 로컬에 저장되어 있으며 작업 출력과 최종 상태를 담습니다. 캐시 없이, 생성된 어셈블리 없이, 깨끗한 소스 복사본에서 추가 로컬 수용을 실행했습니다. 그 로그는 `github-clean-checkout.log`입니다.

저장소와 CI 증거 링크는 공개입니다. 개발은 2026-09-08에 재개되었습니다. 아래의 더 이른 기록은 각자 검증된 기준선을 가리킵니다.

GPL 공개 업데이트는 실행 가능 소스 내용을 바꾸지 않고 라이선스 고지를 더했습니다. 앞선 커밋과 비교해 소스/빌드 편집 90개가 모두 고지만임을 확인했습니다. 새로운 직렬 검증이 관리형 검사 30/30, Unity용 어셈블리 검사 19/19, MCP 통합 그룹 5/5를 통과했고, 빌드 경고나 오류는 0이었습니다. 로그는 `artifacts/reports/license-verification.log`입니다. 이것은 Unity Editor나 Player 검증 증거를 더하지 않습니다.

## 아직 얻지 못한 증거

이 환경에는 Unity Editor가 설치되어 있지 않습니다. Editor 가져오기, Edit Mode와 Play Mode 테스트, 씬 렌더링 검사, IL2CPP 빌드는 실행되지 않았습니다. 프로젝트, 씬, 테스트, 자동화 진입점은 준비되어 있습니다.

```sh
dotnet run --file tools/Build.cs -- unity-test
```

먼저 `POWER_UNITY_EDITOR`를 설정합니다. Unity 로그와 XML 결과는 `artifacts/unity`로 갑니다. Play 테스트에는 그래픽 편집기를 실행할 수 있는 기계와 유효한 Unity 라이선스가 필요합니다. 작성되었지만 아직 실행되지 않은 테스트는 두 모델 자산의 URP와 어셈블리 가져오기, 재생 일치, 잔여물 없는 반복 시작과 중지, 10-second 기준 실험, 실행 중 열 전용 토폴로지로의 전환, 동적 노드와 입력 목록, 7 ms 틱 스케줄링을 다룹니다. 컨트롤, 테마, 창 크기, 데스크톱 표현은 여전히 사람이 직접 봐야 하고, 세 데스크톱 플랫폼의 Player 빌드는 아직 열려 있습니다.

게시 진입점은 `Power.Studio.Editor.ProjectSetup.BuildPlayer`이며, 선택된 데스크톱 대상과 IL2CPP를 사용합니다. 해당하는 Unity 플랫폼 빌드 모듈이 필요합니다. 빌드되거나 테스트된 Player 패키지는 아직 없습니다.

현재의 모든 매개변수는 합성 실험 매개변수입니다. 완전한 엔진과 변속기, 차량 교정, 배출, 음향, 실시간 예산, 장기 실행은 여전히 각자의 구현과 증거가 필요합니다. 이 검사는 그 작업을 입증하지 않습니다.
